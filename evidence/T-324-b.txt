WINDOWS SESSION-END RECORD (T-324-b-rest)
How the app decided "the last run crashed": resources/recovery.rs previous_run_crash reads the log (diag) between the last two start lines; a run with
none of CLEAN_ENDS ("app exit", "could not start:", "kolux ended itself:", "final save:") is a crash record at the next start (startup_scan, lib.rs).
Windows sign-out/shutdown/restart reaches the app as WM_ENDSESSION, which tao 0.37.1 (event_loop.rs:2332) turns into LoopDestroyed -> RunEvent::Exit and
std::process::exit(0), with no ExitRequested first. The final save then runs inside that window of time Windows allows, and the "final save:" line is only
written after it: a slow save cut off by the system left no clean end, so the next start showed a crash prompt.
Built (no new dependency, no window-proc subclass): resources/recovery.rs SESSION_END ("windows session ended:") joins CLEAN_ENDS and quit_spans;
lifecycle.rs session_end(windows, shutting_down, exit_asked) (pure: a Windows exit nobody asked for, or GetSystemMetrics(SM_SHUTTINGDOWN) != 0) and
note_session_end(app), which writes the line first thing; lib.rs (patch) sets lifecycle::EXIT_ASKED in the ExitRequested branch and calls note_session_end at the top of RunEvent::Exit.
Tests: recovery::t324b_a_windows_session_end_is_no_crash_but_a_run_that_just_stops_still_is (session end, clean quit, real crash, first run, an old session end
excuses nothing, quit span) and lifecycle::t324b_a_windows_exit_nobody_asked_for_is_a_session_end_and_a_quit_or_a_crash_is_not.
Red first: the recovery test failed on the old code at recovery.rs:2011 (left Some("Kolux ended without a clean exit ..."), right None), G:/Temp/fix-other-v3-logs/se-fail.log.
Patch: evidence/fix-other-fix-T-324-b-sessionend-lib.rs.patch (apply AFTER the two APP-014 patches; 3 hunk lines of lib.rs; then drop the #[allow(dead_code)] on note_session_end).
