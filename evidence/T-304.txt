# T-304 evidence: SESS-039 open a worktree in an outside editor

Lane: launch, from 0819c57. Date: 2026-10-13.

## What was built
- tools.rs: editor detection. VS Code (code), Cursor (cursor), Zed (zed), Sublime Text (subl) and
  NeoVim (nvim) by their command-line name on the search path, then at their usual install place
  under Program Files / %LOCALAPPDATA%\Programs. JetBrains IDEs (IntelliJ IDEA, PyCharm, WebStorm,
  Rider, GoLand, CLion, PhpStorm, RustRover) by the Toolbox script name on the search path, then by
  the launcher in the install's own bin folder (<root>\JetBrains\<install>\bin\idea64.exe or
  <root>\<install>\bin\...), the newest install winning. Command `editors_list`.
- links.rs: `editor_open(editor, dir)`: the folder goes through the same file fence as every other
  path (inside a registered root, no other machine, no `..`, no link out), must be a folder; a
  windowed editor or its launcher gets the folder as its one argument (a .cmd launcher is run
  through the shell with the standard library's batch quoting, no console window); NeoVim opens `.`
  in the folder in a console window of its own (CREATE_NEW_CONSOLE; x-terminal-emulator on Linux,
  Terminal via osascript on macOS).
- src/launch/editors.ts + PlusMenu.tsx: given the pane's worktree folder (`dir`), the plus menu adds
  a "This folder" group (plain word for a newcomer screen, ONB-036) with one "Open in <editor>" row per installed editor; an open that fails
  shows its reason in the menu. Without a folder (the sidebar's New session menu) nothing changes.
- The Remote-SSH variant is cut (SESS-047), not built.
