fence-cli-worktree: a worktree Kolux just made opens in the Explorer at once
2026-10-27, lane/ux (from main 3d6d15f2). Source: after.md row "prove | NOW | CLI-018 b2 live run", run log G:/Temp/live-v6-logs/CLI-018.run.txt.

CAUSE
- The fence (src-tauri/src/fence.rs, Fence::allow) checks the saved projects first, then, on a miss, the worktrees Git lists for them. That list was cached for TREES_FRESH = 3 s, keyed only on time.
- A worktree lives outside its project folder (workspaces folder), so every Explorer/file call for one goes through the worktree list. Any miss in the 3 s before a worktree existed (the run had just made b, the sidebar and Explorer were reading A) filled the cache without it. `kolux worktree create --activate` then made c and selected it inside that window; the Explorer's first read was refused with "... is outside them" and nothing retried.
- Spelling and case are NOT the cause: `check` canonicalises both the path and every root before comparing (Windows returns the on-disk case), and the test below also passes the CLI's lowercase forward-slash spelling.
- Every route creates through the Git runner (Git::worktree_add, projects.rs checkout of an existing branch via run_within, pr_checkout, removal, move, repair), which funnels into git.rs plain_output / bytes_within. The fence never learned of any of them.

FIX (root, once; the fence is never widened)
- src-tauri/src/git.rs: a process-wide WORKTREE_CHANGES counter (worktree_changes()), bumped by a drop guard (WorktreeChange) in plain_output and bytes_within when the finished git command was `worktree add|remove|move|prune|repair` (also after a `-c ...` prefix; pass or fail, since a failed add can leave a folder). Covers UI, CLI, orchestration and automations with no call-site edits.
- src-tauri/src/fence.rs: the tree cache also stores the counter it was read at; it is reused only while fresh AND the counter is unchanged. The count is read before Git lists, so a change during the read still forces the next read. Only Git's own list ever becomes a root; no path is allowed that Git does not list.
- A worktree made by a plain `git` in a shell (not through Kolux) still opens after at most 3 s, as before.
- No frontend change: with the fix the first Explorer read succeeds, so no auto-retry is needed.
