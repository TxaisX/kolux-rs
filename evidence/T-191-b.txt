# T-191-b evidence: Claude Agent Teams in the picker, its mode preference, its keybinding command

Lane: launch, from 0819c57. Date: 2026-10-13.

## What was built
- src/launch/teams.ts: the Agent Teams mode preference (settings key agentTeamsMode: off, the
  default, in-process or native; anything unknown reads as off), and the picker entry "Claude Agent
  Teams" (id claude-teams). The entry is offered only with the mode on, Claude Code installed, the
  Kolux command line found on the system search path, and never on native Windows or WSL; it is
  placed right after Claude Code and starts `kolux claude-teams` through the found command line.
  On Windows and WSL a saved "native" acts as in-process.
- src/launch/TeamsModeCard.tsx: the Settings > Agents card with the three choices and help text,
  and on Windows / WSL the note that the picker has no entry and teammates always run in-process.
- src/launch/PlusMenu.tsx: the Agent Teams row draws the Claude mark.
- src-tauri/src/tools.rs: `teams_host` command (Windows?, WSL? from WSL_DISTRO_NAME or the kernel
  release, and the Kolux command line path off Windows/WSL) with the pure `teams_host_from`.
- Keybinding command: tab.newAgent.claude-teams "New Claude Agent Teams tab", no key bound, comes
  from adding the entry to the keybinding agent list (src/keys/actions.ts is core's: hunk below).
  App.tsx already resolves tab.newAgent.<id> against the offered agent list, so the command opens
  the tab only when the entry is offered.
- Native panes (teammates as real Kolux panes) is split to T-191-c; the choice is stored now.
