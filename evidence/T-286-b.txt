What the browser lane built
- src-tauri/src/browser_crash.rs (new, pure logic plus one write path):
  classify(): quitting, a closed tab, a hang, a kill (terminated), an unresponsive end, a failed
  launch and a deleted profile are NOT crashes. A browser page's own renderer crash is the site's
  page (diag line only). The browser process, graphics, utility, sandbox helper, plugin and
  unknown helper processes, and the app's own interface renderer, ARE crashes.
  summary(): exit code as 0x%08X, the process name, "seen by N views", the faulting module when
  WebView2 names it, and the host memory reading (physical and commit; free disk is never shown).
  add_or_merge(): newest five kept; the same crash from another view within 30 s merges into the
  one record (siblings never become their own records).
  report(): always writes a diag line, scrubs the summary with recovery::scrub_report, writes
  through recovery::crashes_write with retries at 0/50/150/400 ms when the file is locked; a
  damaged crashes.json starts empty.
- src-tauri/src/browser_engine.rs: ProcessFailed hook (watch_failures) reads the kind, the reason,
  the exit code and the process description (Args2) and the faulting module path (Args3), takes
  the memory reading at once (GlobalMemoryStatusEx), and calls crash::report. watch_page_failures
  runs for every browser page; watch_app_failures is wired for the main window by the lib.rs patch.
- src-tauri/src/browser_helpers.rs: stop_all marks quitting first, so the shutdown exits that
  follow are never crashes.
- Patches (shared files, not applied on the lane):
  evidence/browser-T-286-b-recovery.rs.patch: the crash store keeps five, not twenty.
  evidence/browser-T-286-b-lib.rs.patch: watch_app_failures(main window) in setup; crash::quitting
  on ExitRequested.

Built (unit-tested; live proof pending, batched):
  APP-040 crash records
    - Only real crashes count (recovery::is_crash): a clean end, an exit while Kolux was quitting
      (the final save's line), a graphics or engine exit at quit time (a dump inside a quit span),
      and Kolux ending itself (the new "kolux ended itself:" log line before every restart and the
      update install) are not crashes; an interface process crash and an unknown child crash are.
    - Newest five kept (KEEP 5, was 20). Reports within 30 s of the newest are one crash: they merge
      (count, the siblings' own summaries, one pending prompt). A crash dump up to 10 min late joins
      its report; a dump already merged changes nothing.
    - The last host memory reading (free / total physical, Kolux's own working set, its age) is
      saved every 30 s by the interface watch thread (memory-last.json) and attached to the next
      report; never disk space.
    - The faulting module: resources/crashdump.rs reads a minidump's exception and module-list
      streams (Microsoft's published layout) and names the module holding the faulting address,
      by file name only; the report also gives the exception code in words.
    - Interface crashes are found from the browser engine's crash dumps
      (%LOCALAPPDATA%\<identifier>\EBWebView\Crashpad, scanned at start and every 30 s while
      running; the first look ever takes what is already there as seen).
    - The store survives a damaged file (starts empty) and retries a save up to 5 times, 100 ms
      apart, when Windows briefly locks the file (access denied, sharing or lock violation).
    - The report details now carry "Faulting module", "Memory before the crash" and the merged
      process count.
  APP-017 repaint after sleep, held updates
    - The watch thread notices sleep from a wall-clock jump of 10 s or more between its one-second
      ticks, logs "the computer woke: every window repaints (APP-017)", sends every window
      "app-woke" and nudges a plain window (shown, not minimised / maximised / full screen) one
      pixel taller and back so the engine redraws the whole surface.
    - src/recovery/hidden.ts: Hold / heldListen hold live updates while the page is hidden and
      replay them in order (or only the newest) when it is shown, 200 per frame so a backlog never
      freezes it, capped at 5000; repaint() replays every hold, sends a resize and forces a fresh
      paint pass. RecoveryMount listens for "app-woke". The Claude usage pill's "claude-usage"
      stream is held (latest only) via a patch. The agent-status listener is deliberately NOT held:
      it raises desktop notifications, which must fire while the window is hidden.
  APP-017 background-throttling exemption
    - Every window gets --disable-background-timer-throttling --disable-renderer-backgrounding
      --disable-backgrounding-occluded-windows in its WebView2 browser arguments (after wry's own
      defaults, safe graphics added when on, each switch once). Browser tabs pass the same string,
      because WebView2 refuses a second argument set on the same data folder (this also covers
      safe graphics for tabs, which T-183 left out). tauri.conf.json gets
      "backgroundThrottling": "disabled" (Tauri honours it on macOS 14+ only).
