T-144-c · TERM-035 pane right-click menu and the header More button (lane/core, 2026-10-19)

What changed
- src/terminal/PaneMenu.tsx: paneMenuItems() decides the items and their order; the component draws them.
  Order: Copy, Select All, Paste | agent actions (Review plan) | Split Right, Split Down, Equalize, Expand/Collapse |
  Set Title, Clear Title, Copy Session/Terminal/Pane ID, Copy terminal diagnostics | Close Pane (destructive colour) |
  Clear Screen, Find. Items appear only when they apply: Copy needs a selection, Equalize only while the grid holds
  more than one pane (the pane gets onEqualize only then), Expand/Collapse only when the pane can expand, Clear Title
  only with a title of its own, Copy Session ID once the session is known, Close only when closable.
- Escape (anywhere, capture phase, so the terminal never sees it) or a click outside dismisses; a click or right-click
  within 150 ms of opening is ignored, so the opening click cannot close it. The menu measures itself and moves back
  inside the window; a window shorter than the menu scrolls it.
- src/terminal/TerminalPane.tsx: right-click inside the terminal opens the menu (with right-click-to-paste on, the old
  paste/copy behaviour wins and no menu shows). A program that tracks the mouse keeps its right-click; Shift+right-click
  gets the menu anyway. The header "..." button and a right-click on the header open the same menu. New prop onEqualize.
- Unit tests (src/terminal/PaneMenu.test.ts, 8 tests): order; no Equalize in an unsplit pane; items only when they
  apply; Collapse / no Expand for a lone classic pane; Close Pane is the only danger item, shortcut text only when
  assigned; items run their action; opening click does not dismiss (OPEN_GUARD_MS boundary); fitIn keeps a tall menu
  on screen.
