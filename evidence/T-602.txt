WHAT CHANGED
 - src/editor/richTable.ts:249-251 cellTexts (what the export writes for each cell): a bare | in a cell's text is written
   as \|, so a typed pipe no longer splits the cell in two (and no longer becomes a third cell GitHub hides). A pipe the
   file already escaped (\|, shown as typed in the rich view) is kept as it is; an escaped backslash before a typed pipe
   (\\|) still ends in one escaped pipe. Same splitting rule as splitRow (a backslash takes the next character).
 - src/editor/richTable.ts:66-77 overfullRow(md), used by src/editor/markdown.ts:66-68 limitsOf: a note whose table has a
   row with more cells than its header opens in source view with the existing reason banner ("Showing source: the rich
   view cannot show this file because it has table rows with more cells than their header."). It mirrors the table
   importer's rules (header with a pipe, delimiter row with the same cell count, rows until a blank line or a line without
   a pipe). limitsOf is also what richBlockerSince runs on outside changes, so such a row arriving from disk while the
   rich view is open also switches the tab to source. It reads the raw text, so a table inside a code fence also counts
   (safe direction: that note just opens in source).
 - src/editor/richTable.ts:283-287 export: when respellRow cannot respell an edited row AND the row's line holds more cells
   than the row shows, the line is kept as the file has it (that row's edit is not written) instead of the canonical line
   built from the visible cells. Narrower than "whenever respellRow fails" on purpose: respellRow also fails when a column
   is added or removed, and there the canonical line is right (the existing "a column added" test keeps passing).
