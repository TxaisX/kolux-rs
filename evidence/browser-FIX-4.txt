What the user gets
  1. A page can no longer pull the keyboard into Kolux while the user is in another program: the back end refuses
     the "focus the app" step unless Kolux's own window holds the keyboard at the system level, and the front end
     does not move the focused split, open the address bar or hand the keyboard back to an opener tab then.
  2. A page in another browser split that loops the address-bar chord gets the keyboard at most once a second per
     tab (the remaining gap is T-272-d: it needs the engine's real key events, webview2-com, blocked like T-272-b).
  3. A page on one local port (http://127.0.0.1:3000) can no longer make Kolux fetch an icon from another port of
     the same host, by naming it or by redirecting to it; a redirect within the same host and port still works.
  4. The time an icon fetch may take after a hand-off is computed by one small function with its own test.
