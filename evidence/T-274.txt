== TERM-095 · link scanning capped for pathological lines ==
- src/terminal/links.ts: LINK_SCAN_CAP = 16 KiB cells. spanOf (the join of a wrapped logical line the pane scans on hover)
  stops walking at the cap in both directions and gives an empty text, so a hover over a 1 MB line costs at most
  2 x (cap / cols) row lookups and no join and no regex pass; a line under the cap is joined and scanned as before.
  findLinks finds the same links as before (the chat lane's chatLinks.ts calls it on message text and keeps its links);
  only where a path or name match may start changed (see Tests).
- Typing stays responsive because the only work the huge line adds is this bounded hover walk; xterm's own drawing of
  the line is its own (live proof below).
- Test (links.test.ts, TERM-095 block): a 1 MB logical line (5,243 wrapped rows of 200 cells with a link in each) hovered
  at rows 0, 1, 2500 and the last: no links, under 50 ms for all four, under 2 x (cap/cols + 2) row reads per hover;
  a 12-row line under the cap still finds its link; the same line past a smaller cap gets none;
  four 16 KiB separator-free spans (x, a., a-, base64) each scan in under 40 ms (regex run-start lookbehinds;
  without them 16 KiB of x took 194 ms, 64 KiB 3.1 s: T-274-regex-time.log), the shapes found are unchanged
  (incl. -foo.ts:3 after leading hyphens), a 16 KiB hyphen wall ending in a.ts:1 finds it in under 40 ms.

== TERM-137 · hook files of several builds coexist ==
- src-tauri/src/terminal.rs shell_hook_dir(base): the hook files go to <app data>/shell/<16 hex of FNV-1a over every shim
  text (zsh x4, bash, fish)>/, computed from shell_marks::wrap's own output, so a build whose hooks differ writes to its
  own folder and a shell never mixes halves from two builds; a folder another build left is never written and never
  loaded (zsh's ZDOTDIR, bash's --rcfile and fish's --init-command point at this build's folder only). The user's own
  files still load first (ACCT-047 shims hand over to them; a custom ZDOTDIR is kept in KOLUX_USER_ZDOTDIR), unchanged.
- "Written again if one goes missing while the host runs": shell_marks::apply runs at every pane start and write_files
  writes any file that is missing or differs (unchanged, sessions lane); the test below removes .zshrc and starts again.
- Lasting data folder: tauri app_data_dir (not a temp folder), as before.
- Test: terminal::tests::term137_each_build_keeps_its_hook_files_in_a_content_named_folder_beside_other_builds: the
  folder name is stable and hex, a foreign folder's .zshrc stays byte-identical across two applies, ZDOTDIR names only
  this build's folder, a removed .zshrc is back after the next apply.
- No patch for the resolver: shell_marks.rs untouched (wrap and apply were enough).
