Finding worth knowing (recorded in kolux-rs-after.md)
A Rust test binary that links tauri's window toolkit (view(), get_webview, eval, navigate) fails
to load with STATUS_ENTRYPOINT_NOT_FOUND (comctl32 v6 TaskDialogIndirect; dumpbin import diff in
p1-imports-good.txt / p1-imports-bad.txt). The first cut of the cli.rs patch made `cargo test cli`
fail this way because dispatch -> run -> eval_json -> view(). browser.rs now reaches the web view
only through the DRIVER hook (set in browser_open), so no test binary links it; tests call only
pure functions (gate, exec_words, check, pick_tab).

LIVE PROOF PENDING (batched; run by the proof lane, never by a builder)
Set-up: a worktree W with a browser tab open on a page with a form (any local dev page), and one
agent pane (Claude Code or Codex) in W. CLI = the built kolux-dev with the four patches merged.
1. Annotate: click Annotate in the browser tab's bar (button shows pressed), hover the page: a blue
   outline follows the pointer; click a button: a draft box opens under the bar with the element's
   selector; type "make this bigger", Enter: the tray shows "1 note". Pick a second element, Escape
   in the draft: no note added. Press Escape on the page: picking stops (button unpressed).
2. Send: click "Send to agent...", pick the agent pane: its input receives "Page notes on <title>
   (<url>), 1 element:" then "1. `<selector>` ... note: make this bigger"; the tray is empty after.
   With no agent pane in W the menu says "No agent sessions in this worktree".
3. New address: navigate the tab elsewhere: the tray empties; a #hash change keeps it.
4. CLI target: from a terminal in W run `kolux-dev snapshot`: a numbered element list with [ref=e1]
   marks appears. From a terminal outside every worktree with two tabs open in two worktrees, the
   same command answers for the tab on screen; `--worktree <other>` answers for the other one;
   `--page 99` says "browser tab 99 is not open" and nothing opens.
5. CLI drive: `kolux-dev goto --url https://example.com` (the tab goes there; a blocked scheme is
   refused as the address bar refuses it), `kolux-dev wait --text "Example Domain"` returns within a
   second, `kolux-dev get --what title` prints the title, `kolux-dev find --locator text --value
   "More information" --action click` follows the link, `kolux-dev back`, `kolux-dev fill --element
   e3 --value hello` on a snapshot's input then `kolux-dev get --what value --element e3` prints
   hello, `kolux-dev click --element e999` answers code stale_reference and the hint to snapshot
   again, `kolux-dev exec --command "scroll --direction down --amount 300"` scrolls, `kolux-dev
   screenshot` answers code unsupported, `kolux-dev wait --selector .never --timeout 300` fails
   after about 0.3 s with a timeout message. `--json` on any of them prints the envelope.
6. Help: `kolux-dev help goto`, `kolux-dev help mouse`, `kolux-dev mouse wheel --help` each exit 0
   and show the browser lines; `kolux-dev agent-context` lists goto with a summary.
