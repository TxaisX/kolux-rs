What changed
- src-tauri/src/browser.rs: CHORD_SCRIPT (injected into every page) gains three things. (1) A
  capture keydown handler that swallows the app's own chords and reports each press once as
  `kolux-chord:key?k=<key>&c=<code>&m=<c|m|a|s|g flags>` (repeats of a held key are swallowed, not
  sent); the chord list starts from built-in defaults (Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+W,
  Ctrl+Shift+T, Ctrl+T, Ctrl+Shift+B, Ctrl+PageDown/PageUp, Alt+1-9) and the app replaces it through
  `window.__kxKeys(list)`; matching mirrors the app's keyMatches (letter by code or key, digit by
  code or key, Plus, Space, else code or key; `i` takes any digit 1-9). The older chord handler
  (Ctrl+L/F/R, zoom, Alt+Left/Right) runs first and stops propagation, so no chord is reported twice.
  (2) A capture contextmenu handler (trusted events only) that cancels the engine's menu and sends
  `kolux-chord:menu?x&y&vw&vh&s=<selection 0|1>&l=<link href>`; `window.__kxMenu(spec)` draws the
  menu as a fixed div inside the page (spec: x, y, w, bg, fg, line, hover, items [{id,label,url?,off?}
  | {sep}]); Copy and Copy Link Address run in the page (execCommand("copy") / clipboard), every
  other entry sends `kolux-chord:pick?what=<id>&u=<url>`; a left or middle click elsewhere or Escape
  closes it. (3) Nav::Menu / Nav::Key, parsed by menu_of / key_of (fields_of), are turned into the
  `browser-menu` (MENU_EVENT) and `browser-key` (KEY_EVENT) Tauri events with the pane id (with_id)
  and the navigation is cancelled; off screen they are dropped like chords. browser_go gains
  "menu" (eval menu_script) and "keys" (eval keys_script).
- src/browser/menu.ts (new): menuEntries (Back, Forward always, greyed when the history has nothing
  that way; Copy with a selection; for a link Open Link In Kolux Browser / Open Link In Default
  Browser / Copy Link Address, else Open Page In Default Browser, greyed on a blank page),
  menuHeight, placeMenu (at the pointer; flipped left of it or above it when it would run past the
  page's right or bottom edge; never off the top or left), menuSpec, menuAt / menuContext (the
  event's text fields; only http(s) links count), menuColours (the pane's theme tokens, a plain
  dark menu when unreadable).
- src/browser/keys.ts (new): pageKeys(keymap) = the chords the page forwards, from the live keymap
  (tabs, browser and global scopes; custom bindings count, dropped ones do not; the page keeps
  Mod+C/V/X/A/Z/Shift+Z/Y/Shift+V/Insert; a chord with no Ctrl/Meta/Alt is never forwarded, so plain
  typing stays in the page; Mod is Ctrl on Windows/Linux and Cmd on a Mac); keyEventInit = the
  KeyboardEvent the pane replays.
- src/browser/pages.ts (new): the window's registry of live pages (livePage / dropPage / livePages /
  pageOf), the closed-page ring (rememberClosed on a real close, when the page has an address other
  than about:blank; takeClosed newest first; the ring is the terminal lane's remember(), 10 deep),
  bareAddress (scheme and a lone trailing slash dropped), pageRows (palette rows "Browser pages":
  label = title else address, hint = bare address so a multi-word query matches across both; the
  current worktree's rows first, then by tab age; a picked row whose page has gone calls `gone`
  and opens nothing).
- src/browser/BrowserPane.tsx: listens to browser-menu and browser-key for its own id. A menu
  event goes through chordPlan(id, "menu"|"pick") like a chord (a page script that fakes one while
  the keyboard is in the app is ignored; a real one also focuses this split), then the pane sends
  the spec with browser_go("menu"); a pick runs Back/Forward (act), Open Link In Kolux Browser
  (openInBrowser, a tab in this split), Open ... In Default Browser (open_external). A key event
  goes through chordPlan(id, "key"), focuses this split synchronously (flushSync, so App's window
  key handler already sees it focused) and replays the press as a KeyboardEvent("keydown") on the
  window, so App.tsx runs the bound action exactly as if pressed in the app. The pane pushes
  pageKeys(keymap) to the page when it opens, after each load (a new document starts from the
  script's defaults) and when the keymap's bindings change. It keeps its row in the pages registry
  (address, title, site icon, worktree) and removes it on unmount.
