T-605 · Opening prompts never pass through cmd.exe (L2-rust-crates.1, X-sec.1, R08-orch-auto-chat.2;
ponytail note pty.rs:334; SESS-051, SESS-032)
Safety lane, 2026-10-30, branch lane/safety.

WHAT THE USER GETS
- An agent installed through npm (Gemini CLI as Kolux installs it, OpenCode, Copilot, Codex or
  Claude Code from npm) starts as its real program, node on the package's script, never as
  `cmd.exe /d /c <shim> ...`. A GitHub issue or pull-request title, a check name or an automation's
  event text in the opening prompt can no longer run a command on the PC, the prompt arrives whole
  (every line, quotes and all), and a user folder or npm folder with a space in its path no longer
  stops the agent from starting.
- Any other .cmd/.bat launcher (pnpm's shim, a hand-written one) still starts through cmd.exe, but
  then it gets no prompt on its command line: it starts bare and the prompt is typed in once the
  agent is ready, as one paste (the existing SESS-032 typed route).

LIMITS (ponytail note at pty.rs start_line)
- Only npm's own shim is read. pnpm's (it sets NODE_PATH), yarn's or a hand-written .cmd still
  starts through cmd.exe; its prompt is typed in after start, and the user's own default arguments
  (Settings > Agents, typed by the user) still pass through cmd.exe as before.
- The window decides the route (agents.rs) and the terminal service decides the start (pty.rs) with
  the same function on the same files; if node.exe were found by one and not the other (PATH changed
  between the two moments), a prompt could still go to a cmd.exe start. Not seen; both read the same
  PATH and registry.
- A prompt longer than Windows' 32,767-character command line still cannot start an agent that
  takes it as an argument (R08-orch-auto-chat.2 "in addition"); unchanged here.
