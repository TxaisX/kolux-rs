LEFT (not in this task)
 - A file with MIXED line ends (both CRLF and LF-only lines). Corrected in review round 1; the first version of this note
   said mixed files reload "as before", which was wrong: that version switched a clean LF tab to CRLF when its file gained
   one CRLF line, merging every LF line. Now:
   * At open (rule unchanged by this task): any CRLF means the CRLF separator, so a mixed file opens with its LF-only
     lines merged into their neighbour (a dot where each LF is), as before this task.
   * On a reload (quiet reload, Reload, the followed log's tick) the separator switches only when the new text uses one
     line ending throughout. Text that mixes both, or has no line ending at all, keeps the tab's own separator, as before
     this task: an LF tab whose file gains CRLF lines (an LF log that PowerShell's Add-Content appends to) keeps every line,
     each CRLF line showing a CR mark at its end; a CRLF tab whose file gains LF-only lines shows them merged into their
     neighbour, as at open. Either way the bytes are kept, the tab stays clean, and a save writes the file as it is.
   * A second tab of the same file (a split pane, or View file beside Follow log) takes the first tab's separator and
     lines, so the two never split the text differently (see REVIEW ROUND 1).
   CodeMirror splits on one separator only, so showing a mixed file line by line at open means either showing a CR on every
   CRLF line (and typing at a line end lands after the CR) or normalising the file to one line ending when it is saved.
   That is a product choice (see the result's question).
 - Undo after Reload (EDIT-003) brings the edits back but keeps the new separator, so text undone back from a CRLF copy is
   then saved with the file's new LF ends.
 - Pastes of LF text into a CRLF file (CodeMirror's paste, src/editor/paste.ts chunked paste) and the staged diff's
   refresh (DiffPane.tsx:389) still go in as plain strings; the audit marked the paste case "not verified" on Windows.
