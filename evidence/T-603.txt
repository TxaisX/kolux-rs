WHAT CHANGED
 - src/editor/buffers.ts:11-19 the tab editor's line separator now sits in a CodeMirror Compartment (lineEndsFor(text),
   same rule as before: CRLF when the text holds a CRLF, else LF), and withLineBreaks(state, change) gives a change the
   editor's own line breaks (state.lineBreak). The rich view works on doc.toString(), whose lines are joined with \n, so
   its positions are the editor's; only the inserted text needed the file's spelling (the editor splits inserted text on
   its separator only, which is why the new lines became one line with stray LFs in a CRLF note).
 - src/editor/EditorPane.tsx:345 the tab's editor uses lineEndsFor(text); :536 the rich view's edit is dispatched through
   withLineBreaks; :894 the notebook view's full-text write too (the audit's same mismatch: a cell edit in a CRLF .ipynb
   turned the whole notebook into one line and saved it with LF).
 - src/editor/buffers.ts:122-136 replaceAll (the quiet reload of a clean tab, the Reload button, the followed log) detects
   the new text's line ending and, when it differs from the view's, switches the view's separator in the same transaction;
   the text goes in already split into lines (a transaction splits a string with the separator it starts with).
 - src/editor/DiffPane.tsx:310 the diff tab's editable side uses lineEndsFor too, so its reloads (replaceAll) re-detect.
