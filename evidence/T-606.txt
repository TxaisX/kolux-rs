T-606 · AI writers never run a repository's own Claude settings (R05-git-scm.1, R05-git-scm.3;
GIT-017, GIT-018, GIT-020, GIT-024)
Safety lane, 2026-10-30, branch lane/safety.

WHAT THE USER GETS
- The AI writers (commit message, pull-request text, branch name) run their agent from an empty
  folder of their own in the temp folder, removed when the run ends, never from the workspace: the
  prompt already carries the diff. A workspace made from someone else's pull request can no longer
  run its .claude hooks, env block, apiKeyHelper or .mcp.json servers, or redirect the user's Claude
  sign-in, when the user asks for a commit message; nor its Codex, Copilot, Cursor or other agent
  project files.
- Claude Code writes with only the user's own settings and no MCP servers: `--setting-sources user
  --strict-mcp-config`. The user's own Claude sign-in still works (unlike `--bare`).
- A writer installed through npm that takes its prompt as an argument (GitHub Copilot from npm, the
  audit's example) starts as node on its script, so a prompt with line breaks reaches it instead of
  failing with "batch file arguments are invalid". Any other .cmd/.bat writer is refused in plain
  words: "This writer is installed as a Windows command script (agy.cmd), which cannot be handed a
  prompt with line breaks. Install the agent's own program, or pick another writer."

FLAGS, FROM THE CURRENT DOCS (fetched 2026-10-30)
- https://code.claude.com/docs/en/cli-reference: "--setting-sources | Comma-separated list of setting
  sources to load (user, project, local)"; "--strict-mcp-config | Only use MCP servers from
  --mcp-config, ignoring all other MCP configurations" (no --mcp-config is passed, so none start).
- https://code.claude.com/docs/en/permissions, "What runs before you trust a folder": under `claude -p`
  in a folder never trusted, hooks in settings files, the env block and helper commands such as
  apiKeyHelper are "Used" and .mcp.json servers are "Connected without asking, approved or not";
  advice: "Pass --setting-sources user ... so Claude Code reads neither the project's settings files
  nor its .mcp.json". The same page notes --bare still applies the project's env block.
- https://code.claude.com/docs/en/headless: "In bare mode, Claude Code never reads OAuth credentials or
  the system keychain" (why --bare is not used: it would drop a subscription sign-in).
- https://cursor.com/docs/cli/reference/parameters: "--trust | Trust the workspace without prompting
  (headless mode only)"; print mode stops at "Workspace Trust Required" in a folder not yet trusted,
  so `run` passes --trust for Cursor, which then trusts only the empty folder.
- https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference: in a
  `-p` run the working folder's hooks, workspace MCP servers and plugin settings load only from a
  trusted folder or with --trust-folder; the empty folder is neither, so Copilot needs no flag.
Other writers reviewed: Codex keeps `exec --skip-git-repo-check --ephemeral -s read-only` (the skip flag
lets it run outside a git repository; a Codex project config loads only in a trusted project); Pi
keeps `--no-session --no-tools`; Amp, Kimi and Antigravity need nothing beyond the empty folder.

LIMITS
- An agent that still holds a file open in its folder when it ends leaves the folder in the temp
  folder (ponytail note at Scratch).
- A writer's prompt still reaches the model with the user's own settings and tools: a diff written to
  steer the model could try to use tools the user's own settings allow. Codex is read-only, Pi has no
  tools, Cursor runs in ask mode; Claude could also get `--tools ""` (no built-in tools,
  code.claude.com/docs/en/cli-reference) if wanted: a one-line follow-up, not part of this task.
- A writer installed as a non-npm .cmd that takes its prompt as an argument is refused rather than
  given the prompt another way: none of Copilot, Kimi, Cursor or Antigravity documents a prompt on
  standard input for its print mode (Copilot's docs name "a piped prompt" only as another
  non-interactive form, not its flags), so a change of route there is left for a live check.
