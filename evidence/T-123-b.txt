T-123-b (STAT 025 rest: agents whose hook reports carry no reply text have it read from their transcript) · lane/hooks · 2026-10-13

Which agent: Codex. Claude Code's Stop carries last_assistant_message and status.rs already reads it; Codex's Stop carries no reply text (its hook reports name only the event and the session). So the reader is for Codex's session rollout, the JSON-lines file under the Codex home's sessions folder.

What was built
- src-tauri/src/agent_hooks/transcript.rs (new): last_reply_in(text) finds the newest assistant message in rollout lines; last_reply(path) reads the last 1 MiB of the file and drops the partial first line; codex_rollout(event, home) finds the file.
- src-tauri/src/hooks.rs: fill_codex_reply(event, home) runs in answer() on every /codex event: a Stop with no last_assistant_message gets the rollout's newest reply under that field name, so status.rs's one reply path (clean_reply, the Board card line, the Inbox row, the finish notification) serves both agents unchanged. codex_home() is CODEX_HOME when set, else ~/.codex.

What the reader reads (field names and value types only, from the public codex-rs protocol; no real session file was opened for this task)
- a line's top-level `type` (string) and `payload` (object);
- a `response_item` whose payload has `type` "message" and `role` "assistant": the `content` array's items with `type` "output_text", their `text` (string), joined by a line break;
- an `event_msg` whose payload has `type` "agent_message": its `message` (string);
- the Stop event's `transcript_path` (string) and `session_id` (string), to find the file.

What it refuses or never returns
- lines whose role is "user" (prompts), function_call / tool lines, reasoning lines, session_meta (cwd, instructions) and lines that are not JSON: skipped, never returned;
- the file's path and the session id are used to open the file and never leave the module; the only value returned is the newest assistant message's trimmed text;
- a transcript_path that is not a .jsonl under a `sessions` folder is not trusted (it arrives over the hook port); the session-id lookup runs instead;
- a Stop that already carries last_assistant_message, any other event, and a session with no rollout are left untouched.

Fixture: self-written in the tests from the field names above (serde_json values built in the test, written to a throwaway folder); no transcript of a real session was read, copied or quoted. The shape of a real Codex Stop event (whether it carries transcript_path) and the real rollout file name (whether it ends with -<session_id>.jsonl) are the checks that need a real Codex run: filed as T-123-e, since no builder may start a real agent.
