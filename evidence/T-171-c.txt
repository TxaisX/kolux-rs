- share_user_files(user, home, deadline): before every Codex launch on a managed account, the user's own Codex
  folders skills, plugins, prompts, rules and the files AGENTS.md / AGENTS.override.md are copied into the account
  home when the user's file is newer than the home's (or the home has none). The copy takes the user's modified
  time, so an untouched file is skipped next launch and a file Codex changed in the home since is kept. A fixed
  allow-list: auth.json, .credentials.json, sessions, history, logs, config.toml and every other name are never
  read from the user's folder; the home's own auth.json and sessions are never written. Links are skipped, not
  followed. Each launch spends at most SHARE_LIMIT (2 s) copying; the rest follows next launch. A missing home is
  not created; a home equal to the user's folder is a no-op. A failed copy is only a warning string, the launch goes on.
- settings_source / legacy_home: when the user's own config.toml is missing or empty, the shared settings an older
  release left (roaming kolux\codex-runtime-home\config.toml) are read instead, read only, with its hooks table and
  notify command dropped (Kolux RS installs its own hook entries). A file that exists but cannot be read, or is not
  valid TOML, is never papered over. settings_problem() feeds the Settings warning from the same rule.
- ACCT-024 reattach: terminal_attach only answers from the running-terminal map and never reaches the Codex
  sign-in wait (the wait is in the start path, terminal_spawn). Pinned by a source-scan test.
