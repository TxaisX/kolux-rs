WHAT THE USER GETS (once both patches land)
- Keep-awake in Agent mode lets the computer sleep again when a pane closes or its agent crashes
  or exits, when an agent was never actually heard from, and when a "working" reading has gone the
  whole unverified window (30 min) without a signal. Before, any of these kept the PC awake until quit.
- While keep-awake is wanted, every 5 s tick asks the system again, so a request dropped by a
  sleep and resume is back within one tick (TERM-122 "re-checked after resume").
- Linux: the sleep blocker is `systemd-inhibit ... tail --pid=<Kolux pid> -f /dev/null`, which ends
  by itself when Kolux ends (even a crash; this build never runs destructors on panic). A blocker
  that exits within 200 ms (refused, no system bus) is not counted as a hold, so the bar never says
  Awake while nothing is held. macOS: `caffeinate -i -w <pid>` gets the same 200 ms check.
- The status bar Awake item uses the bar's own `item` class (it drew unstyled before) and is in the
  bar's right-click list as "Keep awake", so it can be hidden like the other items.
- Claude Agent Teams uses the agent id from the COMPAT agents table (claude-agent-teams), so its
  new-tab keybinding is the one main already lists (tab.newAgent.claude-agent-teams) and the
  earlier keys / keymap-count hunk is gone. It still runs `kolux claude-teams`.

NeoVim note for the batched T-304 proof: under a debug (tauri dev) build Kolux is a console program,
so std hands a console editor Kolux's own standard handles and NeoVim may draw a blank console. That
is a debug-build effect (release builds are windowed and fine); judge the NeoVim row on a release
build, or treat a blank NeoVim under tauri dev as expected, not a failure. Not changed in code here.
