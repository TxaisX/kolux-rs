What changed for the user
- (a) BLOCKER B1 / S2: a page can no longer multiply tabs by navigating to our own link channel in a
  loop. Both ways a page opens tabs (a new-window request, and Mod/middle-click links sent through
  the page script) now go through one may_open() and take from the same allowance (5 per 10 s).
  An address that is refused takes nothing from the allowance.
- (b) F1: the site-icon fetch reads no more than 256 KB: an answer that is not image/* or says it
  is larger is dropped before its body is read; a body with no length is read in chunks and dropped
  as soon as it passes the limit. All icon fetches share one client. A tab starts at most one fetch
  per icon address at a time, and a tab that already has the icon for that address gets it back
  without a fetch (a page that reloads itself in a loop costs one fetch).
- (c) S1: the icon fetch never goes to this machine or the local network for a public page
  (loopback, private, link-local, carrier-grade NAT, unspecified, localhost, single-label and
  .local/.lan/.internal/.home.arpa names); a page on that host may still show that host's icon.
  Every redirect hop is checked again with the tab address rule, never goes from https to http,
  never onto a local host other than the one the chain started on, and stops after 5 hops.
- (d) S3: the T-238 App.tsx hunk is now real `git diff` output against main fb322d5:
  evidence/browser-FIX-1-App.patch (same text inside evidence/T-238.txt).
- (e) A3 only: a page in a hidden tab still opens tabs behind, but never pushes one to the front
  (the tab's on-screen state comes from the pane's own bounds calls).
  A1 (an allowance per family with a "popups blocked" note), A2 (document the find limit) and A4
  (the T-319 snippet's site check) are PLAN T-272-c: the opener has to be passed when a
  page-opened tab opens (BrowserPane plus App.tsx tab creation), and an allowance per opener alone
  would give each new tab a fresh five and let a self-copying page grow again.
