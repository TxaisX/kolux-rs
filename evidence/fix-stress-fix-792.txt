fix-stress rows 792 + 793 (S3 many projects): the sidebar never filled with 150 projects

ROOT CAUSE (read end to end, not guessed)
- ProjectsPanel.refreshWorktrees awaited workspace_list then workspace_unseen for each project one at a time, set state only after the last project, and every call bumped refreshSeq.
- The 5 s interval started a new refresh with no in-flight guard; each newer refresh made the older one's result be dropped (seq check), so with 150 projects no sweep ever reached the setState.
- The Rust side ran `git worktree list` twice per project (workspace_list and workspace_unseen each call scan()), and scm_pushed (serial, one blocking thread) was fired after every sweep with no guard.
