ux fix 4: the new-workspace composer no longer flashes "That name leaves nothing usable" on first open (lane ux, 2026-10-25)

Spec check (before any change): PROJ-021 only requires that a name that cleans down to nothing is rejected with a
message; PROJ-023 says the field opens with a suggested creature name. Neither asks for the refusal to show before Git
has answered for a valid prefilled name. Not intended. PROJ-021 box 2 / SESS-036 (typed all-rejected name) unchanged.

Root cause: the composer fetched the branch preview from the backend (workspace_preview) after the suggested name
arrived; until the first answer the preview state was null, and previewSentence (src/projects/model.ts) reads a null
preview with a non-empty name as a refusal.
Fix: previewSentence takes a `pending` flag; src/projects/ProjectsPanel.tsx tracks previewAnswered (false from the moment
the name/branch changes until Git answers). Pending with no preview reads "Working out the branch and folder…", not the
refusal. A stale valid preview still shows while typing (as before); an answered null (typed "???") still refuses.
No App.tsx change, no patch file.
