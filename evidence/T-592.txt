T-592 · Downloaded updates install: the installer and the restarted copy outlive the app (R09-app-core-install.1; APP-025)
lane/release-ci, 2026-10-30, Linux cloud sandbox with the x86_64-pc-windows-gnu cross target (compile proof only)

WHAT WAS WRONG
Since T-184 the app runs inside its own kill-on-close job (KILL_ON_JOB_CLOSE | BREAKAWAY_OK, no
SILENT_BREAKAWAY_OK). The updater plugin (2.14.1 now, same code path as 2.13.3: updater.rs install_inner
runs the before-exit hook, then ShellExecuteW, then exit(0)) starts the per-user NSIS installer from inside
that job, so it dies the moment Kolux exits and nothing installs. app.restart() (tauri process.rs:74-89, a
plain Command::spawn) puts the new copy in the same job, so "Restart Kolux" and both "safe graphics"
restarts never come back; and a new copy that starts before the old one is gone finds the single-instance
claim taken, forwards to the dying copy and exits (code 3).

THE FIX, AND WHY THIS ONE
Options weighed (from the task and the audit):
 a) launch the installer and the relaunch ourselves with CREATE_BREAKAWAY_FROM_JOB: means re-doing the
    plugin's install step (temp file, install-mode arguments, /UPDATE, /R, /ARGS escaping), about 40 lines
    copied from plugin internals that already changed between 2.13 and 2.14;
 b) give the app job SILENT_BREAKAWAY_OK for good and a job per child: every program started outside a
    pane (git, helpers) would outlive a crash for the whole session unless each got its own job (APP-053).
Chosen: b's flag, set only at the hand-off. procs::hand_off() adds SILENT_BREAKAWAY_OK to the app job
right before the app hands over and exits. Membership is not changed retroactively: everything already
running stays in the job and still ends with the app (APP-053 holds); only what is started from then on
(the installer, the restarted copy) is left out. It is one flag and keeps the plugin's own install path.
For the installer it runs as the last step of the updater's before-exit hook, after the package passed its
check and the terminals ended, so a package that fails its check hands off nothing.
