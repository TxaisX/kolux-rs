1. ORCH-056 open prompts read off a pane's screen text (NEW src-tauri/src/prompt_scan.rs).
   find_prompt(rows) looks at the newest FRAME_LINES (40) lines of a pane's output log, strips ANSI
   and box borders, and recognises a menu whose options sit at the very bottom: Claude permission
   and trust menus (pointer or numbered options starting with an option word), AskUserQuestion menus
   (kind "question" -> state waiting / attention input), Codex "Allow command? [y/n]" style tails,
   and Cursor-style accept/reject pairs (kind "approval" -> state permission / attention approval;
   "trust" is a trust menu). The asking line is the option line that asks itself, else the nearest
   line above ending in "?", else the nearest line with words. Any output after the menu means it was
   answered: no prompt. A shell prompt, a composer box and working output are no prompt.
   Scanner keeps one PaneScan per terminal: restored_until (the log cursor at the moment the saved
   scrollback was replayed; prompt_scan_restored sets it) so a menu found only in restored lines
   never counts; the result is memoised by (cursor, pending) and dropped by prompt_scan_pruned.
   Tauri commands prompt_scan(pane_key, terminal) -> {prompt, changed}, prompt_scan_restored,
   prompt_scan_pruned. A found prompt reaches the status model through the in-band path
   (status::status_inband with {"state": permission|waiting}, STAT-034) and a prompt that went away
   pushes {"state":"working"}, so status.rs is unchanged and the tab badge, Inbox and Board read it
   like any hook event. Registration is the lib.rs patch (below).
   Tests (prompt_scan::tests): orch056_claude_permission_trust_and_question_menus_are_read_off_the_screen,
   orch056_codex_and_cursor_menus_that_send_no_hook_are_approvals,
   orch056_a_composer_a_shell_prompt_working_output_and_an_answered_menu_are_no_prompt,
   orch056_restored_scrollback_never_counts_and_the_scan_is_memoised_until_pruned.

Decisions for Txais
- The scan reads the pane's output log (the same text the terminal shows), not the xterm grid; a
  menu older than 40 lines of newer output is answered or gone. If a menu redraws in place (Claude
  repaints its option list), the newest redraw is the one read.
- Cursor's exact menu wording is not in the spec, so recognition is generic: accept/reject pairs,
  y/n tails, pointer or numbered options starting with a choice word. A new agent's menu style is
  one line in OPTION_WORDS / APPROVAL_WORDS.
- "Finished item" = a completed parent-less task that was never dispatched. Dispatched work that
  finished keeps its worker row (ORCH-037 release states).
