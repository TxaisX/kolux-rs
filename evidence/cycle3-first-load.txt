== 6. Still over the bar: 359,889 bytes, and exactly what they are

Measured, not guessed (the App chunk's own bytes per module, from a temporary metafile build):

  @xterm/xterm + addon-webgl + addon-fit     566,536 rendered (~370 kB on disk)
        The terminal is the first frame: Terminals draws a PowerShell pane at start. Not deferrable
        without showing an empty pane on every launch.
  src/projects/ProjectsPanel.tsx + its dialogs 121,157 rendered (~76 kB)
  src/scm/SourceControlPanel.tsx                67,791      (already deferred: it is in pages.tsx now)
  src/terminal/TerminalPane.tsx                 59,252
  src/shell/WindowView.tsx                      54,977      the drawing itself
  @codemirror core (dist-BCxUsHlj.js)                315,352 on disk
        Held by ONE line: src/editor/buffers.ts:6 `import { isolateHistory } from "@codemirror/commands"`.
        @codemirror/commands imports @codemirror/view and @codemirror/language at module scope, so the
        whole drawing comes with the undo annotation. The annotation is compared by identity by the
        history extension, so it cannot be redefined locally: doing that would silently change undo
        grouping (EDIT-003/EDIT-056 behaviour). Fixing it means splitting buffers.ts into the store
        (light) and the transaction helpers that need CodeMirror (heavy) - editor/ work, not this lane's.
  src/onboarding/{Guides,StepPanels,Tours,tour}  65,800 rendered (~40 kB)
        First-frame through named helpers other modules import (useGuideState, TipView, noteUse).
  index-*.js                                         309,971 on disk
        React 19 + main.tsx. tower/TowerView and feedback/FeedbackDialog also land here through
        main.tsx's static import of tower/TowerWindow; deferring that would blank the Tower window
        between creation (Rust side) and its first draw, so it was left alone.

So the 1.5 MB bar needs, in order: (a) the buffers.ts split that releases @codemirror (~315 kB, which
alone would put the total at ~1.545 MB), (b) the guide helpers split out of onboarding/Guides (~40 kB,
which would then clear it), or the sidebars deferred behind a placeholder. (a) and (b) are editor/ and
onboarding/ files; the sidebars are visible first-frame elements, so deferring them trades a blank
sidebar for bytes. None of the three is in this lane's file set.

== 7. Behaviour kept

- Nothing is deferred that the first frame draws: top bar, layout strip, status bar, the left sidebar
  (sidebarOpen starts true), the pane grid, tabs, terminals (xterm) and the Agents rail stay static.
- The deferred wrapper keeps the element's place in the tree, so a pane's tab, close button, focus ring
  and dirty mark are the shell's, untouched; the body fills in a beat later (a file read has the same
  beat today). prefetch() reads all of them on idle after the window is shown.
- The 8 callers of openInBrowser keep one implementation (openIn.ts); BrowserPane re-exports the four
  names, and openDetail still returns the object it is given.
- Re-exports keep every existing import path working: EditorPane still exports editors/copiers, DiffPane
  still exports diffNav, markdown.ts still exports isMarkdown, linkClicks.ts still exports
  missingFileToast, FloatingLayer still exports floatingKeys.
