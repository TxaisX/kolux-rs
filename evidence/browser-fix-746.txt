after-list row 746 · T-319-c · BROW-052 Drags pass across browser pages
lane/browser, Sonnet 5.5 builder. Status: FIXED (live proof pending).

Cause
  Each browser page is a child web view in its own container window (window class WRY_WEBVIEW, made
  by wry). The container sits above the app's own view, so the system's "what is under the pointer"
  test (also used for drag-and-drop targets) lands on the page, and a drag that began in the app
  (tab, pane splitter, sidebar file) stops at the page's edge.

Approach (smallest that works with public APIs; no new dependency)
  While an app drag is under way every page container is DISABLED (EnableWindow FALSE). The system
  skips a disabled window when it looks for the window under the pointer ("WindowFromPoint does not
  retrieve a handle to a hidden or disabled window"), so the app's own view gets the drag. Unlike
  hide(), the page stays painted: it looks unchanged. A drag ending any way re-enables the pages.
  Option 1 (hide) was rejected as the primary because the page would vanish mid-drag; option 2
  (overlay in the main view) needs the app's view to be above the pages, which it is not.
  FALLBACK if the live proof shows a disabled container still takes the drag: in
  browser_drag.rs::apply call each page's hide()/show() instead of set_enabled (one-line change).

Files
  src/browser/dragThrough.ts          state machine (gate) + window event wiring
  src/browser/dragThroughInstall.ts   installs it once, imported by BrowserPane.tsx
  src-tauri/src/browser_drag.rs       browser_drag_through command, dead-man timer, settle(), set_enabled
  src-tauri/src/browser_holder.rs     containers() accessor
  src-tauri/src/browser.rs            mod drag; drag::settle in browser_open's web view callback
  evidence/browser-fix-746-lib.rs.patch   registers browser_drag_through (apply after the 719 and 151 patches)

What counts as a drag, and every way it ends
  starts: dragstart (tab, file, session rows: all HTML5 drags); a pointer press that moves 6 px
          with the primary button down (pane splitters, panel moves, explorer pointer drags).
  ends:   dragend, drop, pointerup, pointercancel (only ends the pointer kind), lostpointercapture,
          Esc, window blur (not in the first 250 ms), window hidden, any mouse move with no button
          down (a lost dragend), stopping the watcher, and app start-up (heals a reload).
  Back end: the front end renews every 20 s while a drag lasts; the back end gives the pages back by
          itself 60 s after the last call (dead-man), so a dead front end cannot leave a page dead.
  A page made in the middle of a drag (browser_open) is disabled as it appears (settle).
  Never touched: any window whose class is not WRY_WEBVIEW (the app's own window is safe).

Tests
  vitest src/browser/dragThrough.test.ts (gate edges, every ending, grace, renewals, wiring).
  cargo test browser::drag (Through state, dead-man outdated by renewal, class guard).

REVIEW FIXES (read-only review: MERGE OK WITH FIXES; lane/browser, Sonnet 5.5)
  H1  browser_drag_through is async, so a start and an end could run on two pool threads and queue
      ENABLE then DISABLE on the main thread (pages stuck disabled, never expired), or the end could
      reach the state before the start (pages dead for 60 s). Now: the main-thread job reads the
      CURRENT state and holder::containers() when it runs (apply_now), so the last job to run always
      matches the latest state, the watchdog's expire path and settle included; and the front end
      numbers every call (seq, createSeq: clock-based and strictly increasing, so a reloaded window
      stays above the old one) and the back end ignores a call whose seq is not newer than the last.
      A call with no seq (older front end) is accepted. Tests: cargo browser::drag
      t319c_a_numbered_call_that_is_not_newer_is_ignored, t319c_a_call_without_a_number_is_accepted,
      t319c_the_last_main_thread_job_wins_whatever_order_the_jobs_run_in,
      t319c_an_end_that_reaches_the_back_end_first_leaves_pages_enabled; vitest "call numbers" and the
      installer wiring check.
  H2  the 20 s renew ran for as long as the gate said "on", so a missed dragend (source re-rendered
      away, drop outside the window, cursor over a disabled page) kept the pages dead for ever. Now a
      renew tick renews only if dragover, drag, or a pointermove with the button down was seen since
      the last tick; otherwise it resets the gate and sends on=false. Tests: vitest "no drag activity
      across a renewal tick resets the gate", "dragover, drag and a button-down move each count",
      "activity seen before one tick does not carry over", "a button-less move is not activity"; the
      renewal test now fires dragover between ticks. Cost: a pointer drag held perfectly still for
      20 s is released; the next move with the button down starts it again.
  NIT wry's DestroyWindow on window.close() never calls holder::forget, so a stale HWND could be reused
      by another wry app's container. set_enabled now also requires GetWindowThreadProcessId(hwnd, &pid)
      to give GetCurrentProcessId (that call's return value is the thread id; the process id comes back
      through the out parameter), and an HWND failing the class or pid check is dropped from the list
      (holder::forget_container). Raw extern "system" user32/kernel32; no new feature or dependency.
  lib.rs patch: the command name is unchanged (generate_handler! lists names), so
      evidence/browser-fix-746-lib.rs.patch needs no re-cut; all five patches still apply in order.
