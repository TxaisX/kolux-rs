T-318 (EDIT-055 new notes can start from the repository's own templates), 2026-10-19
Lane editor, from ab6c9df2 (main d823b3f8 merged in first). No app launch (batched live proof below).

What changed (src-tauri/src/files.rs, src/editor/templates.ts, src/editor/TemplatePicker.tsx)
- md_templates (new Tauri command) lists the markdown files under <repo>/.kolux/templates (md and markdown,
  subfolders searched six levels deep, at most 200). Dependency folders (node_modules, vendor, target, .git,
  .venv and the like) are never entered; symlinks and junctions, to files or folders, are skipped, and a
  .kolux or templates folder that is itself a link counts as no templates folder. Names come from the file name
  ("meeting-notes.md" shows as "Meeting notes"), sorted in natural order (File2 before File10).
- md_new takes an optional template. Without one it still makes an empty untitled.md / untitled-2.md. With one,
  only a path that md_templates itself lists is accepted (anything else is refused and nothing is made), the
  text is read, its placeholders are filled and the result is written into the new untitled note, a real file.
- Placeholders: {{title}} (the note's name without .md), {{filename}}, {{date}} (2026-10-09), {{time}} (07:05,
  24-hour), {{datetime}}. Case, spaces, dashes and underscores inside the name are ignored ("{{ Date }}" works);
  unknown or unclosed {{...}} stay exactly as typed.
- TemplatePicker.tsx (rendered by App.tsx, see the wiring patch): lists Blank first and then each template;
  arrows, Enter, click choose; Escape or a click outside makes nothing. With no templates, or if the list call
  fails, it never shows: a blank note is made and opened at once (the old Mod+Shift+M behaviour).
- The template note is a file on disk with content, so it is kept when closed untouched. A future EDIT-054
  (delete an untouched blank note) must treat a note made from a template as not blank.
