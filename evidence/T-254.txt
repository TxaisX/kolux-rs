== ACCT-060 · modes reset when the program exits ==
- src/terminal/modeReset.ts (new): resetAfterExit(modes, altScreen) gives the DECRST sequences for what the program left on:
  alt screen off first (CSI ? 1049 l, only when the alternate buffer is active), synchronized output off (2026), every mouse
  protocol and encoding off (9, 1000, 1002, 1003, 1005, 1006, 1015) when any tracking mode is on, focus reporting off (1004),
  bracketed paste off (2004), application cursor keys (1) and keypad (66) off, and always the cursor shown (CSI ? 25 h).
  modeView() reads xterm's IModes defensively. Sources: ECMA-48 CSI, xterm ctlseqs DECSET/DECRST list, xterm.js IModes typings.
- src/terminal/TerminalPane.tsx terminal-exit listener: term.write(resetAfterExit(modeView(term.modes), buffer is alternate))
  before the "[process ended]" line. Written INTO xterm, never to the PTY; only on exit, so a running agent keeps its hidden
  cursor and a restarted one hides it again itself (card box 2).

== ACCT-053 · wide characters shown once ==
- Console layer: cmd starts with chcp 65001 (pty.rs CMD_ARGS); PowerShell switches its console to UTF-8 first thing
  (T-223-b, evidence/core-T-223-b-shell_marks.rs.patch). xterm gets raw PTY bytes (base64 across the border, codec.ts) and
  decodes them with its own streaming decoder, so a CJK character or emoji split across two PTY reads is one character.
- Redraw buffer: src-tauri/src/terminal.rs trim_history (the TERM-106 per-pane output log replayed on a restored pane)
  starts the kept tail at the next line break; a tail without one (one huge line) now starts at the next UTF-8 character
  boundary, so a replay never begins with the stray trailing bytes of a wide character (each drawn as a replacement glyph).
- ConPTY's own repaint of wide glyphs is checked live (below); the pane already runs xterm with windowsPty backend conpty.
