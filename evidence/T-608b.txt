Proved in the Linux cloud sandbox (node 22, vitest 4.1.11). Nothing was run on Txais's PC.

THE ANSWERS
1. A pane blocked by a usage limit or a sign-in still counts as needing you in the Inbox and on the bell.
   Nothing changed; a test proves it (passes on the untouched base a7f3f406).
2. An agent whose program has exited shows as "Stopped" in the Inbox, not "Done today", as on the Board and Tower.
3. Ctrl+J and the tab badges count only permission requests and questions (the one status, board/chip.ts),
   not the pane header's own attention flag.

AUDIT: WHAT RELIED ON THE OLD RULES (searched before changing 2 and 3)
grep -rn "needsAttention|needsYou|needs\[|tabBadge|nextNeedsYou|onNeedsYou|inboxItems|GROUPS|canReview" src
- Ctrl+J (App.tsx terminals.focusNextNeedsYou): read `needs` (TerminalPane header flag: blocked, interrupted,
  failed, permission, waiting). Now needsYou(statusOf(p)).
- Tab badges: App.tsx tab strip (TabBadge) and the palette's Open tabs rows (VIEW-040 mark) both fed
  needs[p.key] to tabBadge. Now needsYou(statusOf(p)). A blocked or interrupted agent used to get the question
  mark; under the new rule it would have shown the Working spinner, so tabs.ts gains a "stopped" badge (the
  Stopped vocabulary, VOCAB.stopped) for it; an unseen stop keeps the unread bell.
- Keyboard tests that mirrored the old rule (TERM-030): src/terminal/__cards__/TERM-030.test.ts and
  VIEW-047.test.ts built the jump set from headerOf(...).needsYou. Both now mirror the one status; TERM-030 gains a
  test that a blocked or interrupted pane is not a stop. tabs.test.ts, TERM-055.test.ts, TERM-118.test.ts pass
  booleans into tabBadge directly and are unaffected.
- The bell and the window title (App.tsx needing -> TopBar needsYou, windowTitle): unchanged by answers 2 and 3
  (answer 1 keeps blocked; interrupted still counts, as on main). See T-612b (c) for the failed-start fix.
- The needs strip (waitingInGrid over statusOf): already permission/question only; unchanged.
- The Inbox groups (inbox.ts): "Done today" took any running===false agent pane (paneState gives "done" when
  the program ends). inbox.test.ts (T-035-b test, row 4) expected that row in "done"; it now expects "stopped".
  The Inbox's Review changes button (board/review.ts canReview) is offered on "done" rows only, so an exited agent
  no longer offers it in the Inbox, the same as the Board's Stopped lane. STAT-050.test.ts, EDIT-041.test.ts,
  review.test.ts, exitedPrompt.test.ts pass unchanged.
- Notification code: App.tsx onRunning still sends the "finished" desktop note when an agent's program ends
  (TERM-118/STAT-041), and status/notify.ts turnNote is untouched; neither reads the Inbox groups. Not changed.
- Sidebar row (paneState, smartClass) still sorts an exited agent with the finished ones; not part of the answer.
- Docs (not this lane's files): docs/guide/board-agents-inbox.md describes three Inbox groups.

WHAT CHANGED
- src/board/chip.ts: needsYou's note names Ctrl+J and the badges; needsAttention's note records answer 1.
- src/inbox/inbox.ts: a fourth group "Stopped" (after Done today) for agent panes whose program exited, with the
  same 30-minute window and 20-row limit; its rows read the Stopped vocabulary. Done today keeps running agents
  whose turn is done.
- src/terminal/tabs.ts: Badge "stopped" for a blocked or interrupted agent.
- src/App.tsx: Ctrl+J and both tabBadge calls read needsYou(statusOf(p)).
