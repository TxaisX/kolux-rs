What it proves (T-260-b nesting + T-260-d no-parent nesting, both already unit-tested in activity.rs)
- A coordinator pane starts a worker for a task with no parent task: the worker's Floor lane nests one level
  under the coordinator's lane (dispatch records fromTerminal; cli.rs on this checkout already writes it).
- A worker whose task names a parent task nests under the lane that ran the parent task, two levels down.
- A worker started from a spec with no parent task nests under the coordinator.
- Every lane's bar starts at the axis (the name column grows with the depth and the bars stay in line).

WHAT THE SCRIPT DOES (so a FAIL can be read)
- Sets agentOptions.claude.command to a stand-in .cmd (no real agent starts): it posts SessionStart and
  UserPromptSubmit like Kolux's hook, writes its terminal handle to handles.txt and then runs command files named
  do-<handle>.cmd. Binds view.floor to Mod+Alt+Shift+F for the run. Both are put back in a finally block.
- Adds a throwaway git repo as a project, opens four Claude Code tabs (stand-ins) A, B, C, D.
- Through A's command file (so the kolux-dev calls carry A's own terminal identity): run-create, task-create
  (parent), worker-start --task <parent> --terminal B, task-create --parent <parent>, worker-start --task <child>
  --terminal C, worker-start --spec ... --terminal D, dispatch-show on D's task.
- Opens the Floor and reads each .floor-lane (data-depth, "Terminal N") and the bar/axis left edges.
Expected: A depth 0, B depth 1, C depth 2, D depth 1, one bar start for every lane equal to the axis start,
dispatch-show of D's task carries fromTerminal = A's number.

UNPROVEN ASSUMPTIONS (read before calling a FAIL a product bug)
- The reused-terminal worker-start path wants the stand-in pane to be recognised as a Claude agent, in the
  coordinator's worktree folder; if worker-start answers not_an_agent or wrong_worktree, the out-*.json file in the
  temp folder says so and the stand-in (not nesting) is at fault.
- dispatch --inject types the brief into the stand-in pane; the stand-in ignores it. A not_submitted answer would
  fail the "workers started" check without being a nesting bug.
- Envelope shape of kolux-dev --json: the script reads the first "id" matching task-* and the first "dispatchId"
  anywhere in the answer; a different shape fails the run with the file named.
- The Floor refreshes every 5 s; the script waits up to 60 s for four lanes.
