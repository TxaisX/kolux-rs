  Claude replies: chat.rs:383 msg_id = message.id, else the line's uuid, else "line-<n>". A text block takes that id (chat.rs:399): the first
    text part is exactly msg_id, a later text part of the same message (after a tool call or a thought) is "<msg_id>#1", "#2"... (chat.rs:395-399).
  Codex replies: chat.rs:452 id = payload.id, else "line-<n>".
  line_no (chat.rs:269) counts parsed lines from the parser's first line.
  Unique: yes within one parse. Claude message ids and uuids are distinct per reply/line; the #n suffix and line numbers are distinct per item.
    Two replies with the same words therefore have different ids (the case the tests pin).
  Stable per reply: yes when the id comes from message.id / uuid / payload.id (it does not change when the file is re-read; applyRead
    merges by it, model.ts applyRead). Two limits, stated not fixed: (1) a "line-<n>" fallback (Codex message without an id, a Claude line
    with neither id nor uuid) is only as stable as the line count, and the count restarts if the file is rotated or the first read was
    capped (chat.rs:533-536 drops to the first whole line in the newest bytes), so after such a reset the same reply could get a new
    "line-<n>" id and the refusal note would go (fails safe: the note disappears, never shows on the wrong reply);
    (2) when a reply's later text part arrives, the last-reply id moves from "<msg_id>" to "<msg_id>#1", so a note kept for the earlier
    part goes the same safe way. Neither can show a note on a different reply.
