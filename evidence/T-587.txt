T-587 · Releases publish: release.mjs defines onGitHub (X-proc.1; APP-059; DT-R11)
lane/release-ci, 2026-10-30, Linux cloud sandbox (node 22.22.0, pnpm 10.28.0, vitest 4.1.11)

WHAT WAS WRONG
scripts/release.mjs called onGitHub() at latestRelease (old :162) and before publishing (old :261), but
never defined it. Every real release (pnpm ship --main, release.yml, pnpm release --dry-run) stopped with
"release failed: onGitHub is not defined"; only rehearsals with KOLUX_RELEASE_PUBLISH_DIR got past it,
and that is all the old tests ran.

WHAT CHANGED
- scripts/release.mjs:87-88  onGitHub(repo, env) = isGitHub(repo) || env.GITHUB_ACTIONS === "true"
  (DT-R11: gh runs only for a GitHub origin or inside GitHub Actions, whose release.yml builds from a
  local path, so isGitHub alone would refuse every CI release).
- scripts/release.mjs:184  buildOnce(o, env, run = sh): every outside program the job starts (gh, pnpm,
  cargo, the packaged CLI) goes through `run`, so a test can stand in for them; git still runs for real.
  latestRelease (:160-176) asks gh through `run` with the job's env (a gh failure still means "no release
  yet", as before).
- scripts/release.mjs:147-156  the Windows .cmd-shim handling moved from the deleted tool() helper into
  sh (opts.shim), quoting only arguments that hold spaces; the hand-quoted "--config" path is gone, so
  the argument is also right off Windows.

TEST (written first)  scripts/release.test.mjs:96-191  "release job publishing to GitHub, with gh stubbed"
  1. inside GitHub Actions, from the local checkout release.yml passes, it asks gh for the newest release
     (v0.1.7) and publishes the next (0.1.8): gh calls are exactly view, create (installer + .sig), upload
     (latest.json, last); notes list the scratch main's commits.
  2. a main that was already released (gh's body carries its marker) is skipped; only gh view runs.
  3. a repository neither on GitHub nor in GitHub Actions: gh is never called; a dry run says 0.1.1;
     a real run refuses with "is not on GitHub, so nothing is published".
