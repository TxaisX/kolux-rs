Bug (main): with no ~/.claude/settings.json, the first install created it and wrote no record,
so every later start failed with "already holds Kolux's hook entries but has no .bak-kolux copy"
(updates to Kolux's entries never landed); switching off left the file as `{}`. Gemini CLI's and
Antigravity's files were left as `{}` the same way.
Fix (src-tauri/src/agent_hooks/mod.rs, vendors.rs):
- back_up: a file about to be created gets a record line `missing  <file>` (written synced, then
  renamed, like the hash record). A file holding Kolux's entries with no copy is accepted when its
  record says it was missing; otherwise the refusal stays (T-152-c (4) test unchanged and green).
- drop_created: on removal, when what is left is `{}`, there is no kept copy and the record says
  missing, the file is deleted (only while it still holds the bytes Kolux read, else the usual
  "changed since it was read" error) and the record goes with it. Used by Claude's remove and by
  Gemini CLI's and Antigravity's write_back. Gemini/Antigravity keep_copy now runs back_up for a
  file about to be created, so it is recorded.
