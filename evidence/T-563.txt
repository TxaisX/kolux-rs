T-563 · a late hook from a retired terminal never takes the pane back; in-band status names the live terminal
lane/hooks from b93b335 (after STEP 0 merge 68a4500 of main 26baada), 2026-10-14

What changed (src-tauri/src/status.rs)
- terminal_ended(terminal) now records, for every pane whose session it removes, that the
  terminal is retired for that pane (newest last, at most 16 per pane; terminal ids are never
  reused within a run).
- report() checks that record first: a hook whose terminal is retired for this pane is dropped
  (returns None) before the session is created, adopted, applied or emitted. A hook with no
  terminal, or from a terminal retired only for another pane, goes through as before.
- status_inband takes an optional `terminal` (the pane's live terminal as the window knows it).
  The activity lane is noted for `terminal.or(session.terminal)`; the session does not store it.
  An older window that sends no terminal behaves exactly as before. The fold moved into a private
  inband_change() so it can be tested without an app handle.

Why: after a Restart, a Stop still in flight from the old terminal used to set the session's
terminal back to the old one. The new terminal's exit then found no pane (panes_of(NEW) empty),
so the Floor lane stayed open as "working" and Stats over-counted at quit.
