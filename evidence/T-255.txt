T-255 · ORCH-042 [compat] Agent Teams teammates open as real side-by-side panes
Lane orchestration, BEFORE 46d15306 (main merged in), Opus builder, 2026-10-20. LEFT OPEN.

Why open (the missing documented interface)
- Claude Code's public agent-teams page (https://code.claude.com/docs/en/agent-teams, read 2026-10-20)
  says split-pane mode "Requires tmux, or iTerm2" (teammateMode "auto" / "tmux" / "iterm2", the
  experimental --teammate-mode flag), lists Windows Terminal, VS Code's terminal and Ghostty as
  unsupported, and documents no way for a host terminal to receive teammate pane requests itself.
  COMPAT ORCH-042 (a tmux stand-in exposing TMUX and TMUX_PANE) would mean faking tmux, which no
  public Claude Code doc describes as supported, so it is not built and nothing sets those variables.

What is built (src-tauri/src/orchestration/teams.rs, host-neutral, not wired: #[allow(dead_code)])
- parse: one request in tmux's public command language (https://man.openbsd.org/tmux.1):
  split-window/splitw (-h side by side, -v default, -l cells or N%, -t, -c, -e, -P, -F, command
  after the flags or after --), send-keys/send (-t, -l), display-message/display -p, list-panes/lsp
  -F, kill-pane/killp, respawn-pane/respawnp, -V; tmux's own leading options skipped; getopt-style
  bundles (-dPl30, -t%1); unknown flag, missing value, 0 cells, over 100% -> an error, not a guess.
- Team::place: the first teammate splits the leader to the right; every later one splits the newest
  teammate down, so three teammates make one column of three beside the leader (ORCH-042 acceptance 1
  as a decision; the request's own -h/-v side and -l size do not move it).
- Team::decide: split -> Open at the placement (command joined, team folder when no -c, -P format);
  the 12-pane workspace ceiling refuses the 13th; send-keys -> typed text with Enter/C-m/KPEnter as
  separate presses (-l types words as they are); display-message -p / list-panes -> #{...} formats
  with unknown fields empty (#D #P #S #I, ## kept); a teammate cannot respawn or kill the leader pane;
  kill-pane on a teammate closes it; any other command is refused by name.
- Teams::ended: the leader's exit returns every teammate handle to close and drops the team
  (ORCH-042 acceptance 2 as a decision); a teammate's exit only removes it; pane ids never reused.
- mode / saved_mode: panes only with a usable absolute path to a Claude program file, else in-process;
  reuses T-191-b's saved Agent Teams mode (agentTeamsMode: off / in-process / native; Windows and WSL
  always in-process), no new setting.
- split_event / close_event: the pane open and close in exactly the cli-workspace event shapes
  `terminal split` and `terminal close` already send (kind terminal-split handle/dir/command/ask,
  kind terminal-close handles), so the window's existing splitPane / dropPane path opens and closes them.

Not built (needs the documented interface above): installing the stand-in and its TMUX/TMUX_PANE
variables, rewriting a teammate's direct Claude launch, a restored Agent Teams terminal coming back in
native-panes mode, and T-191-c's launch switch (claude-teams still forces in-process, cli.rs).
