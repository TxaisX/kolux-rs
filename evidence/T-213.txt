Lane i18n, from b9c22233, 2026-10-20 (v3; replaces the withdrawn 2026-10-13 whole-folder copy)

What is imported
- Only settings, from exactly one file in the former folder: its settings file (settings.json, or the
  same name under the former product's name, any letter case), a plain file, at most 1 MiB, never
  through a link or junction.
- Each saved setting takes its current name (renaming rule: nightshiftX -> koluxX, nightshift. -> kolux.,
  then a kolux camelCase prefix read as the bare name) and carries only when:
  the name is on the allow-list import::CARRIED (34 settings, each checked against the field the
  settings pages read): language, uiLook, firstScreen, appIcon, paneHeaderDensity, sessionListView,
  sessionListScope, scmView, defaultAgent, notificationSound (short words); disabledAgents (word list);
  leftSidebarWidth, defaultPaneCount, notificationVolume, quietMinutes (numbers); notifyOnFinish,
  notificationsOn, notifySuppressFocused, needsStrip, keepAwake, renameBranches, renameFolders,
  confirmCloseRunning, confirmWorkspaceDelete, confirmAutomationDelete, generatedTabTitles,
  pinnedTabsAsk, linksOpenInKolux, markdownReviewNotes, scmDiffSplit, allChangesSideBySide,
  allChangesTree, allChangesWhitespace, allChangesWrap (on/off);
  AND the value has the listed shape (a word is <= 64 chars of letters, digits, space and . _ - : +);
  AND neither name nor value looks secret (names holding token, secret, password, cookie, credential,
  auth, apikey, privatekey, bearer, vault, hook, prompt, transcript, proxy, session url, or ending in
  key/keys; values starting like sk-, ghp_, github_pat_, xox, AKIA, eyJ, "Bearer ").
- A value already saved in this profile wins; a current-name spelling beats its former spelling.

What is skipped (counted in the summary, never named, never opened)
- not on the list (unknown settings, retired settings, kolux.-prefixed interface preferences, which this
  rebuild keeps in the window's own storage), secret-like names or values, wrong shape, every other item
  in the former folder (hook scripts, key vault, cookies, transcripts, keybindings, caches, logs), links
  (never followed), and a settings file that is too big, held by another program or not an object.
- Project, repo and worktree records: not carried; no allowed source describes their former shape.
  Moved to T-213-b (blocked).

Flow: first_launch(profile, store) -> fenced profiles (debug/test builds, lane or non-production
identifiers) never run -> once per profile (store key former_name_carried) -> lock file
former-import.lock (taken over after 10 minutes) -> read_former (no store lock held) -> plan (the
preview: what would be added, kept, skipped) -> apply (Store::patch_settings: temp file renamed into
place, last good copy kept) -> summary of counts stored and written to the diag log. This profile's
settings unreadable -> stops without marking done.
Wiring: evidence/i18n-T-213-lib.patch (lib.rs setup, background thread 8 s after setup; emits
settings-saved when something was added so the page re-reads). Until the resolver applies it the
module keeps allow(dead_code) outside tests.
