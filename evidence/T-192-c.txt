T-192-c · AUTO-009 keep one agent session across runs · lane/automations from 4226dcad · 2026-10-19 · Claude Sonnet 5.5

What the user can now do: in New / Edit Automation, with "An existing worktree" chosen, tick
"Continue in the session the last run left open, when the agent is idle there". The next run of
that automation then types its prompt into that agent session (same tab) instead of opening a new
background tab. It does so only when the last run is over, was this automation's own run in the
same worktree with the same agent, no live run holds that pane, the pane is still open and still
the very same pane, and the agent's hooks report it idle ("done"). Anything else (tab closed,
agent busy, agent without hooks such as Gemini, a restart in between) opens a new session as
before. A new worktree for every run always opens a new session; asking for reuse there is
refused ("a session can only be kept across runs in an existing worktree").

Code:
- src-tauri/src/automations.rs
  - save_automation: field reuseSession (stored false unless existing mode; left out on an edit keeps
    it; an edit into new-per-run that says nothing drops it; true with new-per-run refused). This is
    what the CLI's --reuse-session / --fresh-session (T-197-c) will send.
  - trait Panes { idle(terminal, pane_key), send(terminal, text) }, implemented for Terminals
    (idle = attached(pane_key) == terminal and status::state_of(terminal) == "done"; send = bracketed
    paste, a quarter second, Enter) and for the AppHandle. A process-wide registry (use_panes,
    called by start_clock) holds it, so Launch and its constructors (automations_cli.rs belongs to
    another lane) are unchanged and no patch is needed.
  - reusable(store, auto, folder, panes): the checks above, on the automation's newest run that
    had a pane.
  - place_and_start returns Placed (worktree, project, session); when a session takes the prompt no
    "start" event goes to the window. run_with then stamps the new run with terminal, paneKey and
    reused: true, so the hooks follow the run in that pane (the earlier "done" does not count
    until the agent worked, as for every run).

- src/automations/AutomationDialog.tsx: the checkbox, shown for an existing worktree only, sent as
  reuseSession (false for a new worktree).
