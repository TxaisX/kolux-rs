1. Issue command override (PROJ-036, tied to SAFE-025 / T-156)
   Before: .kolux/issue-command was read from the main folder, then the worktree, with no check
   of whether git tracks it. A branch that committed one therefore ran as "shared: false", which
   is the user's own and needs no trust.
   Now: the override is read only from the main folder, and only while
   `git ls-files -- .kolux/issue-command` prints nothing there. If git cannot tell (not a
   repository, or git is missing), it does not count either. A worktree's copy is never read.
   A committed override is ignored, and the shared kolux.yaml command (shared: true) applies.
   Test: setup::tests::proj036_a_committed_issue_override_never_counts_as_the_users_own. It uses
   a real repository with the override and kolux.yaml committed, plus `git worktree add`, and
   checks:
     - main + worktree gives the kolux.yaml command, shared;
     - with no kolux.yaml, None;
     - after `git rm --cached` in main, the user's own (shared: false);
     - the worktree read as root gives None;
     - a folder outside any repository gives None.
   The existing test proj036_a_create_from_issue_12_runs_the_command_and_the_local_one_wins now
   runs `git init` in its main folder.

2. Archive runner hardening (STAT-055; still unregistered, waiting for T-156 and an async remove)
   - The script's process joins a kill-on-close job right after spawn. On timeout the job is
     closed and kill_tree (taskkill /T /F) runs, so processes it started end with it.
   - The run returns Result<bool, String>: Ok(false) means there is no script, Ok(true) means it
     exited 0. Otherwise the error ends with the last 2 KB of its error output, read on its own
     thread so a full pipe never stalls the script.
   Test: setup::tests::stat055_a_failed_archive_script_says_why_and_a_stopped_one_takes_everything_it_started
     - `echo boom 1>&2 && exit 3` gives "The archive script failed with exit code 3: boom".
     - On Windows, slow.bat starts a second cmd that would write late.txt after about 5 s.
       Stopped at 1.5 s, late.txt is still absent 7 s later.
     - First attempt, with taskkill /T alone: this assertion FAILED (cargo-fix-2.log, "the
       process the script started was ended with it"). Under load the grandchild was started
       while taskkill was running. The job closes that race.
