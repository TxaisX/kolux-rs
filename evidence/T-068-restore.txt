T-068 · TERM-106 Restore after the background host or computer died — live proof, 2026-10-12 (lane core, dev app on 1424, dark, new look, 1920x1032 maximised on the second screen, pane 186x57)

How it is built
- terminal.rs: every pane's pty output is appended to <app data>/history/<pane key>.log (opened per chunk, so a crash at any moment leaves a usable copy); past 256 KB the file is rewritten down to the newest 128 KB (from a line boundary) through a temp file and a rename. Commands: terminal_history (the newest 128 KB, base64), terminal_forget_history (a tab closed on purpose), terminal_prune_history (after a start, files of panes no longer in the layout; nothing when the list is empty; files not named by a pane key are kept), terminal_history_append (what the pane itself wrote during the restore).
- history.ts: replay strips the sequences the terminal would answer (cursor position, device attributes, focus reporting); restoreTail writes the reset, the note under the last text, pushes the screen into the scrollback and parks the cursor at the top; that tail goes into the file too, so the file stays a transcript of everything the terminal processed and the next restore replays the same screen.
- TerminalPane.tsx: a pane back from the saved layout replays the file before terminal_spawn; the view follows the new shell's first frames (viewTop: the prompt row last in view, note and old output above) and lets go at the first key. App.tsx forgets the file of a pane closed on purpose; main.tsx prunes after the layout is read.

Findings
- ConPTY's output is a screen-oriented stream (home + full repaints, absolute cursor moves), not a scrollback transcript. A verbatim replay reproduces the last screen only from the same start state at the same size; at a different size it is approximate (frames land as separate screens).
- At a shell start ConPTY asks the cursor position and paints its first frame from the cursor it finds; after a resize it repaints the whole screen from the top. The restore parks the cursor at the top after pushing the old screen into the scrollback, so the new prompt lands under the note either way.
- The terminal's answers to the shell's start-up questions (cursor position report, focus in) go through xterm's onData, so "the user typed" must be read from onKey.
- A resize clears xterm's user-scroll flag, after which output snaps the view to the bottom; the restore view therefore follows each parsed write until the first key instead of being set once.
- Not built (by the card's own terms): no background host exists, so the partly-typed-line discard and the hold after a replaced host do not apply; a finished local agent is not restarted (T-066's restore behaviour, unchanged); large histories are kept to one piece (256 KB cap, 128 KB replayed); a corrupt tab record is dropped by restoreLayout (T-065).
