T-174-b · ORCH-055 Prompts typed into agents land exactly once
lane/orchestration from 4148df12 (main 6cf66db4 merged) · 2026-10-19 · Routing v3 (build first, fix later)

WHAT THE USER CAN NOW DO
Send a prompt from the command line (`kolux terminal send --text ... --enter`) or hand a brief on with
`orchestration dispatch --inject`, and it lands once: the text waits until the agent's input box has
drawn and settled, goes in as one paste, and Enter follows exactly once after a pause sized to the prompt.
Sixteen prompts queued at one agent go in one after another, none merged or doubled. A prompt sent while
the agent shows a permission prompt is turned away as `blocked` with nothing pasted. A retry with the
same --retry-request id after a Kolux restart answers with the first receipt instead of sending again.

DECISIONS (defaults taken, for Txais)
- Pause before Enter was 300 ms flat everywhere; now Windows 60 ms + 40 ms/KiB (cap 1.5 s), elsewhere 60 ms.
- Settled = 250 ms without output, capped at 5 s; an agent that has never written is not waited on.
- Large paste = 4 KiB and up: Enter also waits for the echo to settle (same 250 ms / 5 s).
- A bare `--enter` with no text goes at once and is never refused as blocked: it is how a permission prompt gets answered.
- Permission marks in output: only phrases the public tools print ("Do you want to proceed", "Do you want to allow",
  "Do you want to make this edit", "Yes, and don't ask again", "Allow once", "Allow for this session", "Allow command",
  "Approve this command"), scanned over the last 8 log lines, so a prompt that talks about permissions is not mistaken for one.
- Receipts: 100 kept, 24 h TTL, key orchestration.sends (inside the orchestration store, ORCH-034).

LIVE PROOF PENDING (batched; needs a real agent run, so no builder runs it)
1. Open a Claude tab in a throwaway repo under the scratch home; let the welcome screen settle.
2. From another pane: for n in 1..16: kolux-dev terminal send --terminal term-N --text "say only the number $n" --enter --retry-request p$n.
   Expect 16 turns in the tab, each answer one number, in order 1..16, no merged prompt, no empty turn (a doubled Enter shows as an empty turn).
3. Run step 2's last command again (same --retry-request p16). Expect the same receipt with retried true and no new turn in the tab.
4. Make the agent ask a permission (e.g. ask it to run `echo hi` in a non-auto mode). While "Do you want to proceed?" shows,
   kolux-dev terminal send --terminal term-N --text "hello" --enter. Expect exit code of a `blocked` failure, the message naming the prompt,
   and nothing new in the input box. Answer the prompt with kolux-dev terminal send --terminal term-N --enter (a bare Enter is allowed).
5. Send a prompt of 20 KB (--text from a file) and expect one turn, the whole text in the box before Enter (no cut-off tail).
6. Start a send with --text and, inside the pause, type a character in the tab. Expect receipt stale, enterHeld true, the text left in the box, no turn started.
7. Restart Kolux, repeat step 3: the retried receipt still comes back (the store kept it).
