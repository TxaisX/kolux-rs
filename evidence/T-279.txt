T-279 · ORCH-035 A task that keeps failing is no longer handed out (ORCH-057 / ORCH-059 split to T-279-b, core lane)
Date: 2026-10-13 · lane/orchestration from 07c5d80

Rules as built (src-tauri/src/orchestration.rs, dispatch_check, the one check every dispatch and
worker-start goes through):
- Breaker: once 3 dispatches of the same task in the same Run have ended failed, the next dispatch
  of that task is refused with code breaker_open and the message
  "<task> failed 3 times, so Kolux holds it back instead of handing it out again".
  A completed dispatch in between does not reset the count (the card resets nothing); the count is
  read from the task's kept dispatch records, so it lasts until the task is retired. Failures of the
  same task id in another Run, or of another task, do not count.
- Busy: a dispatch to a terminal that already holds an unfinished dispatch is refused with code busy
  ("<terminal> is already working on <dispatch>"); once that dispatch has finished the terminal is free.
  (Busy existed since T-083; the new test pins both its refusal and its release.)
- Order of refusals: not_found, task_waiting / task_taken / task_not_ready, breaker_open, own_pane,
  not_an_agent, busy.
