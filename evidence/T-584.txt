T-584 (status-hooks lane, 2026-10-30): Claude hooks install even when settings.json has an empty hook list
=========================================================================================================
Audit R02-hooks-status.4 (then hooks.rs:1001; the check is at hooks.rs:1081-1093 now).

THE PROBLEM
~/.claude/settings.json holding "hooks": {"Stop": []} (other hook tools leave this behind when they uninstall):
- install_groups adds Kolux's group to the empty Stop list. The self-check then sets Kolux's entries aside on both
  sides with remove_groups: on the new file, stripping Kolux's group empties Stop and clear_unused drops the key; on
  the original, there is nothing to strip, so "Stop": [] stays. {"hooks":{}} never equals {"hooks":{"Stop":[]}}, so
  every start and every switch-on failed with "the install would change more than Kolux's entries; hooks not
  installed", which does not say why. once_more retries only a file that changed, so it never got past this.
- Removal had the twin problem: the emptied key is dropped, so the result never matched the kept copy and the file
  was rewritten without the user's "Stop": [] instead of coming back byte for byte. Codex's hooks.json removal the same.

WHAT CHANGED
- src-tauri/src/agent_hooks/mod.rs:111-119 without_empty_lists(): a {"hooks": {...}} file as the checks compare it; an
  event whose list is empty holds no entries, so it reads as absent.
- src-tauri/src/hooks.rs:1083-1093 the install self-check compares both sides through it (the empty list is ignored on
  either side; anything else the install would change still refuses the install).
- src-tauri/src/agent_hooks/mod.rs:184 (Claude) and :208 (Codex): removal compares the result with the kept
  .bak-kolux copy through it, so the copy's exact bytes, empty list included, are written back.
Nothing else in the install or removal changed: Kolux's group still goes into the empty list, and a user's own
entries are never touched.
