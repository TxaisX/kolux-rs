WHAT CHANGED
- Rust (src-tauri/src/setup.rs): a project's script trust lives in the store under scriptTrust:<project id>
  as {all, scripts{kind: sha256 of the script with CRLF made LF}}. A project removed and added again gets a
  new id, so its trust is forgotten. Kinds: setup, archive, issue (the VM recipe goes with area 18; default
  tab commands with T-149).
- The runners refuse an untrusted shared script themselves (fail closed): workspace_setup (setup), the issue
  command (workspace_issue_command, checked after git so the store is not held while git runs), and
  workspace_archive (still unregistered, council MERGE 53). Their error reads
  "The <setup script|archive script|issue command> in kolux.yaml did not run: this repository's scripts are
  not trusted yet" (or "it changed since you trusted it"). The user's own scripts (Kolux's per-repository
  setting, the untracked .kolux/issue-command) never ask. When trust cannot be checked (not one of the
  user's projects, an unreadable record, a poisoned store lock) nothing runs.
- New commands (registered by the coordinator hunk below): script_trust_needed(path, kind, root?, local?,
  policy?) returns what to ask or null; script_trust_grant(path, kind, script, always, root?) records the
  approval for exactly the text shown (a script edited between the prompt and the run is refused again).
- Frontend (src/setup/TrustPrompt.tsx, trust.css): one prompt host, a module-level line of waiting prompts
  shown one at a time, built on the app's one confirmation dialog (VIEW-116 Ask): title, the script in a
  scrolling monospace box, "Always trust this repository's kolux.yaml", buttons Don't run (focused, Enter
  and Escape and a click outside all mean Don't run) and Run hooks. Worded for a changed script when one
  approved earlier changed. Another dialog opening over it counts as Don't run and the next prompt still
  shows. With no host mounted every ask answers Don't run. trustedSetup(path) asks before workspace_setup;
  issueCommand() (src/setup/IssueCommand.tsx) asks before workspace_issue_command.
