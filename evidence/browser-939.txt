after.md row 939 (HIGH privacy): with a saved proxy the in-app browser connected directly. lane/browser-proxy, Sonnet 5.5, 2026-10-27.

ROOT CAUSE
- wry-0.57.0 src/webview2/mod.rs:300-328 appends ` --proxy-server=<scheme>://host:port` only inside `pl_attrs.additional_browser_args.unwrap_or_else(...)`, i.e. only when the app passes no browser arguments.
- src-tauri/src/browser.rs browser_open always passed `.additional_browser_args(&recovery::browser_args_now())` (T-286-b, APP-017), so `.proxy_url()` was silently dropped on Windows. Setter order does not matter.

FIX
- src-tauri/src/browser_proxy.rs (browser::proxy): `tab_browser_args(base, proxy)` puts exactly one `--proxy-server=` into the tab's argument string (an existing one, or `--no-proxy-server`, is replaced); `proxy_flag` refuses credentials (CREDENTIALS_REFUSED), a path/query/fragment (SHAPE_REFUSED), and states the default port (http 80, socks5 1080). `Envs`/`admit`: each data folder's first argument string is kept (first open wins); a tab whose string differs is refused (CHANGED_REFUSED), never opened direct. The default folder is seeded with the main window's launch string.
- browser.rs browser_open: `proxy::tab_setup(launch, folder, saved)` returns the tab's args and the address for `.proxy_url()`. Windows: proxy rides in args after `admit`, `.proxy_url()` not called (wry drops it). macOS/Linux: args stay `browser_args_now()` and `.proxy_url(u)` gets the exact Url `proxy_of` returned, as before row 939. Credential/path refusals happen on every OS before anything loads. With a refusal the tab's profile page count is released.
- resources/recovery.rs: `launch_browser_args_for(current, safe, identifier)` reads the profile's settings.json (or .bak) httpProxy, unseals it and puts the same switch into the window's string. NEEDS lib.rs:226 to call it: evidence/browser-939-lib.rs.patch (FLAG; lib.rs is a hard-stop file). WITHOUT the patch the lane still fails closed: the window has no proxy switch, a default-profile tab with a saved proxy is refused ("restart Kolux" message), profile tabs get their own environment with the switch.

REFUSAL TEXTS (shown as the error of browser_open, i.e. the tab stays unopened)
- credentialed proxy (or a path/query): "The in-app browser can't use a proxy that needs a username and password. Nothing was loaded directly; set a proxy without credentials or clear the setting." / "The in-app browser takes a proxy written as http://host:port or socks5://host:port, with no path. Nothing was loaded directly; fix the setting or clear it."
- host with `=`, `;`, `,` (anything outside letters, digits, `.`, `-`, `_` or a bracketed IPv6): the same shape message (Chromium would read it as a per-scheme rule list and go direct).
- settings.json unreadable: "Kolux can't read its settings, so the in-app browser won't open pages in case a proxy is set. Nothing was loaded directly; restart Kolux or check settings.json."
- proxy differs from the one the data folder's engine started with (changed or cleared since launch or since the profile's first tab): "The proxy setting changed. Restart Kolux to apply it; nothing was loaded directly."
- unusable scheme: proxy_of's existing message. Tabs already open keep the proxy they opened with until Kolux restarts.
