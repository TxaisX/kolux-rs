What changed (src-tauri/src/scm_watch.rs)
- ask_git: after check-ignore, the folders it called ignored are listed once with
  `git ls-files -z -- <dir>/ ...`; a folder that still holds a tracked file is answered "not ignored",
  so a change to that tracked file starts a read again (before: it was cached as ignored and the
  status never moved). tracked_under() reads the ls-files output.
- matters: the rule-file check runs before counts(). Before, `.git/info/exclude` was dropped by
  counts() (only HEAD, index and refs pass inside .git), so an exclude edit never cleared the cache.
- New Spot::Info: a linked worktree also watches its repository's shared `info` folder (not
  recursive, only when it exists so a missing folder cannot break the watch); its `exclude` file
  forgets that worktree's answers and reads once; nothing else in info/ counts.
- The Ignores doc comment now names the tracked-file rule and both exclude files.
