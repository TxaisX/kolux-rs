T-607 · Browser tabs and sign-in popups refuse frames of Kolux's own address (L1-tauri.1, R07-browser.1;
BROW-015, BROW-040; live proof pending)
Safety lane, 2026-10-30, branch lane/safety.

WHAT THE USER GETS
- A web page open in a Kolux browser tab, or in a sign-in popup, can no longer embed a hidden copy
  of Kolux's own screen: a frame whose address is Kolux's own (any *.localhost host, where the app,
  its command bridge and its custom schemes answer on Windows; an app scheme such as tauri:, ipc: or
  asset:; the dev server a development build runs from) is cancelled as it starts. On Windows the
  engine gives every frame Tauri's command bridge, and Tauri grants a page at the app's own address
  every app command, so such a frame could have typed into the user's terminals.
- Ordinary third-party frames (videos, sign-in and payment frames, a user's own localhost server on
  any port in a release build) and frames a page makes of its own text (about:blank, about:srcdoc,
  data:, blob: of an allowed origin) still load. Any other scheme (file:, javascript:, edge:, a
  custom scheme) is refused in a frame, as browser::allowed already refuses it for a tab.

WHAT CHANGED (file:line at the commit)

- 591-609  frame_ok(uri, app), the pure rule: http(s) -> browser::allowed (refuses *.localhost and the
  dev origin); about: -> blank and srcdoc only; data: -> loads; blob: -> by its inner origin (an
  opaque "null" origin loads); anything else, or no address at all -> refused. Windows-only caller,
  so `cfg_attr(not(windows), allow(dead_code))` as browser_selfclose.rs does.

  a frame when frame_ok refuses it, and in a preview tab when the preview's own fence refuses it
  (preview::frame_may_load, after-list 285, as before).
- 80-83    imp::attach installs it for every tab (it was installed with the preview fence only, which
  lets every frame through for a tab that shows no preview); dev = browser::app_origin of the app.
- 456-463  popup_frames(w, dev): the same hook for a sign-in popup.
- 4-8, 26-27 module header: the frame rule is the one pure function kept in this glue file.
src-tauri/src/browser_popup.rs
- 156, 194-195  popup::open keeps a copy of the dev origin and installs popup_frames after the identity
  and permission hooks.
Not here (other lanes): the release lane adds frame-ancestors 'none' to the app's CSP; scoping

LIMITS
- data: frames load: their origin is opaque ("null"), which Tauri refuses as a command origin
  (tauri 2.12.1 ipc/protocol.rs parses the Origin header as an address and refuses "null"). If a
  live check shows otherwise, add data: to the refused schemes.
- The rule is checked at each frame's navigation start, as the preview fence already was; a frame
  that navigates later is checked again at that start.

LIVE PROOF PENDING (Windows, WebView2)

3. A dev build: a page framing http://localhost:1420/ stays empty.
