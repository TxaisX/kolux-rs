T-284 · SKILL-023 An interrupted skill delete is undone or completed on restart (lane reliability)

What it is: src-tauri/src/skill_delete.rs, the all-or-nothing delete that SKILL-022's Delete
skills (T-180) will call, plus a startup recovery call in lib.rs setup. Each item (skill folder,
link, install receipt) is renamed aside next to where it sits (".kolux-deleting-<pid>-<time>-<name>")
after a journal (skill-delete.json in the app's folder) records every move. A failed rename puts
back what moved and removes the journal. Only when all items are aside is the journal marked done
and the copies removed. At startup: not done -> every item goes back; done -> removal completed.
A rename refused because another program holds a file is tried 20 times, 100 ms apart.
is_set_aside() is the check the Skills list (T-243) uses to leave set-aside items out.

Acceptance 1, killed mid-delete -> skills back on restart:
- cargo test skill023_killed_after_setting_aside_the_skills_come_back_on_restart: the test re-runs
  its own binary as a child that sets alpha and beta aside and exits (code 9, no unwinding) before
  the delete completes; both are seen set aside, recover() brings both back with their contents,
  journal gone.
- Live restart of the dev app (port 1428, scratch CLAUDE_CONFIG_DIR/CODEX_HOME under
  G:/Temp/reliability-T-284): staged %APPDATA%/com.txaisxiong.kolux-rs.reliability/skill-delete.json
  {done:false, moves:[[skills/beta, skills/.kolux-deleting-1-2-beta]]} with only the set-aside
  folder on disk. After the app started: G:/Temp/reliability-T-284/skills lists "alpha beta",
  beta/SKILL.md reads "# beta", and skill-delete.json is gone.

Acceptance 2, briefly locked skill file -> retried and deleted:
- cargo test skill023_a_briefly_locked_skill_file_is_retried_and_deleted (Windows): SKILL.md held
  open with no sharing for 400 ms; a plain rename is refused; delete() retries and returns Deleted.
  With TRIES set to 1 the same test FAILS (checked, then restored to 20).

Other tests: delete removes skills and receipts and leaves no record; a missing item changes
nothing; a failed rename puts back what moved; a done delete left half removed is completed on
restart; set-aside names are not skills. cargo test --lib -- skill_delete: 7 passed, 1 ignored
(the child half, run only by the crash test).
