T-618 (status-hooks lane, 2026-10-30): a new tab never inherits a closed tab's saved status after a restart
==========================================================================================================
Audit F05-app-shell-launch.3 (src/status/useRestoredStatus.ts:30). Cards: STAT-030 ("sessions return showing their last
status"; "saved status replayed at startup waits until its pane has loaded").

THE PROBLEM
Saved statuses were matched by pane number only. Pane numbers are reused (App.tsx nextKey restarts at the highest saved
key + 1), the Rust save kept a row for every pane that ever reported (saved.rs note), and useRestoredStatus kept a row
for an absent number pending until any pane with that number appeared. So a brand-new tab could show a closed tab's
"waiting" (and sit in "Sessions that need you"), "working", or the "restart this terminal" row.

WHAT CHANGED
- src/status/restored.ts:10 SavedRow carries the row's sessionId (saved.rs Row already serialises it).
- src/status/restored.ts:29-36 restoration() takes `back`: the panes that came back from the saved layout, each with the
  session it was saved with. A row goes only to such a pane, and, when the row names a session, only if the pane carries
  that session. Every other row is never applied.
- src/status/useRestoredStatus.ts:12 and :23-31: the panes of the window's first render are the ones that came back from
  the saved layout (App.tsx:293 starts with layout?.panes and nothing else, "T-543-b: no pane until a workspace is
  opened"), kept once with their session ids; the read of the saved rows sends them as `keep` (none sent when no pane
  came back, so a slow start with no layout read drops nothing).
- src-tauri/src/agent_hooks/saved.rs:342-361 keep_panes(): the previous run's rows of panes not in `keep` leave the
  restored rows for good, and while no live event has rewritten the save from this run's rows, the save loses them too
  (the command holds the store, which note() also takes before writing, so the newer write always lands last).
- src-tauri/src/agent_hooks/saved.rs:363-378 restored() is the old body; the agent_status_saved command takes an optional
  `keep` (and the store) and calls keep_panes first. Same command name, so lib.rs needs no change.
- src-tauri/src/agent_hooks/tests.rs:279 and :336: the two older tests read saved::restored() instead of the command.

WHEN THE SAVED ROW IS PRUNED
At the first window start after the tab closed: the closed tab is not in the saved layout (TERM-106 writes the layout
from the live tabs), so its row is dropped before any tab can be given its number. Pruning at the moment of closing is
not needed for the restart case and was not done (it needs App.tsx's dropPanes or terminal.rs's TERM-106
terminal_forget_history, neither owned by this lane); see "still open".

STILL OPEN
- Live proof on Windows: open a Claude tab, let it ask a question, close it, open other tabs, quit, start again and open
  new tabs until one gets the closed tab's number: it shows no status and is not listed in "Sessions that need you".
- Optional, outside this lane: drop the row at the moment a tab closes (App.tsx dropPanes already calls
  terminal_forget_history for each closed key; a matching saved.rs forget would need a new command or a line in
  terminal.rs). Not needed for the restart case above; it would only matter for a key reused after a window reload in the
  same run by a tab that never reports, whose row has no session id.
