== 2. Cut 1 (acf379da): where the 315,352 bytes come from

Cause: src/editor/buffers.ts had one runtime import that a document store does not need —
  import { isolateHistory } from "@codemirror/commands";
isolateHistory groups a reload as one undo step of its own. @codemirror/commands imports
@codemirror/view and @codemirror/language, so all four packages landed in one 315,352-byte chunk that
the first frame pulled through editor/buffers.ts (FloatingLayer asks isDirty, the window asks keyOf and
baseName, terminal/paneActions asks keyOf). @codemirror/state added 49,171 bytes on top (the lane's
measurement: dropping only the commands import left a 49,171-byte chunk and 1,573,821 bytes first
load, still over the bar), which is why the store drops CodeMirror entirely.

What changed — the seam:
- editor/buffers.ts keeps the documents (open text per file, dirty state, save, line endings,
  carry-over, held text, opening) and its whole public API, and carries no CodeMirror import at all:
  its one @codemirror/state import is `import type`, so it erases.
- New editor/editors.ts is the CodeMirror side. It builds the values the store cannot make itself and
  installs them with useCodeMirror(): `mark` (the annotation that marks Kolux's own change) and `marked`
  (reading it), `isolate` (isolateHistory.of("full")), `ends` (the separator Compartment),
  `lines` (Text.of split as the view splits), and for T-603 `setEnds`, `endsOfState`, `lineEndsFor`,
  `fileText`. It re-exports ./buffers, so every caller imports one module and the values are installed
  before any view can be attached; a missing install throws by name instead of mis-grouping undo.
- EditorPane.tsx and DiffPane.tsx import from ./editors; eight test files (buffers, carryOver,
  diskChange, drafts, fileMoved, logFollow, staleSave, __cards__/EDIT-001-003) changed one import line
  from ./buffers to ./editors. mixedLineEnds.test.ts keeps its named imports from ./buffers — the T-603
  helpers the job asked to stay there — and adds `import "./editors"` so the CodeMirror side they call
  into is loaded, exactly as EditorPane does before it builds a view. No test was weakened or deleted.

== 3. T-603 across the seam (the part that broke the last attempt)

Kept in buffers.ts (plain text work, `import type` only):
  mixedEnds, docText, endsOf, mapEnds, soleLineEnd, withLineBreaks
Moved to editors.ts (values from @codemirror/state):
  the endsField (StateField.define, updating through mapEnds), the setEnds effect, the separator
  Compartment and lineEndOf (a mixed file splits on LF; a file with only CRLF keeps CRLF).
Reached through the installed interface:
  lineEndsFor(text) and fileText(state) are thin calls exported from buffers.ts (so the T-603 test
  imports them from ./buffers); setEnds and endsOfState are used inside the store.
Rules held:
  isDirty, save, carryOver and heldOf compare and write fileText(state), never sliceDoc();
  attach carries a twin's endings with endsOfState;
  replaceAll inserts cm().lines(end === "\r\n" ? text : docText(text), end) and dispatches
  setEnds(endsOf(text)); textOf() stays the drawn text (a mixed file's text has no CRs) and
  fileTextOf() stays what a save would write.
