WHAT CHANGED
(a) FS1 - a browser tab that is not on screen can no longer open tabs (link chord, Mod/middle click, _blank, window.open)
    or send any chord (focusAddressBar, back, forward, reload, find, zoom). It takes nothing from the shared 5-per-10s
    allowance, so a background page can no longer use it up and make the user's real clicks drop, and it can no longer
    pull the keyboard to the app by looping focusAddressBar. Gate: navigation() and new_window() in src-tauri/src/browser.rs.
(b) FS2 - the site-icon fetch has its own name lookup. For any host other than the page's own, addresses on this machine
    or the local network are dropped before connecting, so a public name pointing there (192-168-1-1.nip.io, localtest.me,
    a name rebound after the page loaded) is never asked. Both icon clients skip any proxy. The page's own host keeps an
    unfiltered client (the page is already there); a redirect off that host stops and is handed to the filtered client
    after the usual hop check.
(c) AFTER 2 one icon fetch in flight per tab (a page reloading with ?r=random gets one at a time).
    AFTER 3 browser_open takes `shown`; BrowserPane sends whether the body has a size, so a tab opened behind starts
    off screen instead of counting as shown until its first bounds call. (src/browser/BrowserPane.tsx, no App.tsx hunk.)
    AFTER 4 IPv4 addresses written as IPv6 (mapped and compatible, e.g. [::7f00:1]) and 0.0.0.0/8 count as local.
    AFTER 5 allowed() trims a trailing dot: http://tauri.localhost./ and http://localhost.:1420/ (dev origin) are refused.
    T-272-c notes: DNS rebinding paragraph on IconClients; find-in-page doc says the page's script can see the search text.
    Still open on T-272-c: per-family allowance, "popups blocked" in the opener's toolbar, the T-319 snippet site check.
