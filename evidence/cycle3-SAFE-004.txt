SAFE-004 box 3: a pane whose status never updates gets the Request changes feedback after about
3 seconds. Lane c3-p0-gaps, 2026-10-31.

WHAT WAS WRONG
startFeedback (planReview.ts) waited up to 3 seconds for the pane to leave plan-approval, then
returned "still-asking" and typed nothing. When the pane's status source stops reporting while it
still reads as asking, the wait never succeeded, so the feedback was never delivered at all: the sheet
closed with "The agent is still asking. Answer it in its terminal; your feedback was not typed." The
card's fallback ("if the state never changes the feedback goes anyway after about 3 seconds") was not
implemented.

WHAT CHANGED
planReview.ts: SendSteps gains reads(), a number that advances with every status reading the pane's
source reports (even one that repeats the same word). startFeedback samples it through the 3-second
wait and tells two cases apart:
  - still asking with fresh readings arriving -> "still-asking", nothing typed. The agent really is
    still asking, and an Enter would pick the menu's pre-picked default, Yes.
  - still asking with no new reading at all -> a stuck status. The message is typed and Enter is
    pressed: the feedback goes in anyway at the 3-second mark (30 x 100 ms), then the usual 300 ms
    check. A reading that turns up while the paste goes in makes the status live again and holds
    Enter back.
  - asking false at the first check -> straight away, no 3-second wait.
chat/send.ts: new heardAt(paneKey), the time of the pane's newest agent-status reading, fed by the
window's one listener over the same agent-status events that set the pane's state (hearStates). It
keeps advancing when the state word repeats, which is exactly what "the status never updates" means.
editor/reviewActions.ts: Request changes passes reads: () => heardAt(p.key) ?? 0.
