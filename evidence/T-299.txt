What changed
- src-tauri/src/projects.rs, PROJ-024: a name is retired only when it was SUGGESTED to the user and the
  workspace that used it is then deleted (forget_workspace, which the app and the CLI both call). The
  record is kept per scope (the workspace's parent folder: flat layout = one shared scope, nested layout =
  one scope per project), ignoring case and spaces, bounded (400 names per scope, 100 scopes), and a damaged
  record retires nothing. Typed-by-hand names are never retired. Handing a name out no longer remembers it
  (so a suggestion nobody uses costs nothing). The old global "creatureNamesUsed" list is no longer written.
- src-tauri/src/projects.rs, PROJ-019: clean_icon / project_icons / set_icon and two commands,
  project_icons_list and project_icon_set. Choices live under the store key "projectIcons" (by project id,
  not inside Project, so the other lanes' Project literals are untouched). Three kinds: emoji:<emoji>,
  icon:<built-in name>, image:<data URL, png/jpeg/gif/webp/svg, 64 KB at most as the whole value>. Empty
  resets to the automatic icon. forget_projects drops the icon entry of a forgotten project.
- src/projects/projectIcon.ts (+ test): the catalogue of built-in names, iconView (the automatic icon is the
  first letter of the name when nothing valid is saved; an unknown built-in name is kept and drawn as a
  folder), pictureProblem (type and size check before reading a file), value builders.
- src/projects/IconView.tsx: draws an icon (emoji, built-in glyph, picture or the letter).
- src/projects/IconPicker.tsx: the chooser for the project's settings form: built-in grid, emoji box,
  Picture... (file input) and Reset.
- Hunks for others: evidence/worktrees-T-299-lib.patch (registers project_icons_list and project_icon_set;
  stacks after worktrees-T-212-lib.patch) and evidence/worktrees-T-299-ProjectsPanel.patch (look lane's
