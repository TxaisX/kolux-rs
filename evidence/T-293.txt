T-293 · APP-030 An update whose Windows signature does not match is stopped, with no bypass · 2026-10-14
lane/release from 661693a (BEFORE of this wave dec2513). Text proof; the app was not launched (NO APP LAUNCHES).

What it does
- Before a downloaded update is kept for install, a signed copy of Kolux RS reads its own Windows
  (Authenticode) signature and the download's, with Windows PowerShell's signature check (no window;
  the file path goes in through an environment variable, never the command text).
- Same publisher, valid signature: allowed. Another publisher, no signature, or contents that do
  not match the signature (HashMismatch): refused for good. The download is dropped and the card
  gets a "security-stop: <reason>" error. (Amended by FIX-2, see evidence/FIX-2.txt: the refusal is
  remembered by the installer's SHA-256 and update signature in update.refusedInstallers, capped at
  20, never by its version; NotTrusted, UnknownError, an empty status and the other unclear answers
  now stop once instead of for good.)
- A download whose signature cannot be read at all, or reads unclear: stopped this time only
  ("security-stop-once:"), not remembered.
- update_check passes over a remembered version and answers with the quiet reason "refused"; a
  check the user asked for shows "The newest version was stopped earlier because it did not come
  from this copy's publisher, so it is not offered again."
- The card shows a "Kolux RS <version> was stopped for your safety" stop with the reason, no
  release notes, and only a close button (no install, retry or restart). The status bar shows
  "Update stopped". The rule only applies to a signed copy; every release today is unsigned
  (OD-03), so the path is dormant there, as the card says.
