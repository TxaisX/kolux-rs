WHAT WAS BUILT: src-tauri/src/orchestration/upgrade.rs (new, lane-owned)
- orchestration.version holds the layout number; a store with orchestration data and no number is 0;
  an empty store is written as layout 3 at once and nothing else is touched.
- run(store, now): backs up the raw text of every blob present as <key>.v<from> (mail, tasks,
  dispatches), applies each step from..3, then writes blobs + version in ONE transaction (set_all).
  * 0 -> 1: every message gets a thread: its own id, or the thread of the message it answers (chains
    followed); a reply to a message that is gone becomes its own thread; gates list added.
  * 1 -> 2: unstamped request receipts are stamped "now" (kept the full week, never dropped at once);
    pending ledger added.
  * 2 -> 3: a dispatch with no runtime gets runtime 0 (no live process, so its terminal reads as gone,
    ORCH-038); one with no status is "abandoned" with outcome "unknown" and a detail line (never a
    quiet success or a quiet running); missing created dated now; a task with no status is pending.
- Fail closed: a blob that is not JSON, or JSON of the wrong kind, stops the whole upgrade with an
  error naming the key; nothing is written, no version is stamped. A cleared blob ("null") counts as
  absent. A store from a NEWER Kolux (version > 3) is never downgraded or edited (report.skipped).
  Running the upgrade again is a no-op (same from/to, no new backups).
- at_start(store): the launch hook; logs the steps or the error, never panics. Its call sits in
  lib.rs setup right before cli::serve (shared file): evidence/orchestration-T-173-c-lib.patch.
- upgrade.rs carries #![allow(dead_code)] until that patch lands (same as sendonce.rs); drop both then.

DECISIONS (for Txais; defaults taken, recorded here and in the commit body)
- A pre-status dispatch becomes "abandoned"/outcome "unknown" rather than "failed": failed would count
  toward the task's breaker (ORCH-035) for a worker Kolux never actually saw fail.
- Backups are kept forever as <key>.v<n> rows (the store has no delete); they are small.
