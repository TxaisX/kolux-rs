T-624 Artifacts: import a workspace's artifacts folder automatically, and play media in the tab - evidence
Date: 2026-10-31 (round 2 after the PR #37 review, same day); round 3 2026-11-02 after the second review
Lane: lane/artifacts-auto (PR #37) · DT-C65, a DT-C58 follow-on
Base: 3af39cf3 (origin/main, merged into the branch at 6df949b9)

Why
The library only knew pages added by hand and files Claude Code's Write tool made (DT-C58).
A file written by another agent, such as the design artifact in this workspace's artifacts/
folder, stayed invisible until Add artifact and a trip through the file picker. The user asked
for it to land in the tab automatically, and for video, audio and other files to work there.

What changed (round 1)
- src-tauri/src/artifacts.rs: artifacts_scan(path, project) and workspace_files(). The scan reads
  every top-level file in <workspace>/artifacts, whatever its extension, imports each once,
  refreshes a changed file by its origin instead of adding a second entry, skips entries the
  library already holds, emits artifacts-changed, and leaves relative paths and network shares
  alone. Top-level only, so a test run's shots/ folder is not imported; a page's own relative
  assets are still copied with it. Dotfiles and .tmp/.part/.crdownload/.lock files are skipped,
  so a half-written download is not an artifact. The global Claude Write list stays narrow.
- Media: mp4, webm, mov, m4v, ogv, mkv, avi, mp3, wav, m4a, ogg, oga, flac, aac and opus are kept
  and typed as video or audio. The single-file cap rises from 25 MB to 100 MB. The artifact scheme
  now answers byte ranges (206 with Content-Range and Accept-Ranges) so a video or audio track can
  seek without loading the whole file.
- src-tauri/src/lib.rs: registers artifacts_scan.
- src/artifacts/ArtifactsPage.tsx: scans when the page opens and every 3 s while it is up, and
  refreshes the list when the scan imported something. Video plays in a native player, audio gets a
  player panel, and the Add dialog has a Video and audio filter.
- src/shell/window/Content.tsx: passes the active workspace and its project name.
- src/styles.css: the media and audio viewer surfaces.

What changed (round 2: the review's blocker, two majors and three minors, each failing-first)
- [blocker] A linked artifacts/ folder was followed out of the workspace. workspace_files() now
  refuses a link or junction where the folder should be (fs::symlink_metadata is_dir, the idiom
  files::list_templates uses; a Windows junction reads as a symlink there too) and keeps only a file
  whose canonical path sits under the workspace's canonical path, so a linked file, a folder swapped
  for a link between the check and the read, and a link to a share are all left out.
- [major] Remove from library was undone on the next launch (or as soon as the file changed).
  Library::remove notes the removed file's own (modified ms, length) in removed.json beside
  library.json (a sidecar, so library.json keeps its bare-array shape for an older build) for any
  entry whose origin is an absolute path to a file that is still there; the scan skips that exact
  file; Library::add forgets the note (a hand add, a Claude Write or a rewrite restores the entry);
  a note whose file is gone from disk is dropped at the next scan.
- [major] artifacts_scan was a sync command: file copies (up to 100 MB) and CDN fetches (20 s a
  script, up to 16) ran on the window's thread every 3 s. It is now `async fn` + spawn_blocking,
  the shape artifact_add has (not `command(async)`, which would make fetch_script's block_on panic
  inside the runtime); the path checks moved inside the worker too (a stat on a gone drive blocks);
  the SCANNED map is try_lock'ed, so a tick that finds a scan running returns {changed: 0} instead
  of queueing, and the page's own ticker drops a tick while the last invoke is still pending.
- [minor] A restored file with an older mtime (cp -p, robocopy /COPY:DAT) was counted as changed
  but never refreshed, and a page with assets was re-imported on every launch because the stored
  size counts the assets. Entry gains an optional `stamp` (the origin file's modified ms and
  length when stored; older entries have none and are refreshed once); the scan compares that
  exact stamp, and Origin.at is now_ms so Library::add's "older publish never replaces a newer"
  rule no longer blocks a restore.
- [minor] A file the scan could not keep was retried and logged every 3 s forever. The scan returns
  Scanned {changed, skipped}: a failed file goes into `seen` with its stamp (tried again only when
  it changes) and its reason is returned; the page toasts each reason once ("Not kept in Artifacts:
  clip.mkv is larger than 100 MB").
- [minor] The PDF frame had no sandbox. A sandboxed frame cannot run the PDF viewer (the HTML
  sandbox always disables plugins, no token re-enables them) and an unsandboxed one follows a link
  inside the PDF in-app, so the in-frame PDF view is dropped: view("pdf") is "app" and a PDF opens
  in its own app with the Open PDF button, as DT-C58 already had it. The .art-pdf styles go with it.
  The test now asserts every iframe on the page carries sandbox=.
- Bookkeeping: PLAN.md T-624 (artifacts lane), DECISIONS.md DT-C65, docs/guide/files-and-browser.md
  "The Artifacts tab" and a feature-index row.

What changed (round 3: the second review's three majors and three minors, each failing-first)
- [major] A CDN script address was matched as a string prefix, and the tailwind entry had no
  trailing slash, so https://cdn.tailwindcss.com.evil.example/x.js and
  https://cdn.tailwindcss.com@evil.example/x.js (user name; the host is evil.example) passed the
  gate and the 3 s scan fetched from any host a cloned page named. Every CDNS entry ends in '/'
  and cdn_url() parses the address: https only, no user name or password, no explicit port, the
  host equal to a listed one, the path under the listed path (jsdelivr only /npm/). cdn_scripts and
  fetch_script both use it. fetch_script's client no longer follows a redirect (Policy::none), and
  reads the body with chunk() and drops it the moment it passes 5 MB, instead of buffering a
  Content-Length-less reply for the whole 20 s timeout first.
- [major] Remove from library stat'ed the origin of every removed entry, on the window's thread,
  including an "unavailable" entry whose origin is a network share (which the library never reads,
  DT-R21; a stat there blocks for the share's timeout). Library::remove now notes a tombstone only
  for an entry whose state is "ok" and whose origin is not on a share; the scan's tombstone prune
  skips a share path too; artifact_remove is `async fn` + spawn_blocking like artifact_add.
- [major] Any page in the viewer frame could post {koluxOpen} itself on load, in a loop, and the
  page handed each to open_external: the system browser or mail client opened with no click.
  viewerLink() accepts a message only from our own frame and only while
  navigator.userActivation.isActive (a click inside the sandboxed frame activates its ancestors;
  a script's own message on load does not; a web view without userActivation opens nothing).
- [minor] The scan's link and containment checks were path-based and the copy re-opened the path,
  and a hard link (a second name for the same data, which no path check can see) passed every
  guard. open_source() opens each source once (O_NOFOLLOW on Unix; FILE_FLAG_OPEN_REPARSE_POINT on
  Windows, then the handle's FILE_ATTRIBUTE_REPARSE_POINT refuses it), takes length, modified and
  is_file from the handle (fstat), refuses a link count above one (nlink / nNumberOfLinks), and
  copies from the handle through take(cap + 1), so a file that grows during the copy is an error,
  never a cut-short copy. copy_assets does the same for each asset. Cargo.toml gains `libc`
  (unix only, already in the tree; Cargo.lock gains no crate).
- [minor] `Range: bytes=0-`, which a browser sends for every media load and after each seek, read
  the whole file (up to 100 MB) into memory on the web view's thread for each. One ranged answer
  now carries at most CHUNK (8 MB); Content-Range tells the browser the real length and it asks
  again from there. A request with no Range header still gets a 200 with the whole file: RFC 9110
  15.3.7 reserves 206 for a range request, and Chromium and WebKit always send `Range: bytes=0-`
  for <video>/<audio>, so the no-Range case is not the media path. (The reviewer's "answer 206 to a
  no-Range media request" part is therefore not taken.)
- [minor] The main page's policy had no media-src and img-src did not name the artifact origin, so
  the new <img>, <video> and <audio> viewers were blocked ('self' is http://tauri.localhost).
  tauri.conf.json and vite's DEV_CSP add exactly `http://kolux-artifact.localhost kolux-artifact:`
  to img-src and a media-src with only those two; default-src, connect-src and script-src are
  unchanged (scripts/csp.test.mjs pins that).
- Bookkeeping: DECISIONS.md DT-C65 (round 3), docs/guide/files-and-browser.md.
