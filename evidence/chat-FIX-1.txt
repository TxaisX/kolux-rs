WHAT CHANGED FOR THE USER
- The chat box sends only when Kolux can see the agent is not asking anything in its terminal. With no
  hook reading for the pane (hooks off, Codex trust not given, an agent with no hook route, or no event
  yet) the box holds the message and says "Kolux can't see this agent's prompts. Type in its terminal."
  A permission or question menu holds it with "The agent is asking something in its terminal. Answer there."
  The typed text stays in the box when a send is held.
- A send is bound to the pane it started on: before every write (the Enter above all) it reads that
  pane's own hook reading, from the window (live, by pane key) and from one window-wide hook listener
  that keeps every pane's newest state. Switching to another pane mid-send no longer lets the first
  pane's new menu take the Enter.
- One-line messages go in as a bracketed paste, so a menu that opened before its hook event arrived
  never reads "y" or "1" as a pick. One-line slash commands are still typed as text.
- With nothing picked on the Agents screen, a line above the box names the pane it types into.
- A message over the 8 MB paste limit is not sent; the box says so and keeps it.
- The pane's program session is asked at send time (a reconnect's new session is used); the chat view
  is keyed by pane, so a pane switch starts a fresh view.
