FS1 (a signed copy that could not read its own signature allowed everything) - fixed
- New build flag KOLUX_RS_SIGNED_BUILD=1 (SIGNED_BUILD). With it, a copy whose own signature read
  fails or is not Valid stops the update once ("could not confirm its own Windows signature").
  Without it the old behaviour stands (an unsigned copy stays dormant; a copy that does read Valid
  still compares). The signing release job must set the flag; scripts/release.mjs is the
  coordinator's (hunk below).
- Test: app030_a_copy_built_signed_that_cannot_read_its_own_signature_stops_once (new API, so its
  fail-first was a compile failure, not an assertion).

FS2 (refused list keyed on the version string, no way out) - fixed
- The list is now update.refusedInstallers: entries {sha256, signature, version}. A check skips an
  update whose feed signature (which covers the installer bytes) matches an entry; a download whose
  bytes' SHA-256 matches an entry is stopped without asking Windows. The version string is kept for
  reading only. A stale installer served as "0.9.0" no longer blocks the real 0.9.0.
- Capped at 20 (REFUSED_CAP), oldest dropped. Reset: update_mark with key "refusedInstallers" and an
  empty value clears it (and the old update.refusedVersions); any other value is refused, so the
  command cannot add entries. A forgotten installer that is still signed by someone else is stopped
  again when it downloads, so the reset is never a bypass. No button calls it yet (support action).
- The old version-keyed list is ignored (a list of strings parses as empty).
- Tests: app030_a_refused_installer_is_known_by_its_bytes_not_its_version,
