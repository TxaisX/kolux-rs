TERM-079 · Kolux shortcuts versus shell keys (src/terminal/shellKeys.ts, TerminalPane.tsx)
  change: routeKey() decides every keydown in a pane: a chord bound to a Kolux action (defaults or the
    user's keybindings file; global, terminal and tabs scopes) is Kolux's and the shell never sees it;
    anything else goes to the program. Carve-outs: Ctrl+C with nothing selected is the interrupt; on macOS
    Ctrl+letter chords are the shell's even when a Kolux chord names them, Cmd+Left/Right send line
    start/end (^A/^E), Cmd+Up/Down scroll to top/bottom; Alt/Option+Arrow moves by word on every platform
    (ESC b / ESC f on macOS and Linux; on Windows the Ctrl+Arrow key encoding, which PSReadLine's Windows
    mode, cmd and Git Bash all read — PSReadLine has no ESC b binding there); a composing (IME) key is never
    routed. Ctrl+R and Ctrl+Arrow are unbound in Kolux on Windows, so they reach the shell.
  vitest: src/terminal/shellKeys.test.ts 6 cases (Ctrl+R / Ctrl+Arrow shell and Ctrl+K/F/W/Tab Kolux;
    Ctrl+C interrupt vs copy; custom binding honoured; Alt+Arrow per platform; macOS Ctrl chords and Cmd
    arrows; IME).
