- src-tauri/src/floating_trust.rs (new, 5 unit tests t271_*; compiled only once the lib.rs patch is applied):
  · The trusted list lives in the store (key floating.trusted), not in the settings file settings sync writes; no
    command takes a list, so a list sent from the interface or through sync is never read.
  · floating_pick shows the system folder picker (tauri-plugin-dialog, as files::file_pick does) and trusts only
    the folder chosen there (canonical, once). floating_trusted lists them. floating_start(asked) returns the
    folder a floating terminal or agent starts in, or the refusal.
  · load(): blank entries dropped, reachable ones canonical (no \\?\ prefix), unreachable ones (a drive unplugged
    for now) kept as they are, none twice (Windows ignores case). The older single working-folder setting
    (settings key floatingCwd) is moved in once, behind the marker floating.legacyMoved; a blank old value becomes
    the home folder; the marker is set at first load even with no old setting, so an old value arriving later
    (sync) is never trusted. A stored list that cannot be read trusts nothing and is left as it is (never wiped).
  · Fails closed: an asked folder must be on the list AND reachable now; another folder, a folder inside a picked
    one, a missing folder, a file, ".." and an unplugged pick are all refused. Nothing asked = the most recent
    reachable pick; an empty list refuses ("Pick a folder for the floating workspace first.").
- src/floating/trusted.ts (new, 4 tests in trusted.test.ts): startFolderFor asks Rust; with nothing trusted yet it
  offers the picker once and uses its folder; a cancelled or failed picker and a refused asked folder open nothing;
  never sends a list.
