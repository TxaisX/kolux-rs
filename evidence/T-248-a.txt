# T-248-a evidence: the app menu (APP-009) and the tray model (APP-008), lane/chrome

Date: 2026-10-13. Dev app built from this tree with the coordinator's wiring hunks applied
(lib.rs `mod menu; mod tray;` + `menu::menu_sync, menu::menu_popup` in the handler list, and the
App.tsx `useMenuBar(...)` + `appMenu` hunk, both in the commit body and not committed), launched
with identifier com.txaisxiong.kolux-rs.chrome.smoke, vite 1443, CDP 9260, scratch homes under
G:/Temp/chrome-w1 and KOLUX_APP_DIR under it.

Design (decided here, for Txais to confirm): Kolux's window is frameless, so on Windows a native
menu bar attached to it is never painted (seen live: the HMENU held 5 items, nothing drew), and
its accelerators would catch keys such as Ctrl+C before a terminal sees them. On Windows and Linux
the menu therefore opens as a native popup from the Kolux mark in the title bar; the shortcuts
stay with the page (the hints only show them). macOS attaches it as the app menu bar.

name off) and the screen (Terminals). Ctrl+, Ctrl+B Ctrl+L Ctrl+Shift+R Ctrl+0 Ctrl+= Ctrl+- come
from the page's keymap (toAccelerator of the first chord), so a changed shortcut changes the hint.
