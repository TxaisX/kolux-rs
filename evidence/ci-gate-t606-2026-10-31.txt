CI GATE AND T606 - 2026-10-31
================================================================

WHY
  CI had 30 runs with zero passes. The release workflow refused a red commit; the hand-run
  release path did not, and v0.1.4 was published while CI on its commit had failed.

T606 ROOT CAUSE
  The stand-in agent script ended on:  dir /b /a | find /c /v ""
  On an empty folder find prints 0 but exits 1, so the writer read a successful run as a
  failed agent. The test only passed when the folder happened to be non-empty.

  Fix: the stand-in ends with "exit /b 0", like a real agent. The empty-folder assertion is
  unchanged.

  Proof: cargo test --lib t606_the_claude_writer
    test scm::writers::tests::t606_the_claude_writer_... ... ok
    1 passed; 0 failed

GATE
  release.mjs now calls the same decision rule as scripts/ci-gate.mjs (decide, POLL_MS):
    - before the build, so a red commit fails fast
    - again at the moment of gh release create
  Rehearsal publishes (KOLUX_RELEASE_PUBLISH_DIR) are exempt.
  The only bypass for the real feed is KOLUX_RELEASE_ALLOW_RED=1, which logs a warning.

  Proof: npx vitest run scripts/release.test.mjs scripts/ship.test.mjs
    31 passed
    + refuses a commit whose CI is red, before it builds or publishes anything
    + lets a recovery publish past a red commit only when KOLUX_RELEASE_ALLOW_RED=1 says so

  PR: https://github.com/TxaisX/kolux-rs/pull/39

RUNTIME LOG
  kolux.log only changed when something happened, so a running app and a stopped one looked
  the same. The interface watch now writes "alive: ..." every five minutes (ALIVE_EVERY).
