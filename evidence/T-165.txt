Design (what Txais gets)
  TERM-109 Host crash containment: not applicable by design. Kolux RS has no separate terminal host process: every pane is a PTY the app owns
    (Terminals::spawn / pty.rs spawn_first), and DT-C27 says "Quit stops every pane; agents come back through restore". There is nothing to respawn
    five times and nothing to mark degraded; a pane's own program dying is TERM-111 below. Ticked as N/A with the decision quoted.
  TERM-110 Plain words: pty.rs already says the folder/drive/root/no-shell failures in words ("The folder X no longer exists...", "The drive X is not
    connected...", "No shell would start. Kolux tried ..."). errors.ts adds the ones that reach the pane as raw OS text: process-slot exhaustion
    (fork: retry / resource temporarily unavailable), os error 2 (not on PATH), os error 5 (access denied), "is not running" (writing to an ended
    pane). A known error comes out without the issue link; an unknown one keeps its text, gets the footer "(folder)" and the FEEDBACK_REPO link.
    "Restart host" buttons do not exist (no host, DT-C27). A failed START keeps SESS-024: the pane is dropped and the toast says "A session did not
    start: <explained words>" (App.tsx's failedPane, not core's file), so the words flow through failed.current(why). A failed WRITE shows the flash
    "Typing could not reach the program (<explained>)".
  TERM-111 Overlay: a SHELL pane whose program ends with a non-zero code keeps its buffer and shows an in-pane alertdialog "The shell ended with exit
    code N" with exitAdvice(N) and two buttons: Close pane (onClose) and Restart (runs the original start line again in the same xterm; the buffer
    stays). Exit 0 / null (typing exit) calls onClose: closeTab() asks terminal_busy, a gone pty is not busy, so the pane is dropped without a
    question and its neighbours take the space; the tab goes with its last pane. An AGENT pane whose program ended keeps what it printed (the Finished
    state and the Inbox notice depend on it) and prints "Enter starts a shell here"; Enter then opens a plain shell in that pane (restart(true)).
    The process-limit failure is explained by errors.ts (see TERM-110). Escape on the overlay closes the pane.
  TERM-112 Hidden terminals: hidden panes stay mounted with their xterm buffer, so the screen is exact on return and bells/exits are still seen
    (the unread badge comes from the pane's bell handler). Memory is bounded two ways that already exist: at most six panes hold a GPU context at a
    time, hidden tabs counted (src/terminal/renderer.ts, TERM-103), and scrollback is sized to the machine's memory profile (ACCT-059). No parking or
    retention budget was built (ponytail: measure first; see "seen, not fixed").
  TERM-113 Fast startup: a pane mounted while not on screen (clientWidth 0, a background tab of the restored layout) waits stagger() (150 ms + 60 ms
    per pane already waiting) before terminal_spawn, so the shown tab's panes get the first spawns. The workspace is not shown before saved state has
    loaded: src/main.tsx awaits restoreLayout() and stillThere() before ReactDOM.createRoot(...).render(<App layout={layout} .../>).

Seen, not fixed
  - kolux-dev with KOLUX_APP_DIR=<core data folder> answers "Kolux is not running ... (os error 2)" while KOLUX_USER_DATA_PATH with the same value
    works; cli.rs data_dir_of() looks right, so something between the shell and the CLI drops or rewrites KOLUX_APP_DIR (CLI-007 lane to check).
  - Ctrl+W through CDP does not close tabs in a layout with several groups (60 presses, 10 panes stayed); the pane's own exit does.
  - TERM-112's "parked after a short delay" and the worktree retention budget are not built; memory is bounded by the six-context GPU pool and the
    scrollback cap. Measure a 40-tab session before building parking.
  - Hidden panes report 50 columns to their program (the brisk-puffin prompt wraps at 50 in a hidden pane's screen read); a resize on show fixes it,
    but programs that draw while hidden draw narrow.
  - TERM-110's SESS-024 toast path (App.tsx failedPane) is outside core's files; the words are produced here, the toast is theirs.
