T-239-b: BROW-025 Google sign-in works inside the pane (desktop Firefox identity on the Google and
YouTube sign-in hosts, no client hints there, native mode per profile).
lane/browser from 18c45db9 · 2026-10-20 · Opus 5.5

What was built
- src-tauri/src/browser_profiles.rs: the decisions, all pure and unit-tested.
  - SIGN_IN_HOSTS = accounts.google.com, accounts.youtube.com (exact hosts; any letter case; a
    trailing dot ignored; http or https only). Google app subdomains (mail.google.com,
    www.google.com, www.youtube.com), lookalikes (accounts.google.com.example.net,
    evil-accounts.google.com), other country domains and a sign-in address inside a query string
    keep the pane's own identity.
  - firefox_identity(): "Mozilla/5.0 (<platform>; rv:140.0) Gecko/20100101 Firefox/140.0" with the
    platform part for Windows, macOS or Linux.
  - firefox_at(url, ua_spoof): Firefox only on a sign-in host and only when the profile is not in
    native mode. spoofs(store, profile): a profile's mode (the default profile, and an unknown one,
    are in normal mode; --no-ua-spoof makes native mode; a copied profile keeps its mode).
  - CLIENT_HINTS: the sec-ch-ua* request headers dropped on the sign-in hosts; no_hints_script():
    the page script that hides navigator.userAgentData on the sign-in hosts only.
- src-tauri/src/browser_engine.rs (glue, Windows): identity(controller, spoof). The engine's own
  identity is read once from the first page. With normal mode, at every navigation start (each
  redirect hop starts one) the page's identity is set from firefox_at: Firefox on a sign-in host,
  the engine's own identity again on any other host; the navigation's own request gets the same
  User-Agent header and, on a sign-in host, loses its client hints. Every other request to the
  sign-in hosts (scripts, frames, fetches) loses its client hints through a request filter, and the
  page script hides navigator.userAgentData there. Native mode hooks nothing: the stock identity
  everywhere.
- src-tauri/src/browser.rs: with_profile also answers the tab's profile mode; browser_open hooks
  engine::identity next to engine::attach and hands the mode to a popup.
- src-tauri/src/browser_popup.rs: a popup follows its tab's profile mode: one opened straight onto a
  sign-in host starts as Firefox (builder user agent), and engine::popup_identity keeps every later
  hop right.
- A viewport preset is untouched: the preset is page-script emulation (size, touch, scale) kept per
  tab, and the identity switch changes only the engine's user agent, so a preset active before the
  sign-in is still in force afterwards.
- evidence/browser-T-239-b-cli.rs.patch (for the resolver): the help line says what native mode
  costs: "--no-ua-spoof is native mode: the pane keeps its own identity on Google sign-in too, where
  Google may then refuse it as an embedded browser". Compat: --no-ua-spoof on profiles create
  already sets native mode (browser_cli.rs, since T-241).
