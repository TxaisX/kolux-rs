== ORCH 057 ==
- Resync from a snapshot (terminal.rs): every session keeps its output count and newest 128 KiB of raw output (Snap,
  updated under the registry lock with each chunk); each output event carries the count after its chunk (seq). When a
  pane stops answering past the 2 s flow wait and the reader goes on without it, the flow marks it behind; its next
  acknowledgement (terminal_ack, no new command, so no lib.rs change) is answered once with a snapshot {seq, data}
  starting at a line break. The pane (TerminalPane + resync.ts) clears its screen, draws the snapshot and drops every
  queued event whose count the snapshot covers, still acknowledging their bytes so the reader's count stays true.
- Capability queries (queries.ts): DA1 (CSI c / CSI 0 c) on Windows gets the console's documented answer CSI ? 1 ; 0 c
  (Microsoft Learn, Console Virtual Terminal Sequences, "Query State": DA); elsewhere xterm's own answer goes out.
  XTVERSION (CSI > q) is answered DCS > | Kolux RS ST. DA2 keeps xterm's answer.
- Dark-or-light (TERM-098's CSI ? 996 n and the 2031 notifications) is answered from the palette background's
  brightness (WCAG 2 relative luminance; dark when white text contrasts more than black), the app's mode only when the
  background cannot be read.
- A hidden Grok pane (hidden prop and a program named grok) holds back the version answers only (XTVERSION, DA2); DA1,
  colour and dark-or-light answers still go out.
- Unverifiable end: the exit event carries outcome "exited" (exit code known) or "unverifiable" (the wait for the
  program failed, no code); the pane prints "[process ended, outcome unverifiable]" and a shell pane with such an end
  stays open instead of closing as a clean exit.

== ORCH 059 ==
- Closing (kill) takes the handle out of the session list, folders, marks, keys, history file, flow, screen bits and
  snapshot at once; list, sessions, every, by_key, dir_of, program_of, live and read all stop knowing it. The output log
  stays only for the exit waiter (it keeps an automation run's tail, then drops it); read already refuses a closed handle.
- Per incarnation: a session id about to be used (spawn; the test helper too) first clears anything an earlier
  session under the same handle left (end flag, log, screen bits, marks, keys, snapshot, flow), so a reopened handle
  is a new terminal. Ids also never repeat within a run, and events of a replaced service run are dropped (APP-052).
