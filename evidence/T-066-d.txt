What was built (src-tauri/src/terminal_session_id.rs, declared from terminal.rs as terminal::session_id)
- SOURCES: one row per id-only agent (15): copilot, cursor, gemini, devin, droid, mistral-vibe, qwen-code, hermes, grok,
  antigravity, kimi, pi, goose, amp, openclaw. Claude Code and Codex are not rows: their hooks supply the id.
- Source 1, built and wired: the agent's OWN RESUME HINT. hint_session(agent, text) finds the agent's own resume form
  (the one agents::resume_args builds, so the parser and the restore can never disagree) followed by an id-shaped token
  (8+ characters with a digit, agents::safe_session) in the pane's output; the last hint wins; prose after the word
  "resume" and words like "latest" give nothing. terminal.rs reads it from the pane's log when the program exits and puts
  it on the terminal-exit event as `session` (omitted when there is none, so an old window sees the payload it always saw).
- Source 2, parser built, not yet run: the agent's SESSIONS COMMAND run in the pane's folder. pick_listed(agent, output,
  folder, taken) returns the newest listed id for that folder that no other pane holds (never-twice). Two output shapes:
  Lines (a UUID-shaped token per line, Amp's T- prefix kept, newest-first or oldest-first per agent) and Json (array or object
  holding one; id / session_id / sessionId / uuid / thread_id keys; folder key skips another folder's row; newest by time stamp,
  else by row order).
- The vendor's "continue the last session here" form is recorded per agent (continue_form) and NOT used: a restore with no id
  still starts fresh (test t066d_every_id_only_agent_has_a_row_...), until the live proof checks it never opens a picker and
  never resumes one session in two panes.
