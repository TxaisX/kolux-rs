Rules as built:
- task_list (src-tauri/src/orchestration.rs): a task whose stored status is ready but whose breaker is open
  (3 failed dispatches in its Run since its last reset) lists with status "held", "failures": 3 and
  "held": "held (3 failures)". Its stored status stays ready. --ready and --status ready leave it out, so a
  coordinator choosing work never picks it; --status held lists only those. Every row carries its
  failure count.
- Reset: breaker_reset stamps the task's counted failed dispatches with the reset time ("breakerReset"),
  so they no longer count; the records stay (history kept). The task lists and dispatches as ready again;
  a later failure counts from one; a repeated reset changes nothing; an unknown task, or a task of another
  Run, is not_found. The window reaches it through the new command task_reset (one line in lib.rs).
  There is no Tasks view in src/** yet, so no window hunk; the CLI command is a cli-lane hunk (handoff).
- A success still does not reset the count (unchanged from T-279; the review offered "reset on a success
  or a reset action": the reset action was taken).
- Inventory (src-tauri/src/inventory.rs): for_socket / tabs_for_socket give the session tab inventory with
  each program line cut to the program name (no folder, no .exe/.cmd/.bat/.com/.ps1 extension, no
  arguments), for whatever serves it to agents over the runtime socket; the agent credit is worked out
  before the cut. Nothing serves it over the socket yet (T-262-b, cli lane, is its first caller).
  The app's own session_tabs keeps the full line.
