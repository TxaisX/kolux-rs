T-178 (EDIT-046 saves are all-or-nothing; big or binary files are handled safely), 2026-10-19
Lane editor, from ab6c9df2 (main d823b3f8 merged in first). No app launch (batched live proof below).

What changed (src-tauri/src/files.rs, src/editor/buffers.ts)
- Save: the text goes to a temporary file in the same folder (created new, never over another file),
  is flushed and synced to disk, and only then renamed over the target. Any failure at any step removes
  the temporary file and leaves the target exactly as it was. A copy left by an app that died mid-save
  (older than 10 minutes, named for the same file) is cleared away by the next save of that file; a
  recent copy and other files' copies are never touched. On Unix the old file's permissions carry over
  and the folder is synced after the swap.
- Read: the bound is 32 MB (the old limit was 5 MB); a bigger file is refused by its size with a plain
  message ("... is too large to open (40 MB; the editor opens up to 32 MB)") before any byte is read.
- Binary: the first 8 KB of every file is sampled before the rest is read. A known signature (zip, gzip,
  7z, pdf, png, gif, jpeg, exe, elf), a NUL byte, or mostly control characters means "... is a binary file,
  so it is not shown as text"; the editor shows that as the tab's "did not open" notice and does not retry
  (buffers.ts loadText gives up at once on binary, oversize and non-UTF-8 refusals). UTF-16 text is refused
  the same way (the editor reads UTF-8 only); tabs, form feeds, escapes and CRLF stay text.

Tests (cargo test files:: 26/26; the new ones are edit046_*)
- edit046_a_save_that_fails_part_way_leaves_the_original_whole_and_no_temporary: writer puts half the new text
  out then fails; the original is read back whole, the folder holds only the original (acceptance 3).
- edit046_a_swap_that_fails_leaves_the_target_and_no_temporary: a folder where the file should go; the swap fails,
  the folder's contents are kept, no temporary is left.
- edit046_saves_in_a_row_leave_one_file_and_no_temporary.
- edit046_a_copy_left_by_a_dead_save_is_cleared_by_the_next_save_but_a_fresh_one_is_not.
- edit046_a_20_mb_log_opens (acceptance 1, 20 MB+ of log lines read back whole).
- edit046_a_file_over_the_bound_is_refused_by_size_and_one_at_the_bound_opens (read_text_up_to with a small bound;
  a compile-time assertion keeps TEXT_MAX above 5 MB).
- edit046_an_archive_or_other_binary_is_never_shown_as_text (zip signature, NUL, control characters, UTF-16;
  text with tab/FF/ESC/CRLF and an empty file stay text) (acceptance 2).
- edit046_only_the_start_is_sampled_so_a_big_binary_is_turned_away_by_its_first_bytes (a 1 MB file with a NUL in
  the first 100 bytes is refused; a NUL after the sample is not looked for).
- failures_name_the_file (changed: the non-UTF-8 case is now a real Latin-1 byte, since a NUL means binary).
- vitest src/editor/buffers.test.ts "edit046: gives up at once on a binary, oversize or non-UTF-8 file instead of
  retrying" (one read attempt for each of the three refusals).
