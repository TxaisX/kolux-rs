PER-VENDOR RULES (each from the public doc cited in PROVENANCE.md, T-122)
- Copilot CLI (route /copilot/<event>): $COPILOT_HOME/hooks/kolux.json or ~/.copilot/hooks/kolux.json, a file of
  Kolux's own ({"version":1,"disableAllHooks":false,"hooks":{<event>:[{"type":"command","powershell":"& '<copilot.cmd>' <event>","timeoutSec":5}]}}),
  all 13 documented events registered. The camelCase payload carries no event name, so the event rides the route
  (the script's first argument, the Antigravity pattern); the PascalCase shape with hook_event_name is read too.
  sessionStart -> SessionStart; userPromptSubmitted -> UserPromptSubmit; preToolUse -> PreToolUse; postToolUse and
  postToolUseFailure -> PostToolUse; permissionRequest -> PermissionRequest; agentStop and sessionEnd -> Stop;
  errorOccurred -> PostToolUse when recoverable, Stop otherwise (COMPAT 3.5: the turn ends only on an error it
  cannot recover from); notification with notification_type permission_prompt -> the ask-the-user shape (waiting);
  subagentStart, subagentStop, preCompact change nothing. Tool fields: tool_name|toolName, tool_input|toolArgs|toolInput.
  Only the powershell slot is written (Windows build); the bash slot is not.
  Off deletes kolux.json and the hooks folder when it is then empty. inspect: not installed / partial / disabled
  (disableAllHooks true) / installed / error (the file is not JSON).
- Grok (route /grok): $GROK_HOME/hooks/kolux-status.json or ~/.grok/hooks/kolux-status.json, a file of Kolux's own
  with Claude-style groups for 9 events and no matcher (Grok's matcher is a regex, so none is written); timeout
  5 s as Grok's default. hook_event_name|hookEventName: UserPromptSubmit; Stop, StopFailure and SessionEnd ->
  Stop; PreToolUse; PostToolUse and PostToolUseFailure -> PostToolUse; Notification and SessionStart change
  nothing (a routine notice never notifies; which notices mean needs-you or done waits on the payload doc).
  Install = install_hooks (the T-121 helper), off = remove_hooks: a file Kolux created goes, a user's own
  entries stay. Removal at quit, the wording rule and "emptied by hand stays empty" are T-122-b.
- Devin (route /devin/<event>): %APPDATA%\devin\config.json read as <home>\AppData\Roaming\devin\config.json
  (never APPDATA itself, so a scratch HOME is enough; .config/devin/config.json elsewhere). The file may carry
  // and /* */ comments (strip_comments is string-aware, so https://a/b inside a value survives). Kolux's groups
  go in one block between the marker lines `// >>> Kolux RS hooks (Devin) >>>` and `// <<< ... <<<` inserted
  right after the first `{`, pretty-printed two spaces in, each event's command carrying its own name
  ("<devin.cmd>" <Event>) because the script's route names the event; PreToolUse, PostToolUse and
  PermissionRequest get the match-everything matcher. The user's text after the block is kept byte for byte
  and the whole file must still parse after the insert (else nothing is written). A file with hooks of its own is
  refused with a message (merging into the user's groups is past the ponytail ceiling; T-122-b if wanted), as is a
  file that is not JSON. Off restores the kept copy of the original bytes, or deletes the file Kolux created.
  Events: UserPromptSubmit; Stop (interrupted|is_interrupt|user_interrupted true -> kolux_interrupted);
  PostCompaction -> PostToolUse (still working); SessionEnd -> Stop; PreToolUse; PostToolUse; PermissionRequest ->
  the ask-the-user shape (waiting); SessionStart changes nothing. Devin's doc does not say whether its settings
  share the Claude settings key, so the overlap warning is unticked (T-122-b).
- Pi (route /pi): ~/.pi/agent/extensions/kolux-status.js, a file of Kolux's own: `export default function (pi)` that
  registers pi.on for session_start, before_agent_start (prompt), tool_execution_start / tool_execution_end
  (toolName), agent_settled and session_shutdown, and POSTs {event, prompt, tool_name, session_id} to
  http://127.0.0.1:<port>/pi with the X-Kolux-Token and X-Kolux-Pane headers (fetch, fire-and-forget). agent_end is
  not registered: Pi's doc says it is not the final-idle signal; agent_settled is. Dialog/title forwarding and
  approval prompts: no public API shown -> T-122-b. Off deletes the file; inspect: installed / not installed.
- All four normalize into the Vendor shape and status::Agent::Vendor (status.rs untouched); PreToolUse with the
  ask tool name -> waiting, PermissionRequest -> permission, PostToolUse -> working, Stop -> idle.
