WHAT CHANGED
(1) FIX-BEFORE 1 - DNS rebinding through the page's own name is closed. The unfiltered "near" icon client now serves only a
    page that is itself open on this machine or the local network (icon_near = local_host(page) && same host). A public
    page's icon, on its own name and any port, goes through the public-only lookup, so a name rebound to 127.0.0.1 or
    192.168.x.x after the page loaded is never asked. Cost: pages served under public names that point at this machine
    (localtest.me, nip.io) lose their site icon; Txais's FIX-2 localtest.me question is moot. The IconClients doc comment
    that said "the page's own script can already reach that host" is replaced.
(2) FIX-SOON 1 - a page's script can no longer pull the keyboard. The back end no longer focuses the app's window when a
    focusAddressBar chord arrives. New src/browser/chord.ts decides per chord: pressed in the page (the app's window does
    not hold the keyboard, document.hasFocus() false) = focus that split and run, and focusAddressBar first asks
    browser_go("focusApp") to give the app's window the keyboard; sent by the page's script while the app holds the
    keyboard = no split change, focusAddressBar and find do nothing, zoom/back/forward/reload still run on that page.
    BrowserPane gives the keyboard back to the opener after a tab opened behind only for a real click in the page.
    The App.tsx listener change is a coordinator hunk: evidence/browser-FIX-3-App.patch. Until it is applied, App.tsx
    still runs every page chord as before, but a real focusAddressBar from inside a page no longer moves the keyboard
    to the app (the Rust set_focus is gone), so the bar gets the cursor only once the patch lands.
(3) AFTER 1 - local_ip adds whole ranges: 198.18.0.0/15, 192.0.0.0/24, 240.0.0.0/4 (broadcast inside), NAT64
    64:ff9b::/96 and 64:ff9b:1::/48, 6to4 2002::/16, site-local fec0::/10.
    AFTER 2 - one overall limit per icon fetch (ICON_TIME 8 s): each request's own reqwest timeout runs until its body is
    read, and the far request after a hand-off gets only what is left. The redirect cap is per client, so a hand-off can
    take up to 2 x 5 hops, all inside the 8 s (documented on fetch_icon_within). The Icons comment now says a request while
    a fetch runs is dropped and the tab's next finished load asks again (it said "waits ... within 8 s").
    Review "Tests": the hand-off is a pure hand_off(from, location, app) with its own test.
    AFTER 3 (live proof of `shown` on open) stays in LIVE PROOF PENDING.
    AFTER 4 - the stale FIX-2 privacy patch is not applied; evidence/browser-FIX-3-privacy.patch holds only the privacy.ts
    change, with the Ruling 2 wording, now true with (1) in.
