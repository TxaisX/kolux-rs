Rows 955 / 959 (second windows refused with WebView2 0x8007139F) and 954 (window.close() kills a tab)
lane/browser-proxy, 2026-10-27. Code facts below are read from this repo and from wry 0.57.0 / tauri 2.12.1 in the cargo registry.

ROOT CAUSE (955, 959)
- WebView2 rule: every environment on one user-data folder is created with identical options; a mismatch fails creation
  with 0x8007139F (ERROR_INVALID_STATE).
- The main window's string is built in recovery.rs launch_string -> browser_args: wry's default list, plus
  UNTHROTTLED (3 switches, APP-017 / T-286-b), plus FedCM off (BROW-026), plus the renderer heap ceiling (T-324-b),
  plus safe graphics (--disable-gpu) when on, plus --proxy-server when a proxy is saved (row 939). lib.rs:228 sets it on the
  window config; recovery::browser_args_now() (recovery.rs ~748) returns it for later webviews.
- A webview built with NO additional_browser_args gets wry's default list only (wry webview2/mod.rs:300-331).
- browser_pdf.rs (AppHost::open, was :161) built `note-pdf-N` with no args, and the Tower pop-out was made from the page
  (src/tower/ownWindow.ts `new WebviewWindow(label, opts)`, no additionalBrowserArgs). Neither sets a data_directory, so both
  share the default folder with the main window (and the default-profile tabs) -> mismatch -> refused.
- NO-PROXY BASELINE: it fails too. The window string ALWAYS differs from wry's default (UNTHROTTLED + FedCM are
  unconditional), so both windows have been broken since T-286-b, with no proxy saved and no safe graphics. Row 939 (proxy) and
  safe graphics (--disable-gpu) change the main string further but are not needed to reproduce. Test:
  recovery::tests::row955_the_window_string_never_equals_what_an_argless_window_passes (four settings: neither, proxy,
  safe graphics, both) - passed before and after the fix because it pins the cause, not the fix.
- Which settings broke which window BEFORE the fix:
      setting                   PDF export    Tower pop-out
      neither                   broken        broken
      proxy saved               broken        broken
      safe graphics             broken        broken
      both                      broken        broken
  (The prover saw it with a proxy; the code shows the other three fail the same way. Not run live: the prover owns the app.)
- Browser popups (browser_popup.rs:156) work: `.window_features(features)` calls with_environment(opener environment)
  (tauri webview_window.rs:1481-1503, tauri-runtime-wry lib.rs:4845), so a popup shares its opener's engine and needs no args.

THE FIX
- One source: recovery::browser_args_now(). browser_pdf.rs passes `.additional_browser_args(&browser_args_now())`.
- Tower: built from Rust (new src-tauri/src/browser_tower.rs, declared in browser.rs; command `tower_window_open(place)`),
  with the same call. src/tower/ownWindow.ts `tauriWindows.create` now invokes it (createViaRust); label "tower", focus-if-open,
  size/position/maximised/centre and the created/error result are unchanged. Only if the build lacks the command ("... not
  found") does it fall back to the page making the window (today's behaviour), so the unpatched lane is no worse than before.
- lib.rs registration is a FLAG patch: evidence/browser-955-lib.rs.patch (one line in generate_handler!, after
  browser::pdf::browser_pick_pdf_path). Without it the Tower pop-out behaves as today (still refused) and the PDF is fixed.
- Ratchet: recovery::tests::row955_every_top_level_webview_gets_its_browser_args_from_the_one_source scans src-tauri/src; every
  file that builds a WebviewWindowBuilder::new / WebviewBuilder::new must use browser_args_now() (popup and tools.rs exempt).
  Red before the fix ("browser_pdf.rs builds a webview without the one browser_args_now string"), green after.

EVERY OTHER WINDOW / WEBVIEW CREATION
- browser.rs:1163 (WebviewBuilder::new, add_child at :1347): default-profile tabs pass browser_args_now() via proxy::tab_setup
  (:1167-1178); other profiles use their own data_directory (with_profile) and their own string - own folder, safe.
- browser_popup.rs:156: reuses the opener's environment (window_features) - safe.
- tools.rs:381 (WebviewWindowBuilder::from_config): the main window; its config carries launch_browser_args_for (lib.rs:228).
- No `new Webview(` / other `new WebviewWindow` in src/ besides the Tower's legacy fallback in ownWindow.ts.

954 (BROW-001 b2)
- wry registers add_WindowCloseRequested for every webview and answers with DestroyWindow(hwnd) (wry-0.57.0
  src/webview2/mod.rs:683-685). That handler cannot be removed through tauri, so a page's window.close() destroyed the tab's
  container and left the dead page under the "stopped responding" overlay.
- Fix: browser.rs NO_CLOSE_SCRIPT, installed on every tab with .initialization_script (main frame, before page scripts), makes
  window.close a non-writable no-op, so the engine never raises the close request. Popups do not get it (a sign-in popup closes
  itself when done). Test: browser::tests::row954_a_tab_page_cannot_close_its_own_tab (red = compile error, NO_CLOSE_SCRIPT
  missing; green after). Behaviour of the script itself, run in node vm (G:/Temp/browser-955/vm.mjs, vm.log):
      before script, window.close() destroys: true
      after script, destroyed = 0 (want 0)
      page script calling window.close(): destroyed = 0
      page cannot swap it in sloppy mode; destroyed = 0 swapped = false
- Limit: a page that deletes/redefines close before we run cannot exist (we run first); a frame's own close() is a no-op already.

LIVE PROOF PENDING (prover lane; apply evidence/browser-955-lib.rs.patch first; loopback only, scratch profile)
Do the first two steps three times: (a) no proxy and normal graphics, (b) a proxy saved in Settings, then relaunch, (c) safe
graphics on (the safe-graphics flag file), then relaunch. Expect no 0x8007139F in any.
 1. Open the Tower pop-out (Tower screen -> Own window). Expect a second window "Kolux Tower" (on the second screen maximised,
    or centred 1200x800 with one screen); clicking Own window again brings it forward, no second window; closing the main window
    closes it. Before the patch is applied the click still shows the no-window notice (today's behaviour).
 2. Export a note to PDF (note menu -> Export as PDF, pick a path). Expect the file written, starting with %PDF, no error text.
 3. Open a browser tab on a loopback page whose script calls window.close() (e.g. a page with a button: onclick="window.close()";
    also one that calls it on load). Expect the tab stays, the page stays responsive, no "stopped responding" overlay, and
    switching to other tabs and back still works.
 4. A sign-in-style popup (window.open then close() inside the popup) still closes itself (popups are exempt).
