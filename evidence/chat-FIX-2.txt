WHAT CHANGED FOR THE USER
- After an agent starts a tool, the chat box waits about a second before pressing Enter (and before
  typing anything), so a permission menu that opens for that tool is heard first and the send stops
  instead of approving it. While it waits the box says "Waiting a moment: the agent is starting a tool."
  A tool that already finished (its PostToolUse arrived) holds nothing.
- A held send now always says why in the box (asking, can't see the prompts, terminal not running, too
  long). A send that stopped midway says "The send stopped before its Enter." plus the reason, and its
  bubble is marked failed.
- Approve or Deny on a card clears the chat's own reading of the old menu (App hunk calls answered()),
  so the box no longer stays held on a menu that was already answered.
- A hook reading from a pane's earlier terminal (the agent was started again or reconnected and its new
  program has not reported yet) no longer counts as clear: the box says "Kolux can't see this agent's
  prompts." The window already drops a pane's reading when its program ends (main 5f3b287 App.tsx onRunning).
- With the App patch applied: Send notes (Source Control line notes and review notes), a kit's role
  prompt, and Request changes' feedback go through the same check as the chat box. Notes sent to an
  agent showing a menu are not typed; the sheet says "The notes were not sent: <reason>" and keeps them.
  A kit role prompt waits and is tried again on the next tick. Request changes' feedback now also has
  escape codes stripped (AFTER 2).
- The chat's 8 MB send limit counts UTF-8 bytes, not characters (AFTER 1).
