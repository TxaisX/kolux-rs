HOW THE PALETTE RUNS A COMMAND (the same handler its shortcut runs)
- src/keys/runCommand.ts: once the palette has closed and put the focus back, a stand-in keydown goes to the element that has
  the keyboard; src/keys/keymap.ts matchEvent (:302-317) answers that one event with the command where its scope is live, so
  the window's key switch, a pane's, the editor's or the explorer's handler runs exactly as for the chord, unbound commands
  included; a real key press is never taken for it. tapHit.ts maps old ids too (matchOf).
- src/keys/terminalPolicy.ts:24-27: with "Terminal first", a command picked in the palette is never left to the terminal program.
- src/keys/commands.ts commandRows: one row per command in a "Commands" section with its keys as the hint; Select Tab and Select
  Workspace get a row per digit (Alt+1 .. Alt+9); TERM-041's new-tab commands one per installed agent.
- App patch: paletteItems gets ...commandRows(keymap, installedIds); the key switch's default asks windowCommand first;
  renameRequest state passed to ProjectsPanel.
