What changed for the user
- `kolux-dev orchestration worker-start --retry-of <dispatch>` re-arms a task that a failed start
  left marked as dispatched: once that dispatch's terminal is gone (or it was stamped by an earlier
  run of the app), the task can be started again and the old dispatch is marked abandoned with
  retriedBy pointing at the new one. It refuses, with a reason and the next command, when the old
  terminal is still live (stop it with worker-stop first), when the dispatch worked on another task,
  when the dispatch is unknown, when a newer worker already took the task, or when the task is done.
- A worker-start row now carries wall-clock time (created = epoch ms) and the runtime that stamped
  it, so a later run of the app can tell a dead start from a live one.
- An archive saved from a terminal that outgrew its kept output opens with one line saying how many
  lines were dropped and which line it starts at.
- After lane/orchestration lands: worker-release saves its pending mark before it reads or closes
  the terminal, a failed read closes nothing (release_unknown, with the retry command), and
  worker-show is a read so it may run alongside another Run.
