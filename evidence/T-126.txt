DECISIONS FOR TXAIS (recorded in the commit body too)
  1. A second fully idle Stop (Antigravity) or a second agent.end (Amp) for a transcript that already ended is discarded as well; the card lists only
     tool and end-of-invocation events, but a repeated end would re-mark done (a second done-today entry) or, for a late `cancelled` end, flip a
     finished pane to interrupted. Discarding keeps "the finished pane stays done" true. A fresh PreInvocation / agent.start lifts it.
  2. The memory is one process-wide list keyed by (vendor, transcript id), bounded at 256 entries, not per pane: Antigravity conversation ids and
     Amp thread ids are unique per transcript, so one pane's ended thread never silences another pane's, and the listener's answer path (hooks.rs,
     off limits this wave) did not have to learn the pane key.
