# T-278 evidence: fast output never freezes a pane (ACCT-054) and scrollback caps scale with the machine (ACCT-059) - 2026-10-13, lane/core on 3060ccb
Handed over from the reliability lane (lives in terminal.rs / TerminalPane.tsx). No old Kolux source read, nothing copied.

Design
- ACCT-054: each session has a Flow (terminal.rs): unacknowledged bytes, a condvar, a pause count. The PTY reader thread adds
  every chunk it emitted; at 512 KiB unacknowledged it stops reading the PTY (so the program blocks on its own write, ConPTY's
  buffer being full) until the pane has acknowledged down to 128 KiB, or 2 s have passed (a pane that never answers is taken as
  caught up, so no program is ever stuck for good). The pane acknowledges what xterm has drawn, in running totals: the write
  callback counts bytes and src/terminal/flow.ts sends one terminal_ack per 32 KiB or per 50 ms. Kill, quit and exit release a
  paused reader at once. The pause count shows in the pane diagnostics (TERM-116) as "output paused".
- ACCT-059: terminal.rs profile_for(total physical memory) is pure: < 8 GiB "small" 2000 lines, < 16 GiB "medium" 5000,
  else "large" 10000 (unknown: medium). terminal_memory_profile answers {profile, totalMb, scrollback}; the pane asks once per
  app start (cached promise in flow.ts) and sets term.options.scrollback from it. Same machine, same answer, every start.

## ACCT-059 live
terminal_memory_profile on this machine (32,592 MB): {"profile":"large","totalMb":32592,"scrollback":10000}, the same on every
call; the profile is a pure function of the machine's physical memory (unit test above), so a restart picks the same caps.
A low-memory machine gets "small" 2000 lines, a mid one "medium" 5000: asserted in the unit test (no such machine here).

## Seen, not fixed
- resources.rs already calls GlobalMemoryStatusEx in a private imp::memory(); terminal.rs has its own six-line copy because
  resources.rs is not in this lane's files. One `pub` would let terminal.rs reuse it.
- ConPTY itself caps a flood at about 0.5 MB/s in a pane this size; the flow control above it is only reached when the
  pane is slower than ConPTY (a busy page, a stalled webview).
