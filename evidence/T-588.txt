T-588 · The release job gives its secrets to as little code as possible (X-proc.5; APP-059, APP-060)
lane/release-ci, 2026-10-30, Linux cloud sandbox (node 22.22.0, pnpm 10.28.0, vitest 4.1.11, @tauri-apps/cli 2.12.1)

WHAT WAS WRONG
release.yml used mutable action tags (pnpm/action-setup@v4, dtolnay/rust-toolchain@stable, actions/*@v4)
and wrote the updater private key to disk before the build. release.mjs then put the key, its password and
the write-scoped GH_TOKEN into the environment of pnpm install, the CLI's cargo build and tauri build, so
every dependency's install and build script could read them (key + token = a signed fake update).

PROBES THAT SHAPED THE DESIGN (this sandbox)
- tauri-cli 2.12.1 strings: "A public key has been found, but no private key. Make sure to set
  `TAURI_SIGNING_PRIVATE_KEY`..." (so tauri build cannot ask for updater artifacts without the key) and
  "Signing without an app version. Pass --app-version ... `requireSignedVersion` will reject this signature."
- tauri-plugin-updater 2.13.3 updater.rs verify_signature / verify_signed_version: minisign verify, then
  "version:" from the trusted comment must equal the announced version.
- node:crypto check of a real `tauri signer sign` output: alg ED, key id match, data and global
  signatures true; one appended byte -> data signature false.

REVIEW ROUND 1 FIX: an already-released main no longer fails the release run
Problem (reviewer): with two steps, APP-059's skip ("main was already released; nothing to do") made
--build-only exit 0 with no build, then --finish threw "no build to finish" (exit 1). --finish also
signed the newest v* folder in <checkout>-out, which on a local machine can be an already-published one.
Fix (the reviewer's first option, a record of what was built):
- scripts/release.mjs:218 --build-only removes <checkout>-out/pending before it starts (so a skip or a
  failed build leaves none); :287 writes it ("v<version>") after the smoke test passes.
- scripts/release.mjs:294-301 pendingFile/pendingBuild replace newestBuild; finish() takes the folder
  explicitly (no default).
- scripts/release.mjs:344-353 run(o, env, exec): --finish with nothing pending says "nothing was built,
  nothing to sign" and exits 0; otherwise signs exactly the recorded folder, then removes the record
  (a second --finish does nothing). run takes the injected runner like buildOnce (test seam only).
- release.yml unchanged: both steps still run; the skip now ends both with exit 0.
Tests (scripts/release.test.mjs):
- new "in CI's two steps, an already-released main builds nothing, and --finish then signs and publishes
  nothing": an old published v0.1.3 folder sits in <checkout>-out; run --build-only then run --finish;
  no throw, the only call is gh release view (no create, no upload, no signer).
- the existing two-step test now goes through run({finish:true}), puts a newer-named v0.1.9 folder beside
  the build and checks that v0.1.8 (the recorded one) is the release created, and that a second --finish
  publishes nothing.
