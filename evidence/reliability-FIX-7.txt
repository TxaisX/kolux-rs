    Tests (both new, in scm::tests):
      fix7_the_real_runner_runs_the_program_with_its_arguments_and_waits  runs cmd /C "echo ran & exit 7" (sh -c on Unix) through the
        runner: exit code 7 and the whole output "ran" are in hand when it returns (so it waited), then run_program on the same
        program and on a program that does not exist: no panic.
      fix7_kill_leftover_uses_the_shared_runner  reads this file and checks the body of kill_leftover contains
        kill_leftover_with(pid, &run_program); (Windows cannot compile the Unix body, so the wiring is pinned by reading it).
(3) Item 6 (review AFTER 2): fix4_a_timeout_ends_the_tree_through_the_job_and_uses_the_tree_kill_only_without_one.
    - late.cmd now writes started.txt first.
    - The no-job half starts gh with a two second delay (ping -n 3) before its second program, as a loaded PC would, so the 1 s
      limit runs out before that program exists. The tree-kill closure waits (up to 30 s) for started.txt, THEN asks kill_tree.
      The 1 s limit is a product constant and cannot be moved from a test, so the wait sits where the walk by parent pid needs it:
      the walk only finds a program that exists.
    - A second race showed up while proving it (below): a tree kill ends the leaf (the ping wait, exit code 1) a moment before the
      batch above it, and the batch read that as the wait being over and wrote late.txt. late.cmd now writes the mark with
      "ping ... >nul && echo late>late.txt", so only a wait that ran to the end leaves a mark.
