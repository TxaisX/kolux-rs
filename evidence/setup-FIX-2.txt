What changed
- Item 3 (FIX-SOON 1): words_before no longer cuts the command at a ; & | or ( that sits inside a quote that is
  already closed (new segment_start pairs quotes as they come; a separator inside the quote that wraps the command,
  as in bash -c "cd x; mysql ..", still counts). curl "..?a=1&b=2" -u admin:hunter2 and
  mysql -u root -e "use shop; select 1" -pS3cret are masked again. A bare value no longer swallows a following ;|&.
- Item 4 (FIX-SOON 2): in header context (-H / --header in a curl-like command, or Authorization on the line) any
  secret-sounding name is a header (Token, X_API_KEY, Secret). A secret-sounding "name: value" that begins a line or
  a quoted string is hidden when its value is one word (echo "password: hunter2", a YAML line password: x); prose with
  spaces ("token: rotate the keys", "note: remember the password") stays.
- Item 5 (AFTER 1): in JSON values a $ is never a variable reference (the body is text for a server), and an escaped
  quote inside a value does not end it (json_end). Outside JSON a $NAME reference still stays.
- Item 6a (AFTER 2): the program is the command word (command_index skips sudo/env/timeout/bash -c/cmd /c and
  NAME=value), plus words after a launcher (ssh host mysql, docker exec db mysql, kubectl exec pod -- mysql). A path
  or argument that only contains mysql, or a -h word on the line, no longer counts: find /var/lib/mysql -perm 644,
  ls -h; echo "Basic HttpClient" and grep curl -u a:b notes.txt stay as typed.
- Item 6b (AFTER 3): SafetyPage guarded() no longer sets the re-read to null at the start of a save, so the page keeps
  the last re-read on screen until the next one lands (useSettings keeps what a refused save wrote, so dropping it
  flashed the wrong switch). New render test of the default export with a rejecting save.
