What the user can now do: a background automation run that was still going when Kolux quit is
found again on the next start. If the terminal service still holds its terminal, the run is
followed through it again at once (no two-minute settling), the Runs page shows "Output so far"
with what the terminal had printed before the restart ("The run carries on in that terminal"),
and the run's Detail reads "Reconnected to its terminal after Kolux restarted"; its real finish
later completes it and the end's text replaces the replay. If the service knows the terminal
ended while Kolux was away, the run reads failed with "Kolux restarted and this run's terminal had
already ended" and keeps the terminal's last text. If the service knows nothing of it (today's
case: a new process starts terminal numbers over), the run waits for its pane to come back and
is claimed by it or closed after settling, exactly as before.
