WHAT WAS BUILT (lane-owned: src-tauri/src/orchestration.rs, src-tauri/src/orchestration/sendonce.rs)
ORCH-036 · takeover
- sendonce::other_writer (the hook the window's terminal_write calls for the user's keystrokes, via
  evidence/orchestration-T-174-b-terminal.patch) now also records WHEN the user last typed into each
  terminal (TAKEN, wall ms, this run of Kolux). sendonce::taken_over_since(id, created_ms) answers
  whether that happened after a dispatch was made. Kolux's own sends go through sendonce::claim and
  never count; a click never writes, so focus alone moves nothing (ORCH-036 rule).
- keep_open (the one check stop_with and release_with share) asks it first: a taken-over terminal is
  left open and the receipt's terminalLeftOpen says "the user typed into term-N after the worker
  started, so it was taken over and is theirs now". worker-stop then reads the process as
  unverifiable (Kolux did not end it) and still frees the task; worker-release releases without
  closing and the CLI prints "its terminal term-N is left open (...)".
- Ownership is tied to the dispatch's created time, so a terminal the user typed into earlier and a
  coordinator later reuses for a new dispatch is that new worker's again.
ORCH-067 · dispatch pass
- brief_tied(task, brief, Some(pass)) puts " --dispatch-capability <pass>" (PASS_OPTION; the option
  name COMPAT keeps) into the brief's done, failed, heartbeat and question commands, nowhere else.
  brief() stays as it was (no pass): the low-level dispatch command keeps giving none, so its workers
  stay tied to the pane's process (terminal + runtime checks in report()).
- report(): after the terminal check, a dispatch with a pass settles only when the report carries it;
  otherwise settles=false and the why names --dispatch-capability and that the task is unchanged. The
  mail itself is delivered as before (Mail::post runs first in the CLI's send).
- Mail::ask: a question from a terminal whose running dispatch has a pass is turned away (code
  forbidden, "... so no question was made") when the pass is missing or wrong; nothing is posted.
  --resume needs no pass (no question is made). A terminal with no passed dispatch asks as before.
- pass_refusal(d, a): the one wording for both, naming the option since the reader is an agent.
- passes(dispatches), redact(value), redact_read(out) (every string in a terminal read's JSON: lines,
  pending, screen rows; adds the warning "a dispatch pass was hidden from this output ([dispatch pass
  hidden])"), redact_lines(archive) (marker line "[Kolux: a dispatch pass was hidden from this
  archive]").
- The pass itself: cli::secret() (already in the tree: two std RandomState hashes, OS-seeded), one
  per worker-start, stored on the dispatch row as "pass" (the row already holds the brief, which
  carries it, so this is no new exposure; dispatch-show strips both). worker-list/worker-show build
  their own rows and never print it.
- cli.rs is shared: evidence/orchestration-T-155-b-cli.patch (applies AFTER
  evidence/orchestration-T-174-b-cli.patch; checked in that order) does: ask accepts
  --dispatch-capability; worker-start makes the pass, uses brief_tied and stores "pass" on the row;
  dispatch-show removes "pass"; terminal read passes its three answers through hidden(ctx, out)
  (redact_read with the passes on record); the release archive goes through redact_lines.
- Until that patch lands, PASS_HIDDEN/passes/redact/redact_read/redact_lines carry #[allow(dead_code)]
  (the lane tree has no caller); drop those five attributes on main.
