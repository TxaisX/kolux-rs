T-272-b: BROW-032 site permission requests in the pane (Windows engine: answered by one rule set,
a refusal named in the pane's toolbar).
lane/browser from bbb623cd · 2026-10-20 · Opus 5.5

What was built
- src-tauri/src/browser_permissions.rs (pure, unit-tested): answer(kind) and name(kind) over the
  engine's permission kinds.
  - Pointer lock and storage access: the WebView2 engine grants both without raising its
    permission event (it has no permission kind for either), so pages get them with no prompt.
  - Autoplay and repeated automatic downloads: the engine's own handling, no notice (downloads keep
    their own rules in browser_downloads.rs).
  - Every other kind (camera, microphone, location, notifications, motion sensors, clipboard
    reading, file editing, local fonts, MIDI devices, window placement, unknown) is refused and the
    pane is told "<permission> access was denied" in plain words. A kind the list does not know is
    named by its raw number ("permission 13 access was denied").
- src-tauri/src/browser_engine.rs (glue, Windows): permissions(id, controller, app) hooks the
  engine's PermissionRequested event on each page; a refusal sets the request's state to Deny and
  emits PERMISSION_EVENT {id, text}.
- src-tauri/src/browser.rs: browser_permissions module, PERMISSION_EVENT ("browser-permission"),
  browser_open hooks engine::permissions next to engine::attach and engine::identity.
- src/browser/BrowserPane.tsx: the pane listens for "browser-permission" (registered with its other
  listeners, before browser_open, so a request from the first page load reaches it) and shows the
  text as a toolbar status badge for 10 s; the user's own navigation clears it.
