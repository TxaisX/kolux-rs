== Part B: the context gauge (items 5-7; T-052, USAGE-001) ==

What the user gets:
- A Codex pane's gauge hover now reads "Context used: Codex does not report its context to Kolux,
  so there is no figure to show." instead of promising a figure that never comes (only Claude's
  status line reports context). Claude panes keep "nothing received yet"; shell panes "agents only".
- Once the hooks hunk lands: a Claude pane resumed in a new terminal keeps its session id while
  Claude's running time starts over; its gauge now fills from the first report instead of staying
  grey or frozen until the new running time passes the old one.

The resume fix (item 7), chosen as the review's "per-process stamp" option:
- evidence/marks-FIX-1-hooks.patch (replaces the first marks-T-052-hooks.patch, now deleted) gives
  the usage payload `session` = the session id with the terminal handle that ran the report, joined
  by "@", and `at` = cost.total_duration_ms. Every Kolux start or restart of a pane is a new
  terminal (terminal ids count up per spawn), so a resumed Claude is a new clock and the floor or
  stamp of the old process never holds it back. /clear (new id) and a manual compact (same id,
  same terminal, running time goes on) keep today's straggler protection.
- No terminal in the pane identity, or a missing or blank session id: no clock at all, and the
  window falls back to arrival order (the hook server's one-at-a-time loop keeps that).
- The window compares `session` only for equality, so it needed no logic change; the UsageEvent
  doc says what the field holds.
- Left as is: a straggler from the exited process that arrives after the resumed one's first
  report is taken once (different clock) and replaced by the next report.
