T-562 · a cancelled clone can hang on an orphan git-upload-pack (newproject::tests::proj003_cancel_removes_only_a_folder_the_clone_made hung full cargo runs for 10-20 minutes)
lane/setup from 3e734a0 (on main 3891c1a), 2026-10-14 · no app launched

ROOT CAUSE
clone_into killed git with taskkill /T on cancel, then read Git's error output until the pipe closed. A
process the clone started whose parent had already exited (an orphan git-upload-pack) is outside the
tree taskkill walks, keeps the inherited error pipe open, and the reader never ended.

FIX (src-tauri/src/newproject.rs, clone_into -> clone_with)
- Git joins a kill-on-close job (crate::procs::Job, the same one the archive runner uses) right after it
  starts, so every process it starts, orphans included, is in the job; a cancel closes the job (ending the
  whole tree), then kill_tree and Child::kill as before.
- The error output is read on its own thread and handed over in chunks; the main loop polls the cancel
  flag and the child every 50 ms, stops listening at once on cancel, and after Git ends waits at most 2 s
  for the pipe to drain. It never blocks on the pipe closing.
- After Git ends the job is closed, so anything it left behind lets go of the folder before the undo.
- clone_with takes extra git clone arguments; clone_into passes none (the test passes --upload-pack).
