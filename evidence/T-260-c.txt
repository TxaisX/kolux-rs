The problem: the Floor's per-pane lanes were trimmed only when the Floor read them, so with the
Floor never opened, every closed pane's lane stayed in memory for the whole run of the app. And a
state that arrived after its pane closed (a hook still in flight) cleared the lane's end time, so a
closed pane showed on the Floor as open again.

What is built (src-tauri/src/activity.rs; status.rs call sites as a patch, see below)
- trim(now): drops every lane that closed before the 26-hour reach. It runs first in every mark
  (any pane's state change, and the closing "done" every pane close writes) and on the Floor's
  read, so lanes go as marks and closes are written. FIX-1: end()'s second trim, which never had
  anything left to drop after its own mark, is gone.
- note/mark/end take the terminal the state came from. end() records the terminal that ended the
  lane. FIX-1: a state from that terminal, or from no known terminal, is dropped entirely: no mark,
  no reopened lane, no turn counted and no working stretch left open (note() returns as soon as
  mark() rejects it). A state from a different terminal on the same pane key (TERM-111 Restart, or
  Enter after exit) clears the end and the lane is open again, and counts a new turn as before.
- end(): a second close of the same pane keeps the first close time and terminal and adds no mark.
- Quit: the save at quit closes the open turns with no terminal (nothing outlives the app).

The status.rs side (hooks lane owns status.rs; NOT committed here)
