The problem: the Floor's per-pane lanes were trimmed only when the Floor read them, so with the
Floor never opened, every closed pane's lane stayed in memory for the whole run of the app. And a
state that arrived after its pane closed (a hook still in flight) cleared the lane's end time, so a
closed pane showed on the Floor as open again.

What is built (src-tauri/src/activity.rs only)
- trim(now): drops every lane that closed before the 26-hour reach. It now runs on every mark
  (a state change of any pane), on every pane close, and on the Floor's read, not only the read.
- mark(): a lane that has an end time takes no more marks: a state reported after its pane closed
  neither reopens nor extends it. The day's turn counts (USAGE-011) still see that state, so a
  new pane on the same key still counts a new turn (usage_011_closing_a_pane... unchanged).
- end(): a second close of the same pane keeps the first close time.

- New: activity::tests::t260c_ended_lanes_go_as_they_are_written_and_a_late_state_changes_nothing
  (a late working then done after the close leave ended = close time and the last mark "done";
  another pane's mark past the reach drops the closed lane without any Floor read; pane closes
  past the reach drop older closed lanes; a later mark drops them all).
- Changed: view013_each_pane_keeps_its_state_changes_for_the_floor_and_old_ones_go now asserts a
  state after the close keeps the lane ended (it asserted the opposite before).
