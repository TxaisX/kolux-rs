T-546-b item 2 · OD-09 control tower usage cards: one figure set per provider, never one account's figures under another account's name
Date: 2026-10-13 · lane look · checkout G:/Dev/kolux-rs-lanes/look (lane/look, on 7ae48db) · dev build, new look, dark

What was wrong
  usageByAccount grouped the panes by (program, account) and made one card per group, but src/usage/plan.ts holds
  ONE Claude figure set and ONE Codex set (whichever account reported last). Two Claude accounts therefore got two
  cards carrying the same figures under two names: a wrong number on the screen used to decide where work goes.

What it does now (ponytail: one card per provider; a per-account read is T-548)
  usageByAccount keeps its name (the T-546 App.tsx wiring on main imports it) and returns one entry per provider
  in use: the figures once, the pane count, and the accounts those panes run on with a pane count each. The card
  shows the provider, "N panes", one chip per account ("work 1", "personal 1"; "default" for a pane with none),
  then the 5-hour and Weekly bars once, or "No usage figures yet". The TowerView header comment no longer calls
  the Tower a second-monitor window (that is T-546-c); the summary card lost its duplicate empty-state sentence,
  the list keeps the one "Nothing is running. Start an agent and it shows up here." (there was no role="group" on
  the lane sections to drop; they are <section aria-label>).

Unit tests (src/tower/tower.test.ts, red first: 3 failed / 5 passed, then 8 passed)
  gives one card per provider with its figures once and the pane count per account under it
  never repeats a provider's figures: two Claude accounts share one card
  keeps a provider whose figures have not arrived, with null figures
