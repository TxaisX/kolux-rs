WHAT
- src/settings/importSchemes.ts (the SET-024 importer, extended):
  importGhostty(files, readTheme): reads every `key = value` line of the config (and its included files), later lines winning.
    Mapped onto Kolux settings: font-family -> terminalFont, font-size -> terminalFontSize (10..24), cursor-style -> terminalCursorStyle, cursor-style-blink -> terminalCursorBlink, scrollback-limit -> terminalScrollback (Ghostty counts bytes; about 1000 bytes counted as one row, said in a note), split-divider-color -> paneDividerDark and paneDividerLight, unfocused-split-opacity -> paneDim (30..100), copy-on-select -> terminalCopyOnSelect.
    Colours (background, foreground, cursor-color, cursor-text, selection-background, palette 0..15) and the named theme become one colour scheme; the file's own colour lines win over the theme's. A light:A,dark:B pair becomes two schemes, dark first. Names: "Theme (Ghostty)" when the file overrides the theme, the theme's own name alone, "Ghostty" with no theme.
    Theme references are looked up by name only (the back end searches Ghostty's theme folders); a name with a separator or ".." is refused and reported.
    Unknown keys, and keys Kolux has no setting for yet (window-padding-x/y, macos-option-as-alt, bold-color, selection-word-chars, selection-foreground, mouse-hide-while-typing, focus-follows-mouse, background-blur(-radius), palette 16..255), go in `unsupported`. A zero or false on the off-able ones is not reported (zero means off). scrollback-limit = 0 sets scrollback 0.
    Invalid values (not a number, out of range, not a colour, not true/false, a line with no =) go in `invalid` with the value and a reason; nothing is guessed.
    A config file over 256 KB is skipped by name with a reason, and the settings read from the other files are kept.
  parseWarpTheme(text, file, budget): the Warp reader now also takes gradients (first colour kept) and reports what it left out ("background image", "background gradient", "foreground gradient", "accent gradient"). Reading is time-limited (250 ms default) and line-limited (2000 lines); both fail with a readable message. parseWarp is kept (same result as before).
  scanWarp(files): good themes with their left-out list; unusable files by bare file name with a reason (plainSkip cuts any folder path down to its last part).
- src-tauri/src/term_import.rs (new): term_import_ghostty (first config found + `config-file` includes, relative and inside its own folder only, at most 8, each once), term_import_ghostty_theme (by name, from the themes folders, names that could leave the folder find nothing), term_import_warp (.yaml/.yml in Warp's theme folders, at most 400 files, 3 s scan budget). Every read is size-capped (256 KB); a file that cannot be used comes back with a reason that carries no folder path.
- src/settings/terminalImportRead.ts (glue: asks the back end, prefetches the theme files, builds the save patch), src/settings/TerminalImport.tsx (the Settings > Terminal section "Bring in from Ghostty or Warp": Look for my Ghostty settings / Look for my Warp themes, preview, Bring in), mounted in src/settings/TerminalPage.tsx.
- Applying a Ghostty import saves through the existing useSettings save (one patch) and shows it on the open window at once; Warp themes join terminalCustomSchemes through planImport (the 40-scheme cap and replace-in-place rules of SET-024).
