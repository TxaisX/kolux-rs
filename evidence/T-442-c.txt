T-442-c  file_read, file_write, dir_list, kit_samples off the window thread (council D2 MERGE 26)
Date: 2026-10-13, lane reliability dev app (port 1425, CDP 9247), text proof; no visible UI

Why: each of the four runs fence.allow, and for a path outside every project root (Kolux worktrees
sit outside the roots by default) allow() asks git for the worktrees of every project when its 3 s
cache is stale. As plain commands they ran on the window thread, so typing waited for git.

Fix (files.rs, kits.rs): #[tauri::command(async)] on all four. file_write: the fence check stays
outside any lock, then a WRITES mutex (one for all paths) holds the disk-hash check and the write
together, so two saves now running on worker threads cannot both pass the check; a save that
arrives second is refused as changed on disk instead of landing out of order. kit_samples now asks
git (locate_repo) before it locks the state store, then registers (register_project), as project_add does.

Harness (T-442-b method, rewritten for this card, run over CDP inside the window): stand-in git.exe first
on PATH waits 3 s then runs the real git. A project repo under G:Tempeliability-t441cepo and a worktree
made with git under G:Tempeliability-t441cworkspaceswt1 (KOLUX_WORKSPACES_DIR stand-in for
%USERPROFILE%kolux-rsworkspaces; KOLUX_SAMPLES_DIR, KOLUX_APP_DIR, CLAUDE_CONFIG_DIR, CODEX_HOME all
under the same scratch root; the real folders were never touched). Before each call the harness waits
3.6 s so the fence cache is stale, starts the call, and while it runs types one key into a cmd.exe pane
every 250 ms and times key -> echo. Calls: file_read wt1a.txt, file_write wt1a.txt (then read back),
dir_list wt1, kit_samples spreadsheet. Pass bar: echo under 50 ms on every sample.
