What is built
- TERM-082 enhanced (kitty) keyboard protocol: src/terminal/kittyKeys.ts. Per-pane state with separate flag stacks for
  the main and alternate screens (CSI > flags u push, CSI < n u pop, CSI = flags ; mode u set/or/clear, CSI ? u query
  answered CSI ? flags u; stack cap 16 with oldest evicted; a pop that empties the stack resets all flags). Keys are
  encoded only while the active screen's flags are non-zero: Escape, Ctrl/Alt/Super combos as CSI code;mods u, Alt+digit
  as CSI 49;3u, Shift+Enter as CSI 13;2u, modified arrows/function keys as CSI 1;mods X or CSI n;mods ~ (F3 = 13~),
  event types (:2 repeat, :3 release), alternate keys (shifted and base-layout key), all keys as escape codes
  (modifier keys left/right apart, keypad numbers) and associated text. Dead keys, input-method keys and AltGr typing are
  never encoded, so accented characters still compose. Kolux chords are routed before the encoder (shellKeys.ts), so
  Ctrl/Cmd chords Kolux owns are never sent. Wired in TerminalPane.tsx: CSI u handlers for the four prefixes, ESC c and
  program exit reset the protocol (VIEW-109 reset), the key handler encodes keydown/keyup; an agent pane on the protocol
  gets Shift+Enter as CSI 13;2u instead of the agent newline bytes.
- TERM-086: latinControl() sends the Latin control byte for Ctrl+letter on a non-Latin layout from the physical key
  (Ctrl+C on Russian = 0x03, Ctrl+D on Greek = 0x04). macOS system-wide key remaps: Mac-only, not built (Windows has
  no equivalent the web view sees; the OS applies its own remaps before the key event).
- TERM-085: Rust command terminal_next_input_source (terminal.rs): posts WM_INPUTLANGCHANGEREQUEST with HKL_NEXT to
  the focused window (the OS language-hotkey behaviour, per Microsoft Learn). The keybinding command
  terminal.switchInputSource already ships unbound in src/keys/actions.ts; the pane now runs the command when the
  assigned chord is pressed and the key never reaches the terminal. Registration: evidence/core-T-306-lib.rs.patch.
- TERM-073 / TERM-084 / TERM-087: already built under SET-025 (inputPrefs.ts middleClick/pastesOnMiddle +
  inputWire.ts middlePastes/middleSource; yenToBackslash in the pane's onData; watchPointer). Existing tests:
  src/terminal/inputPrefs.test.ts (middle-click on for Linux, off on Windows; Yen to backslash only when on; pointer
  hides only while typing and only when on). TERM-073's macOS default conflicts with SET-025 (P1 says on for macOS):
  SET-025 kept, after-list row.
