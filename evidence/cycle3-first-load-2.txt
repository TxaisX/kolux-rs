== 2. Item 1: where the 315,352 bytes come from, and why the whole chunk had to go

Cause: src/editor/buffers.ts had one runtime import that was not needed for its job as a document store —
  import { isolateHistory } from "@codemirror/commands";
isolateHistory groups a reload as one undo step of its own. @codemirror/commands imports
@codemirror/view and @codemirror/language, so all four packages landed in one 315,352-byte chunk that
the first frame pulled through editor/buffers.ts (FloatingLayer asks isDirty, the window asks keyOf and
baseName, terminal/paneActions asks keyOf).

Measurement A — drop only that one import, nothing else, to see what it alone costs:
  commands import replaced by a one-line stand-in, $ pnpm exec vite build && node scripts/bundle-budget.mjs
  bundle-budget: first load 1573821 bytes in 41 chunks (ceiling 1880000)
  the chunk fell 315,352 -> 49,171 bytes: @codemirror/state alone, still on the first frame through the
  same module. 266,181 bytes were commands+view+language.
So dropping only commands would have landed at 1,573,821 — still 73,821 over the 1.5 MB bar, with the
state package (49,171) still in the first frame. That is why the fix removes CodeMirror from the store
entirely rather than just the commands import.

Measurement B — the split as committed (a0acb905):
  bundle-budget: first load 1524454 bytes in 40 chunks
  dist-BCxUsHlj.js (315,352) gone; buffers-DcBqAKQY.js 26,471 -> buffers-D5naiSCn.js 3,396 (the store
  itself); App 1,019,415 -> 1,019,359; index 309,971 -> 309,942.
  Cut: 1,862,966 - 1,524,454 = 338,512 bytes.

What changed: editor/buffers.ts keeps the documents (open documents, dirty state, save, line endings,
carry-over, held text, opening) and its public API, and carries no CodeMirror import at all — even its
@codemirror/state import is `import type`, which erases. The five values it cannot make itself are
installed by the new editor/editors.ts, the CodeMirror side: the synced annotation and reading it, the
undo grouping, a view's line separator compartment, and Text.of split into lines. editor/editors.ts also
takes over lineEndsFor and withLineBreaks and re-exports the store, so a caller imports one module and
the CodeMirror values are installed before any view can be attached; a missing install throws by name
instead of mis-grouping undo.

Identity proof for isolateHistory (it is compared by identity with the history extension, so a local copy
would silently change undo grouping): EDIT-001-003's box 2 ("Reload makes the buffer match disk and offers
undo; undo brings the edits back") builds a real history() extension, reloads through replaceAll(....,
undoable), then calls undo() and expects the typed text back. With the real isolateHistory: passes. With
one stand-in annotation swapped into editor/editors.ts: fails ("box 2 ... 1 failed"). The file was put back
byte for byte and the test passes.

Files: editor/buffers.ts, editor/editors.ts (new), editor/EditorPane.tsx, editor/DiffPane.tsx,
editor/buffers.test.ts, editor/carryOver.test.ts, editor/diskChange.test.ts, editor/drafts.test.ts,
editor/fileMoved.test.ts, editor/logFollow.test.ts, editor/staleSave.test.ts,
editor/__cards__/EDIT-001-003.test.ts (the last eight: one import line each, from ./buffers to ./editors,
so the test that builds a CodeMirror state imports the CodeMirror side).

== 3. Item 2: the onboarding guide helpers, and which of them the first frame really needs

Cause: the help button in the sidebar footer (onboarding/HelpMenu.tsx, drawn at start) imported the guide
window for its ring and live steps (Guides.tsx), the tour catalogue, the step panels, the stop cards, the
CLI setup, the integrations panel and the star prompt. That is also why vite never split Guides.tsx:

  [INEFFECTIVE_DYNAMIC_IMPORT] src/onboarding/Guides.tsx is dynamically imported by src/lazy/pages.tsx
  but also statically imported by src/onboarding/HelpMenu.tsx, dynamic import will not move module into
  another chunk.

Fix: HelpMenu.tsx is now the button only; the menu is onboarding/HelpSheet.tsx, deferred through
lazy/pages (prefetch() reads it after the first frame). Same items, order, backdrop, Escape and
autoFocus; useGuideState(true) reads the steps when the sheet mounts, as useGuideState(at !== null) did
when the menu opened.
