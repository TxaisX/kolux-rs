T-074 · BROW-008 Pages that fail to load get a recovery overlay · BROW-009 Crashed pages recover by themselves
Lane browser, from 0a301115 (main b603fb22 merged). 2026-10-19. Routing v3: unit tests at the boundary, live proof batched.

What the user now sees
  BROW-008: an address that cannot load (nothing listening, unknown host, bad certificate) gets an overlay over the
  pane body: "This page could not load", a plain sentence naming what failed, Retry, and when they make sense
  "Switch to HTTPS" (a failed http address that is not this computer's, scheme only) and "Open Externally" (the
  system browser). Local-server advice ("If this is your own server, start it, then press Retry") appears only for
  this computer's addresses. While an overlay action runs its buttons are disabled together and "Connecting..."
  appears after 300 ms, so a quick retry does not flicker. Every reload trigger on a failed page is a Retry.
  BROW-009: a page whose process died is reloaded once by itself (the tab reloads in place, no overlay). If that
  reload never answers or lands on the engine's error page, the overlay says "This page stopped responding ...
  Kolux reloaded it once and it did not come back" with Retry and Open Externally and no network advice. No
  reload loop: the one automatic reload comes back only after the user's own Retry or a typed address.

Why this detection route (the 2026-10-13 HAND TO FABLE question)
  wry 0.57 (local cargo registry source, src/webview2/mod.rs ~line 726) registers NavigationCompleted with the
  event args ignored: `|webview, _|`, so IsSuccess / WebErrorStatus never reach Tauri; on_page_load gives only
  Started and Finished, with webview.Source() as the url. There is no public failure or ProcessFailed hook.
  Route taken: the pane asks the page where it is. `browser_probe` runs `location.href` through
  Webview::eval_with_callback (tauri 2.12.1, webview/mod.rs line 2185; the answer is the result as JSON, as the
  icon query already relies on). WebView2's own error page answers "chrome-error://chromewebdata/"; a live page
  answers its address; a page whose render process died answers nothing useful (wry's ExecuteScript handler
  passes the result string and drops the HRESULT, so a dead page gives "" or "null", or no callback) and the
  command answers "no-answer" after 1.5 s (std mpsc recv_timeout inside spawn_blocking; no tokio dependency).
  The pane probes every 250 ms while the page is on screen (BROW-008: "about four times a second, paused while
  hidden"), one probe in flight at a time; three unanswered probes in a row = dead (a page in a long script
  misses one or two). The same probe serves both cards, so no new dependency (webview2-com) is needed.
  Rejected: a TcpStream probe alone (cannot tell a failed page from a slow one and says nothing about a crash);
  webview2-com's ProcessFailed / NavigationCompleted args (Cargo.toml, outside the lane; the probe covers the
  behaviour; the event would only make crash detection instant instead of ~1 s).
  Why the overlay hides the page: the page is a native child web view laid over the pane body, which the app's
  own elements cannot cover; BrowserPane sends shown=false to browser_bounds while the overlay is up and the
  overlay fills the body in its place; Retry's `started` brings the page back.
  What failed, for the wording: `browser_diagnose(url)` (same `allowed` check as a load) does name lookup +
  one TCP connect (url.socket_addrs, 4 s) and for https a strict reqwest HEAD whose error chain is searched for
  certificate wording -> kind unknown-host / refused / timeout / unreachable / certificate / unknown, plus
  `local` (local_host) and the https twin.

Open (one sentence each, also on the PLAN line)
  - BROW-009 "rebuilt when a reload cannot work": the web view is not recreated; after the one failed reload the
    user's Retry reloads again. A rebuild (browser_close + browser_open) needs the tab's spot and colour from the
    pane; left for the bug-fix phase (kolux-rs-after.md row).
  - Instant crash detection through WebView2's ProcessFailed event needs webview2-com (Cargo.toml, outside the lane);
    the probe detects a dead page in about a second instead.
  - BROW-008 "Open Externally is hidden when no outside handler exists": the system's handler is not queried; the
    button is hidden only when the address cannot be reached from this computer.
