lane/orchestration from b6e8ab4a · 2026-10-19 · Claude Sonnet 5.5

What is built
- src-tauri/src/activity.rs: Track gets a parent (the pane number of the session this one was started
  under). New nest_lanes(lanes, tasks, dispatches, runtime) works it out from what the CLI stores: the
  dispatch that ran in a lane's terminal belongs to a task; if that task has a parent task (same Run), the
  newest dispatch of the parent task that sits in the terminal of another lane makes that lane the parent.
  Dispatches stamped by an earlier start of Kolux are ignored (terminal numbers count up again), a parent
  task of another Run is not the parent, a task naming itself or two tasks naming each other nest nothing.
  activity_timeline now also reads the stored tasks and dispatches (read only, apart from the activity lock)
  and fills parent; it was already registered, so no registration changes.
- src/floor/timeline.ts: lanes() returns each lane with a depth: roots in pane order, every child right under
  its parent, grandchildren one step further; a child whose parent has no lane in the range, or whose chain
  loops, stays on top; no lane is drawn twice.
- src/floor/FloorView.tsx: a child lane's name is indented 14 px per step with an arrow; the bars keep the
  same left edge so the time axis stays true.
