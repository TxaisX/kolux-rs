No app launch. Proven with unit tests (a real PowerShell in a real ConPTY for 801) and vitest; LIVE PROOF PENDING: stress S6 re-run on main.

ROW 801 ROOT CAUSE
  On Windows the console host (ConPTY) honours "CSI 8;rows;cols t" (resize the text area) itself: a program printing ESC[8;1;1t
  shrinks the pty to 1x1. The page never asked for that, still thinks the pane is 44 rows, and nothing tells the host otherwise,
  so the pane draws one character per line and looks dead. xterm.js was not the cause (it refuses window ops by default).
FIX (src-tauri/src/pty_window_ops.rs, wired in pty.rs)
  - PtySession keeps the master behind Arc<Mutex> and a SizeKeeper holding the page's latest size (set by resize()).
  - The output callback is wrapped (window_ops::guarded): WindowOpScan reads each chunk for two signs and, on either, a short-lived
    thread re-applies the page's size (requests arriving while one is queued fold into it):
      1. a size report "ESC[8;rows;colst" for a size other than the page's (the page's own size never loops);
      2. the way a 1x1 console draws, every character as "ESC[H LF char" (4 within 2 s), for hosts that shrink without reporting.
  - Cost: a chunk with no ESC byte returns at once; no per-byte allocation; the carry-over between chunks is at most 12 bytes.
    Gated with cfg!(windows) (added this pass): on other systems the output is not read at all. Only PtySession (local pty) is
    touched; SSH/remote panes do not go through it.
  - Changed in the predecessor's tree: the cfg!(windows) gate above, and a stray line left by a mangled edit in
    pty_resize_tests.rs (it stopped the test build). Nothing else.

ROW 802 ROOT CAUSE
  xterm.js reports every byte its escape parser has no move for ("ESC [ <non-ASCII>") with console.error("xterm.js: Parsing error: ").
  Random escape noise gives thousands (12464 lines for 2 MB), costs time and hides real errors.
FIX (src/terminal/xtermLogger.ts, wired in TerminalPane.tsx: `logger: xtermLogger`)
  - Parse errors are counted and summed up in ONE console.warn per 10 s window ("xterm: N malformed escape sequence(s)...").
  - Every other message and level still reaches the console unchanged (error, warn, info, debug, trace->log).
  - The settings preview Terminal (TerminalPage.tsx) only prints a fixed sample, so it is left as is.
  - Changed in the predecessor's tree: the test's control assertion matched "Parsing error" at the start, but without a logger option
    xterm prefixes "xterm.js: ", so it counted 0; now uses includes(). The node:fs read of TerminalPane.tsx became a ?raw import (tsc had no node types).
