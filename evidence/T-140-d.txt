The problem: a finished run kept up to 16,000 characters of its pane text (RUN_OUTPUT_CHARS) inline
in the "automations.runs" list, and on_status loads and saves that whole list on every hook status,
so up to 100 runs x 16 KB were parsed per status. The opened run also said "its terminal had
closed before the run ended" for any finished dispatched run with no output, whether or not its
pane had closed.

    that key and leaves "outputSaved": true; with_output puts it back for the page; has_output
    reads either form; drop_outputs clears the keys of runs that are gone.
  - keep_output (screen text) and patch_run (a precheck's skipped output) store the text in the
    run's own key; keep_screen's and keep_output's "already has output" checks use has_output.
  - list() puts each run's output back, so the page reads run.output as before.
  - tidy() (on load) moves output saved inline before this change to its own key.
  - prune now returns the runs it dropped; new_run, tidy and delete clear those runs' keys.
  - pane_ended marks the run it closes "paneEnded": true.

- src/automations/RunsDashboard.tsx RunPage: "No output was saved for this run: its terminal had

  again, so a run that just finished gets its usage without reopening the page.

  Store::remove in state.rs (not this lane's file) would drop it.
