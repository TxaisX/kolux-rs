after-list row 151 (T-241 BROW-038): the drawing canvas.

Built
- Back end: src-tauri/src/browser_picture.rs. browser_capture(id) asks the page's engine for Page.captureScreenshot
  (the visible page, PNG) and Page.getLayoutMetrics (its CSS size) through browser::devtools, the same driver path
  `kolux screenshot` uses. browser_save_picture(data, name) decodes a PNG (data URL or base64, 32 MB cap, PNG header
  checked), names it <clean name>-<seconds>.png in the app's captures folder, never overwrites, answers the path.
- Front end: src/browser/DrawCanvas.tsx (+ SendButton.tsx), rules in src/browser/draw.ts (add/undo/redo/clear,
  finishDrag, addText, fitScale/toPicture, arrowHead, paint, describe, drawMessage), calls in src/browser/picture.ts
  (capturePage, sendPicture). BrowserPane: a "Draw" button; the page is hidden while the canvas covers the pane body.
- Send path: the pane's existing targets()/onSend(key, text) (the one page notes use); the agent gets the saved
  picture's path and a list of the marks.
- Registration: evidence/browser-fix-151-lib.rs.patch (two lines after browser_pane_ready; apply after the 719 patch).

Tests: vitest src/browser (draw.model.test.ts, picture.test.ts); cargo test browser::picture (5 tests).

a box, press A and drag an arrow, press T, click, type, Enter; Ctrl+Z undoes; Send to agent lists the worktree's
agent sessions; the chosen one receives "Marked-up screenshot of ..." with a Picture file path that opens as the
marked-up PNG. Close/Esc shows the page again. Rest: WebView2 must answer Page.captureScreenshot for a page that
is on screen (it does for `kolux screenshot`).
