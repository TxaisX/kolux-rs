What the user can now do (PROJ-039)
  Start an agent with a prompt in a workspace whose name Kolux suggested (a creature name the composer offered and the user left
  as it was, or a workspace an agent launch made for itself): the branch is renamed to a short lowercase hyphenated name taken
  from the work (the configured commit-message writer proposes it; without one, or when it answers nothing usable, the task's own
  words do), and the shown name becomes its sentence-case form ("Fix the login bug"). It happens once per workspace: the mark
  that allowed it is taken away by the rename, so a later prompt changes nothing. Never renamed: a workspace the user named by
  hand, the main checkout, a branch somebody already renamed in Git, a branch that was pushed (tracking configured, or a remote
  holding the name), a branch linked to a pull request, and everything when Rename branches after the work is off in Settings or
  the branch-naming switch of GIT-020 is off. Work-item markers in the prompt (#123, KOL-12, [ABC-7]) never become the name.
  The rename is "git branch -m" only: nothing is deleted or overwritten; a taken name gets -2, -3.
