Setup: throwaway repo G:/Temp/release-T-177e/repo with committed draft.txt ("alpha line", "second line") and
taken.txt ("already here"). Added with project_add, workspace selected, explorer opened (Ctrl+Shift+E).

1. Opened draft.txt from the explorer and typed "EDITED " at the start without saving: the tab is unsaved,
   text "EDITED alpha line / second line".
2. F2 on draft.txt in the explorer, typed taken.txt, Enter: the explorer says "taken.txt already exists here";
   rows still draft.txt, taken.txt; on disk taken.txt still reads "already here"; the tab is still draft.txt and
   still unsaved with "EDITED alpha line". Screenshot: evidence/T-177-e-taken.png.
3. F2 again, typed renamed.txt, Enter: explorer rows renamed.txt, taken.txt; the tab strip shows renamed.txt;
   the tab is still unsaved with "EDITED alpha line" and the caret where it was (offset 7, after "EDITED ").
   Screenshot: evidence/T-177-e-renamed.png. On disk renamed.txt still held the old text (nothing saved yet).
4. Ctrl+S in the tab: renamed.txt on disk now reads "EDITED alpha line / second line"; git status " D draft.txt",
   "?? renamed.txt" (no draft.txt written back).
5. Typed "AGAIN " (unsaved), then Ctrl+Z in the explorer undid the rename: rows draft.txt, taken.txt; the tab
   followed back to draft.txt and still holds the unsaved "EDITED AGAIN alpha line".
