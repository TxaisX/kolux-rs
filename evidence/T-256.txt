WHAT CHANGED
- src-tauri/src/shell_history.rs (new): a bash or zsh pane gets HISTFILE = <app data>/shell-history/<worktree key>/{bash,zsh}_history, a fish pane
  gets fish_history = kolux_<build tag>_<worktree key>. The worktree is the nearest folder at or above the pane's start folder with a .git entry
  (folder or file, so linked worktrees count). Key = last folder name + 16 hex of SHA-256 of the normalised path. cmd, PowerShell, WSL's bash.exe,
  sh and anything else get nothing. A HISTFILE / fish_history already on the command (the user's environment or the pane's own variables, empty
  too) is kept and no folder is made. Folders are made 0700 on Unix; on Windows they inherit the profile's private rights.
- Sweep at start-up (first shell spawn of a run, on its own thread): a history folder whose recorded worktree is gone while the folder above it
  is there is removed; fish sessions of this build without a folder are removed; an unplugged drive (parent also missing) is kept.
- src/settings/TerminalPage.tsx: switch "Keep shell history separate for each worktree" (field shellHistoryPerWorktree, on unless false).
- Hand-back hunks (terminal.rs spawn env, lib.rs mod line): evidence/shell-T-256-terminal.rs.patch, evidence/shell-T-256-lib.rs.patch
  (both `git apply --check --ignore-whitespace` clean on dff7cd49). They were applied in the working tree for the runs below, then reverted.
