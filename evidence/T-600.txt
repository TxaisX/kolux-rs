T-600 · The update card never opens itself or takes the keyboard (F02-settings-update.1; APP-024, APP-026, VIEW-100), reliability lane, 2026-10-30

Cause: the card's `requested` flag was sticky. Only Dismiss cleared it: Escape (collapse) left it set, and a download
error set it even after a quiet check. A later half-hourly check inherited it (checkDone used s.requested ||
a.requested), so the card re-expanded by itself. The focus effect focused the card whenever shown && !collapsed &&
requested, on every change of phase, so the terminal lost the keyboard. In the ready phase the user's next Enter (meant
for an agent) ran Restart, which ends every agent.

What changed (src/update/card.ts, src/update/UpdateCenter.tsx):
- card.ts:25-31  `requested` now means "the user asked for what the card shows and still holds it" (their Check for
  updates, the status-bar item, the card's expand). New `flow` = "the current flow started with the user's own check":
  its changes of phase reopen the card, also after a collapse, as APP-026 says ("every change of phase reopens it").
  A quiet check starts a flow of its own, which never reopens it.
- Rule 1 (card.ts:123-149, 174-187): a quiet checkStart only clears requested/flow and leaves the card as it is. Only a
  check the schedule reports as the user's (a.requested, including a quiet check the user took over) shows, reopens or
  hands the card to the user (`theirs`). A quiet check's failure never shows an error (APP-024). downloadFailed (normal,
  refused, calm or compatibility) still brings the card up (APP-026: download errors do) but never sets requested; the
  calm "not yet" after a quiet check keys on `flow`.
- Rule 2 (card.ts:201-204, 220): collapse clears requested; expand and the status-bar show set it (both are the user's
  clicks); faded and dismiss clear requested and flow.
- Rule 3 (card.ts:113): reopen() keys on `flow`, so phase changes from a quiet check never re-expand a collapsed card.
- Rule 4 (UpdateCenter.tsx:42-44, 79, 146, 172-177, 255, 261): the focus effect on phase is gone. The user's own clicks
  (check(), the status-bar show, the card's expand) bump a click counter, and only a new click moves the keyboard to
  the card, once that click has drawn it. A counter, not a flag: a show with nothing to show leaves no focus claim
  behind for a card that comes up later (tested).
- Rule 5 (UpdateCenter.tsx:250-251): a bare Enter on the card runs Restart only when `requested` is set; every other
  main action, and the Restart buttons, work as before.

Judgement call to confirm: APP-026 says "the card can be collapsed and every change of phase reopens it". That is kept
for the user's own flow (`flow`): if they collapse the card while the update they asked for downloads, it opens again
when the download is ready. It no longer takes the keyboard, and Enter will not restart from it until they click it
open. Background checks never reopen it. If Txais would rather a collapsed card stayed collapsed, delete `flow` and
key reopen() on `requested`; the card test for that rule then changes.
Still needs a live Windows run on an installed copy with updates on: click Check for updates, let it get ready, press
Escape, type in an agent for over 30 minutes -> the card stays collapsed and no Enter restarts Kolux; with the network
cut during a background download -> the card shows the error without taking the keyboard.
