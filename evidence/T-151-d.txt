What changed
- src-tauri/src/terminal.rs: new last_drawing() decides what a line shows after its last redraw. OutputLog::push (a
  finished line) and OutputLog::read (the unfinished pending text) both use it instead of a bare split on carriage
  return. A redraw starts over at the first column, and now so do the cursor-movement forms of that: CSI n G, and CSI
  row;col H / f with the column left out, 0 or 1 (plain CSI H too). A shell that repaints what is typed through those
  sequences used to have every drawing run together after the escapes were stripped, which an agent reading the stream
  saw as the command twice or more. A move to any other column keeps the text before it, so a screen laid out with
  positioning still reads in order. The row of an H / f move is ignored (noted in a ponytail comment).
- Unit test: terminal::tests::log_keeps_one_drawing_of_a_repainted_line (CR repaint, CSI G, CSI 2K after a start-over,
  H with hide/show cursor around it, f, the pending text, a mid-line move that must keep its text, and the progress
  line that keeps its last drawing). The existing log_numbers_lines_and_pages_by_cursor still passes unchanged.

Not verified at the byte level: the real bytes PSReadLine / ConPTY write for a repaint were not captured (no app is
launched in this lane), so the card's "CR repaints" is covered in all three forms it can take (CR, CSI G, CSI H / f).
