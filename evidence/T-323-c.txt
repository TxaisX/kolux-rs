(a) Icon fetches and a saved proxy (browser lane) - DECIDED + BUILT
DECISION (coordinator default; Txais may overrule): with a saved proxy (Settings httpProxy) the page icon is not fetched at all.
  The icon clients are built with no_proxy() on purpose (their public-only name lookup could not see a proxy's side), so they
  always connect DIRECT. Before this change a saved proxy therefore did not stop icon fetches: they went around the proxy.
  The card text ("a saved proxy leaves them without icons rather than sending them around it") is now true.
BUILT: src-tauri/src/browser.rs - icon_fetch_allowed(saved) (false for a saved proxy, an address the engine cannot take, or an
  unreadable sealed value), fetch_icon_unless_proxied (the gate in front of fetch_icon), saved_proxy(app) (the store read that
  browser_open already did, now shared), icon_for calls the gated fetch.
TEST: browser::tests::t323c_with_a_saved_proxy_no_icon_fetch_goes_direct - a loopback listener: under a proxy value the fetch returns
  None and the listener sees NO connection; with no proxy the same fetch returns the data: icon as before.
NOT CHANGED (noted for the coordinator, outside this card): the other direct requests through the same clients (browser::head: a
  download's size in browser_downloads.rs, the failed-load diagnosis, dev-server checks in browser_ports.rs) still go direct. The
  dev-server check is local by design; the update installer HEAD probe is skipped under a proxy by the T-323-b patch chain. A
  download-size HEAD to a public host under a proxy is the one left; icon_fetch_allowed(&saved_proxy) is the call a caller would use.
