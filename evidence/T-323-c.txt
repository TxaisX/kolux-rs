(a) Icon fetches and a saved proxy (browser lane) - DECIDED + BUILT
DECISION (coordinator default; Txais may overrule): with a saved proxy (Settings httpProxy) the page icon is not fetched at all.
  The icon clients are built with no_proxy() on purpose (their public-only name lookup could not see a proxy's side), so they
  always connect DIRECT. Before this change a saved proxy therefore did not stop icon fetches: they went around the proxy.
  The card text ("a saved proxy leaves them without icons rather than sending them around it") is now true.

FOLLOW-UP T-323-d (lane/browser-proxy, 2026-10-26, after-list "T-323-c follow-up" browser MEDIUM)
Every request Kolux makes itself goes through browser::head (the AppHandle one). It now reads the saved proxy and calls
head_unless_proxied -> head_gate(saved, url): without a proxy it asks as before; with a saved, unreadable or unusable proxy
only this machine's own addresses (localhost, 127.0.0.0/8, ::1) are asked; every other address returns Failed{text:
PROXY_SKIPPED} ("skipped: a proxy is saved, so Kolux made no direct request") with no connection.
PER CALLER
- Download-size probe (browser_downloads.rs ask_total): GATED via head; the Err hits its `else return`, so no size shows under a
  proxy; the download itself still goes through the engine's proxy. Test t323d_with_a_saved_proxy_no_head_goes_direct.
- Failed-load diagnosis (browser_diagnose): GATED twice: skipped_diagnosis() runs first, before the name lookup (a lookup would
  also go around the proxy), and answers Diagnosis{kind:"skipped"}; head's own gate is the backstop. UI: Kind "skipped" in
  src/browser/loadState.ts reads "<host> did not give Kolux a page. Kolux did not look into why, because a proxy is saved.",
  no local advice, Open Externally kept. Tests t323d_the_diagnosis_under_a_proxy_is_skipped_not_probed (Rust),
  loadState.test.ts "a skipped diagnosis ..." (TS); t074_the_diagnosis_serialises_for_the_pane unchanged and green.
- Dev-server check (browser_ports.rs browser_dev_ports): DIRECT-KEPT, loopback only (loopback(port)); a proxy never carries
  loopback (the engine's implicit bypass), so it is not a bypass. Proof: the same test (loopback head connects under a proxy,
  unusable proxy and `localhost` included).
- Update installer probe (update.rs installer_missing): ALREADY-GATED at the call site by T-323-b (skips the HEAD when
  app_http::plan_for routes via a proxy); update.rs is unchanged. It now also passes through head's gate (release host is public,
  so it is skipped under any saved httpProxy; same outcome, not doubled work).
LAN DECISION: browser_open applies the proxy with proxy_url only (browser.rs ~1067), no bypass list, so the browser pane's own
LAN traffic goes through the proxy. A direct LAN request from Kolux would therefore go around it: LAN addresses (192.168.x,
10.x, *.lan, single-label names, 0.0.0.0) fail closed like public ones. Test rows in t323d_with_a_saved_proxy_no_head_goes_direct.
NOTE (not changed): an EMPTY proxy setting means "the system's own proxy" (OD-18); head_gate treats that as no proxy, exactly as
icon_fetch_allowed did in T-323-c, so a Windows system proxy is not honoured by these direct requests.
