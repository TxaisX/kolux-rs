What is built
- src-tauri/src/resources/update_care.rs (new, lane-owned):
  - install record: before the installer starts, update.lastAttempt holds {from, to, at, notes};
    `outcome(raw, running, now)` at the next launch says Failed (still on `from`) or Updated (now on
    `to`); records older than 7 days, or a launch on some third version (a deliberate move), say
    nothing. The page reads it once (update_last_attempt clears it).
  - restart watchdog (APP-029): `Watchdog` arms a 20 s deadline when the installer is started; if
    the app is somehow still running then, it exits so the installer is not blocked; an install
    error stands it down. Arming again never moves the deadline later.
  - `install_cause`: plain reasons for an installer that would not start (permission refused / UAC
    cancelled, needs administrator, access denied, file in use, disk full, other), with paths
    scrubbed and secrets masked.
  - `classify`: download/check errors sorted into no release yet, no installer for this system yet,
    installer not uploaded yet (incomplete release), connection protocol problem, other.
  - `compat_mode(saved, env)`: compatibility mode (HTTP/1.1 only) from the store key
    update.compatMode or KOLUX_RS_UPDATE_COMPAT=1/0 (the variable wins).
  - `CheckRounds`: only the newest check may store its answer (an older one answers "stale").
- src-tauri/src/resources.rs: pub mod update_care (dead_code allow until the update.rs patch).
- Wiring (evidence/reliability-T-199-update.rs.patch, applies after the T-293 patches):
  update_check: newest-round guard, compatibility client, no release JSON = up to date, missing
  platform entry = calm "no installer for this system yet", installer URL answering 404 to a HEAD
  request = calm "still being published", protocol error = offer compatibility mode;
  update_download: same sorting; update_restart: a second click while installing does nothing;
  records the attempt, arms the watchdog, and on an installer error stands down, clears the
  record, writes a diagnostics line, keeps the update ready and returns the plain cause;
  install_on_quit records the attempt too. New commands update_last_attempt and update_compat
  (evidence/reliability-T-199-lib.rs.patch registers them). The patch drops the dead_code allow.
- Card (evidence/reliability-T-199-UpdateCenter.tsx.patch: card.ts, card.test.ts, UpdateCenter.tsx):
  calm "No update to install yet" card on a requested check (no status-bar item, no button),
  silent on a quiet check with one short re-check 10 minutes later; "Use compatibility mode"
  button that saves the choice and checks again; "Kolux RS X could not install" with the cause and
  Restart to update again; a stale answer is ignored.
- Lane-owned page (src/recovery/model.ts updateNotice, src/recovery/RecoveryMount.tsx): at the
  launch after a failed install, a notice "The update to Kolux RS X did not install, so this is
  still Y" with Try again (runs a requested check), Download installer (link to the releases
  page) and Dismiss. Without the patches the command is missing and nothing shows.

Why APP-061 stays open
- scripts/release.mjs already checks, before publishing, that the installer and its .sig exist,
  that `kolux --version` of the built CLI matches, and that tauri.conf.json carries the version.
  The rest of APP-061 (start the packaged app on a throwaway profile, 16 panes with GPU, clipboard,
  WSL, migrate an old profile) needs the packaged app launched, which builders may not do, and the
  CLI has no profile-migration command to drive. It needs the release lane plus a live-proof run.
