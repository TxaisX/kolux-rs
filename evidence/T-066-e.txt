1. What the user gets
- An agent tab without status hooks (Cursor, Gemini CLI, Hermes, Goose, Amp: the five rows of SOURCES with a sessions
  command) comes back resumed after a quit, the way a Claude Code or Codex tab does: when the layout is written down,
  Kolux runs the agent's own sessions command in the tab's folder and takes the newest session listed there that no
  other tab holds. An id the agent printed itself (its exit hint, T-066-d source 1) or a hook's id is never replaced.
- Two tabs of one agent in one folder never get the same session (each answer is added to `taken` for the next ask).
- A sessions command that hangs is killed after 5 s and gives nothing; a missing program gives nothing; a layout save
  never waits on it (the ask runs beside the write and the id rides the next write).

2. What changed

  LIST_WAIT (5 s; taskkill /T on Windows), at most LIST_CAP (256 KB) read, then session_id::pick_listed. The .cmd shim
  case goes through pty::start_line_on as every other agent start does.

  program found; the program is the user's own command for the agent when set, else agents::installed_program (now
  pub(crate)); Err only for an empty folder.

- src-tauri/src/terminal_session_id.rs: `#![allow(dead_code)]` and its ponytail note dropped; the module comment names the caller.
- src/terminal/layout.ts: panesWantingListedSession(panes) -> { asks, taken }: a started agent tab with no session and
  an agent outside HOOK_FED_AGENTS (claude, codex) is asked, with its folder; a chooser never started, a non-terminal
  tab and a tab with no folder are not; `taken` is every session id some pane holds plus each fork's source.
