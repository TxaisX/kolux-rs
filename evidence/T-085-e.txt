T-085-e · AUTO-004 agent finished trigger · lane/automations from fe376cf9 · 2026-10-19 · Claude Fable 5.1

What the user can now do: an automation switched to Event > "agent finished" starts a run when an
agent working in one of that project's worktrees finishes its turn for real. It does not start on
the session's opening prompt, on /clear or a resume, on a Ctrl+C-interrupted turn, on a sub-agent's
finish, on a pane restored after a restart whose agent has not been seen working since, or on a
pane that an automation run itself opened (no automation triggers itself). The usual five-minute
rest after an event and the precheck ahead of the run still apply (on_event, unchanged).

Code: src-tauri/src/automations.rs
- agent_finished(seen, pane_key, state, boundary, child, interrupted) -> bool: the per-pane state
  machine ("work seen since the last finish or boundary"); a done spends it, so it fires once.
- own_pane(runs, terminal, pane_key): any run that follows (or followed before a restart) this
  terminal or hook pane makes it an automation's own pane.
- on_finish(app, ...): the live feed. Looks the pane's folder and agent up (Terminals::of_pane),
  skips automation-owned panes, then on_event(l, "agent-finished", cwd, "Event: <agent> finished
  its work in <folder>", now).
