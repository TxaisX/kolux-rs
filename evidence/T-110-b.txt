What the user can now do (STAT-039)
  The first prompt an agent gets in a worktree Kolux named (typed into the composer, or into an agent started without one: the
  hook stream's UserPromptSubmit report carries the prompt and the pane; T-107-d) renames the branch and the shown name to a
  slug of the task. Then a question appears: "Rename the folder too?" with the folder's old and new last parts. Rename folder
  runs `git worktree move` (Git's own records follow; nothing in the folder is removed, the uncommitted files come along) and the
  open panes, the active folder and the sidebar follow the folder. Keep the folder leaves the folder as it is. A move Git refuses
  (a terminal or agent still working in it holds the folder on Windows; the place is taken) is shown in full and nothing changes.
  Settings > Git & worktrees: "Ask to rename the folder too" (on by default, shown while branch renaming is on); off keeps the
  folder while the branch and the shown name still change. Work-item markers (#123, KOL-12) never become the name (T-107-d).
  A project that is a plain folder without Git only gets a new title (no branch, no folder move), once, unless the user named it.
  A failed rename is kept as the folder's error and cleared when a later rename succeeds (renameOnWork.ts, T-107-d).
