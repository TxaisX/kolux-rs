WHAT CHANGED (what the user gets)
- A Stop sends back the start time of the program the row showed. The Rust side refuses the Stop when
  that start time is not the live program's, so a row that went stale (the program ended and another
  one took its process number before the click) stops nothing and says why. Three readings of the
  start time must now agree: the scan the user saw, the stop's own re-scan at the click, and one taken
  right before the kill. NOT covered, and now said so in the code: the milliseconds between that last
  reading and taskkill reaching the process; no process handle is held across them. FIX-1's claim
  "a reused process number is never stopped" was too strong; the exact claim is the one above.
- The start time travels as text, not a JSON number: Windows counts it in 100 ns ticks since 1601
  (about 1.3e17, past 2^53), so a JS number would round it and every match would fail.
- Every home folder the machine names refuses a stop, and so does each of their parents: USERPROFILE,
  HOMEDRIVE+HOMEPATH and HOME are all taken (plus the pty home the terminal code already resolves),
  deduplicated, so a pane whose HOME differs from USERPROFILE is covered too. Pure function, tested with
  two different homes.
- A printed address binds only to a program under the terminal that printed it: each row names the
  terminal whose pane (shell pid) is the program or its nearest ancestor; UrlBook ties the address to a
  holder with that terminal, so terminal A printing :3000 while terminal B's server holds 3000 gives B's
  row no address, and a server nothing in Kolux started never inherits one.
- The real-process Rust test kills its node servers when the test ends, pass or fail (Drop guard).
- The stream-decoder test asserts the replacement character itself ("\uFFFD"), not a loose shape.
- ports_scan's doc no longer claims the store rule for the scan: the rule is applied at stop time
  only (it costs a git call per project), so a row inside a folder the store does not know can show a
  Stop that the backend then refuses with a message.
