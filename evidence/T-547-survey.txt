A. Claude (Anthropic)
A1. Plan usage. No public HTTP service returns a Pro/Max user's 5-hour or weekly figures. The one
    documented source is Claude Code's own status line input: Claude Code passes a status-line
    command JSON on stdin that includes rate_limits.five_hour.used_percentage / resets_at and
    rate_limits.seven_day.used_percentage / resets_at, "only for claude.ai Pro and Max subscribers
    ... and only after the first API response in the session".
    Doc: https://code.claude.com/docs/en/statusline (fields table and "rate_limits" notes).
    This is the route USAGE-021 already describes (figures from running sessions; hidden-terminal
    fallback). Host: none (local process data). Credential: none handled by Kolux.
A2. The Usage and Cost Admin API (api.anthropic.com/v1/organizations/usage_report/messages and
    /cost_report) needs an Admin API key, "is unavailable for individual accounts", and covers
    Claude Console API organizations, not claude.ai plan windows.
    Doc: https://platform.claude.com/docs/en/manage-claude/usage-cost-api
A3. Sign-in renewal. Not publicly documented. Claude Code's docs say it refreshes its own login and
    that /login renews it; no token or refresh host is published for other apps.
    Doc: https://code.claude.com/docs/en/authentication ("Renew an expiring login", "Credential
    management"). That page also documents claude setup-token (a one-year token for
    CLAUDE_CODE_OAUTH_TOKEN, "can only make model requests"), which is the ACCT-004 path and is
    unaffected.
A4. Terms. Claude Code legal page, section "Authentication and credential use": OAuth "is intended
    exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and
    is designed to support ordinary use of Claude Code and other native Anthropic applications";
    "Anthropic does not permit third-party developers to offer Claude.ai login into their own
    applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their
    users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or
    session tokens - sign-in to a Claude account must complete through Anthropic's own flow." and
    "Anthropic reserves the right to take measures to enforce these restrictions and may do so
    without prior notice." It does permit "an end user signing in to the unmodified Claude Code
    binary with their own Claude subscription".
    Doc: https://code.claude.com/docs/en/legal-and-compliance
    Risk to the user's account: HIGH. A Kolux that stores a claude.ai token and renews it, or calls an
    undocumented usage host with it, is exactly what the page names; enforcement can be without
    notice and lands on the user's subscription. Running the unmodified claude binary in a pane
    (what Kolux does today) is the permitted case.

B. Codex / ChatGPT (OpenAI)
[corrected 2026-10-14] B1-B3 below were not verified first-hand by the council review (its fetches of
these pages were refused), and B3 is second-hand by this survey's own account. Treat all three as
unsourced until the pages are read directly.
B1. Plan usage and sign-in state are documented through Codex's own app-server (codex app-server,
    JSON-RPC 2.0 over stdio, newline-delimited JSON): account/read "fetch current account info;
    optionally refresh tokens" (refreshToken boolean), account/rateLimits/read "fetch ChatGPT rate
    limits" (usage percentages, window durations, reset times), account/rateLimits/updated
    notification "emitted whenever a user's ChatGPT rate limits change", account/login/start
    (apiKey, chatgpt browser flow, and an "experimental" chatgptAuthTokens mode "intended for host
    apps that already own the user's ChatGPT auth lifecycle"), account/logout.
    Doc: https://learn.chatgpt.com/docs/app-server (redirected from
    https://developers.openai.com/codex/app-server). The page says: "The app-server command and
    WebSocket transport are experimental and aren't supported for production workloads."
    Host for Kolux: none; Kolux would start the user's installed codex as a child process and talk
    stdio; Codex makes the network calls with the login it already holds. Credential handled by
    Kolux: none (on this route Kolux never sees the token).
B2. Direct calls to the ChatGPT backend that Codex uses: not publicly documented (no host or
    endpoint is published). Codex's auth page says Codex "refreshes tokens automatically during use
    before they expire" and stores them in ~/.codex/auth.json or the OS credential store, "treat
    ~/.codex/auth.json like a password", and recommends API keys "for programmatic Codex CLI
    workflows". Doc: https://learn.chatgpt.com/docs/auth (redirected from
    https://developers.openai.com/codex/auth).
B3. Terms. OpenAI Terms of Use, "What you cannot do" (quoted via search; the page itself answered
    403 to the fetch): "You may not share your account credentials or make your account available to
    anyone else" and users may not "automatically or programmatically extract data or Output".
    Doc: https://openai.com/policies/terms-of-use/
    Risk: low when Kolux only asks the user's own Codex app-server (OpenAI's documented interface for
    host apps; the token never leaves Codex). Medium to high if Kolux read auth.json and called the
    backend itself (undocumented host, credential handled outside Codex). The chatgptAuthTokens mode
    is for hosts that own the ChatGPT sign-in, which Kolux does not; not proposed.

C. Google: Gemini CLI and Antigravity
C1. Gemini CLI quota: not publicly documented as a service. The quota page documents the user-facing
    /stats model command and a usage summary on exit, and says "Unpaid tier and Google One users:
    Gemini CLI was replaced by Antigravity CLI on June 18th, 2026."
    Doc: https://geminicli.com/docs/resources/quota-and-pricing/
    Static limits (requests per user per day by edition; only per-day limits are published, Standard
    1500 and Enterprise 2000 [corrected 2026-10-14: "per minute" dropped]) are published at
    https://developers.google.com/gemini-code-assist/resources/quotas but there is no documented
    call that returns what a user has left.
C2. Antigravity quota: not publicly documented as a service. Plans page: "You can view baseline quota
    usage across models on the Settings page"; quota refreshed every five hours (Pro/Ultra) or weekly.
    Doc: https://antigravity.google/docs/plans
C3. Terms: NOT ASSESSED in this pass. The fetch of the Gemini CLI terms and privacy page
    (https://geminicli.com/docs/resources/tos-privacy/) was refused by this session's tooling, so its
    rules on third-party software using a Gemini CLI sign-in were not read. Someone must read that
    page before any Gemini or Antigravity scope is decided.

D. Kimi (Moonshot)
D1. Kimi Open Platform balance (pay-as-you-go API credit): documented. GET
    https://api.moonshot.ai/v1/users/me/balance (a China host on api.moonshot.cn was named here, but
    the cited page does not source it [corrected 2026-10-14: unsourced]),
    Authorization: Bearer <Moonshot API key>, returns available_balance, voucher_balance,
    cash_balance. Doc: https://platform.kimi.ai/docs/api/balance
    Risk: low (a documented call with the user's own API key). Host: api.moonshot.ai.
D2. Kimi Code membership quota (a rolling 5-hour window; [corrected 2026-10-14] for new members the
    weekly limit is removed, so only the 5-hour window remains): not publicly documented as a service. The membership page says to use the Kimi Code Console or type /usage in the CLI, and
    that "Requests from the CLI, VS Code, Desktop, and third-party tools all count toward that quota".
    Doc: https://www.kimi.com/code/docs/en/kimi-code/membership.html

    pages, not in MiniMax's docs; not proposed.

Proposed scope for T-547
Build only the documented, low-risk routes. (1) Claude: no direct calls at all; Kolux keeps
renewing nothing and asking no Anthropic usage service, because Anthropic's terms forbid a third-party
app collecting, storing or intermediating claude.ai tokens and no usage or renewal service is
published; plan figures stay on USAGE-021 (the status line data the user's own Claude Code passes
out), so the ACCT-006 opt-out stays on and DT-C32 is narrowed for Claude. (2) Codex: read plan usage
and sign-in state by starting the user's own codex app-server over stdio and calling
account/rateLimits/read, account/read and the account/rateLimits/updated notification; Kolux never
reads or stores a ChatGPT token and needs no new network host; the experimental status is handled by
a version check and a quiet fallback to what running sessions report. (3) MiniMax: one call to
https://www.minimax.io/v1/token_plan/remains with the user's M Plan key (which key: see E1), stored by the app in
the OS credential store and never logged; host www.minimax.io on the capabilities allowlist.
(4) Kimi: the documented Open Platform balance (api.moonshot.ai) only for users who give a Moonshot
API key; Kimi Code membership quota stays "not available" until Moonshot documents a service.
(5) Gemini CLI and Antigravity: no calls; show the static published limits at most, until a public
service exists and the Gemini CLI terms page has been read. T-263-c shrinks to MiniMax plus the Kimi
balance; a security-auditor review of the key storage and the two allowlisted hosts before merge.
