Row 954 (b): a page that destroys its own browser tab through an escape the shim cannot stop
lane/browser-proxy, kolux-34 browser. Windows only (WebView2). Nothing here was run live (no app launches in a builder).

ROOT CAUSE
- NO_CLOSE_SCRIPT makes a tab page's own window.close() a no-op, but it is page script. A popup (exempt from the shim) can run
  window.close.call(opener); a cross-origin popup can run opener.close(); a cross-origin iframe can run top.close(); a fresh
  about:blank iframe can run f.contentWindow.close.call(top). None of these run the shim in the tab's realm.
- WebView2 then raises WindowCloseRequested on the tab. wry registers its handler first and answers with DestroyWindow(hwnd)
  (wry-0.57.0 src/webview2/mod.rs:683-685). The event has no "handled" flag and wry throws its token away, so the destroy cannot be
  vetoed from the host. It can only be observed: a handler added later still fires.
- Before this change the pane got no probe answer from the dead page: three misses, one automatic reload, then the "This page
  stopped responding" overlay on a tab that was gone.

DECISION (coordinator ruling kolux-15, option b, no wry fork): detect the destroy, rebuild the tab at its last address, say so.

WHAT WAS BUILT
- Observe: src-tauri/src/browser_engine.rs imp::watch_self_close adds a WindowCloseRequestedEventHandler on the tab's
  ICoreWebView2 (browser_engine.rs:159-168; public #[cfg(windows)] wrapper at :461), wired in browser_open right after
  watch_page_failures (browser.rs:1395). Tab views only: browser_popup.rs never calls it (test
  row954b_only_tab_views_hear_their_close_request).
- Decide: src-tauri/src/browser_selfclose.rs, pure seam on_self_close(history, now) -> Reopen | LeaveClosed. A tab already rebuilt
  twice within 10 s is LeaveClosed (a refusal is not recorded, so it does not extend the count); older rebuilds age out.
  requested() emits the event "browser-selfclosed" {id, reopen}.
- Rebuild: src/browser/BrowserPane.tsx listens for the event on its own tab id and feeds {t:"selfclosed", reopen} to the
  loadState machine (src/browser/loadState.ts). reopen=true goes to phase "loading" with the action "rebuild", which is the
  existing reopenPage path (browser_close then browser_open): same id/slot, same profile data folder, same browser_args_now(),
  same NO_CLOSE_SCRIPT, at the pane's last URL. No second tab builder was written.
- Notice: the existing .notice (role=alert) channel via setNote(selfCloseNotice(payload)) in src/browser/selfClose.ts:
  "This page closed itself; Kolux reopened it" or, on LeaveClosed, "This page keeps closing itself; Kolux left it closed".
- Left closed: new phase "closed" and overlay "This page closed itself" / "It keeps closing itself, so Kolux left it closed. Press
  Retry to open it again." Retry rebuilds (the 10 s window has usually passed by then; if not, it is simply refused again).

WHAT THE USER SEES
- A popup kills the tab: the tab blinks and comes back on the same address (a fresh load, so unsaved page state is lost), with the
  line "This page closed itself; Kolux reopened it". No "stopped responding" overlay.
- A page that does it in a loop (row 954c): the tab is left closed after 2 rebuilds inside 10 s, OR 3 inside 5 minutes (a page
  closing itself every 5.1 s therefore stops at the third). Once closed it stays closed: only Retry reopens it, and Retry also
  clears the record. The destroyed page is closed for real (browser_close), so it stops running and its popup goes.
  Other tabs and the rest of the app are unaffected.
- A rebuild keeps the tab's profile (the saved one, so cookies survive), never takes keyboard focus, and re-applies where the
  pane is NOW. If the reopen itself fails, the tab shows "This page could not be reopened" with Retry.
- A popup closing itself (sign-in flows): unchanged, it just closes (popups have no hook).

STOPPED-RESPONDING OVERLAY AND THE PROCESSFAILED DOUBLE REPORT
- The overlay: the selfclosed event moves the machine to "loading" (or "closed") before the probe-miss path can reach "crashed";
  the "closed" phase ignores late probe results. Tested in loadState.test.ts (describe "row 954b: a tab that closed itself").
- ProcessFailed (row 954c replaces the 2 s by-id window): each browser_open makes an Engine record (selfclose::register). The
  close-request handler, the probe's IsWindow fallback and browser_close mark THAT engine destroyed, and only that engine's
  failure handler ignores a later Source::Page failure (it also ignores one when its own container HWND is gone, which covers
  the order where the failure arrives before the close request). A failure in the rebuilt tab is a different engine and is
  always reported. NOT verified live: whether WebView2 raises ProcessFailed at all after DestroyWindow.
- H2 (order-independent detector): wry destroys the window in its own close-request handler, and WebView2 documents no handler
  order, so our WindowCloseRequested handler may never run. browser_probe (browser.rs:1637) calls selfclose::probe_missed when the
  tab gives no answer: IsWindow(recorded container) false means a self-close through the same on_self_close seam and event;
  true is the existing crash path. Both detectors call Engine::mark_destroyed (browser_selfclose.rs:138), which is true only
  for the first caller, so one destroy gives one decision. No new command, no lib.rs change, no FLAG patch.
- Focus: selfclose::focuses_after_open (browser_selfclose.rs:107) is the seam; a rebuild (auto or retry) never focuses, a user
  open does. The set_focus call site itself in browser_open is reachable only live (step 12).

OFF WINDOWS
- The hook and the pane-side wiring that needs it are #[cfg(windows)]; browser_selfclose.rs carries
  #![cfg_attr(not(windows), allow(dead_code))] so it still compiles clean. macOS and Linux have no such hook today: their tab is
  guarded only by NO_CLOSE_SCRIPT, so the same escapes are not caught there (the engine on those platforms is not WebView2 and
  Kolux has no equivalent close event yet). The pure seam and the frontend are platform-neutral if a hook is added later.
