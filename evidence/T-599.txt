T-599 · The crash screen never reloads while you are writing a report (F08-onboarding-look-misc.1; APP-042, PROJ-089), reliability lane, 2026-10-30

Cause: the watch in src-tauri/src/resources/recovery.rs reloads a page that sends no heartbeat for STALL (20 s). The
crash screen (ScreenBoundary) replaces App, and with it RecoveryMount, the only heartbeat sender. So about 20 s after a
crash the page reloaded, even while the user was typing in the Report box, and the typed text and the error details
were gone.

What changed:
- src/recovery/heartbeat.ts (new, 21 lines): useHeartbeat() is RecoveryMount's heartbeat effect, moved out
  unchanged (beat at once, then every HEARTBEAT_MS = 2 s, stop on unmount), plus <Heartbeat/> for a class component.
- src/recovery/RecoveryMount.tsx:16-17,29 calls useHeartbeat() instead of its own copy of the effect (no change for App).
- src/recovery/ScreenBoundary.tsx:2-15,18,21,35,42,45  the crash screen remembers that Report was opened (it passes its
  own `request` to ReportButton, which then opens the box through requestFeedback as before) and from then on renders
  <Heartbeat/>, so the watch sees the page alive until the screen is left (Try again resets it; Reload starts over).
  Before Report the screen still sends nothing, so a crash screen nobody touches is still recovered by the watch as
  T-183 designed. ponytail comment: FeedbackDialog keeps open, typed and sent to itself, so the beat also goes on after a
  sent report until the screen is left (Try again and Reload are on screen); upgrade path: the box reports its state and
  the beat stops on send.

Test added: src/recovery/ScreenBoundary.test.ts (the real ScreenBoundary, Report button and Send Feedback box on the fake
DOM under vi.useFakeTimers; `reloaded` applies the watch's rule, Interface::tick in its Live phase with STALL 20 s, to the
heartbeats sent):
  1. the crash screen alone is still recovered by the watch: no heartbeat, so it reloads after 20 s (T-183)   (guard)
  2. once Report is opened the page stays alive while the report is open or has text, so the box and the error stay
     (90 s with the box open, then 90 s after Cancel with its text kept; the crash text is still in the box)
  3. leaving the crash screen with Try again stops its heartbeat (App's own takes over)
