ux fix 5: a returning user's startup Tip no longer covers the restored workspace or takes typing focus (lane ux, 2026-10-25)

Spec: ONB-027 asks for "at most one small tip dialog at launch" for an existing user, one tip per launch in a set order, and
says nothing about blocking the workspace or taking focus. Not an every-start tip (a tip counts as seen when it appears).
So the tip stays; only its modal form changes. ONB-012/032 (first-run wizard, tours) untouched.

Root cause: StartupTip rendered the tip inside a full-window .ask-backdrop with aria-modal=true and autoFocus on its button, so
it covered the restored pane and stole typing focus. Side finding: the card used the class "tip", which the hover-tooltip rule
(.tip: pointer-events none, 280px max-width, 11px, inverted colours) also matched; the card is now "tip-card".
