lane/release-ci, 2026-10-30, Linux cloud sandbox (node 22.22.0, vite 8.3.3 build of this lane's tree)

WHAT CHANGED
- scripts/invoke-contract.mjs (new): reads lib.rs's generate_handler![...] (last path segment of each
  entry, line comments and #[cfg(...)] attributes skipped) and every invoke("name") / invoke<T>("name")
  / invoke('name') in src/**/*.ts(x) outside *.test.ts(x) and __cards__/; type arguments may nest and
  hold `=>`; plugin:... names are skipped; a name in a variable is counted, not checked (ponytail comment:
  13 such calls today; upgrade path one typed map of names). Unknown names print as `name (file:line)`,
  exit 1. Comments are deliberately not stripped: StepRows.tsx:53 has "//" inside a regex literal on the
  same line as a real call.
- scripts/bundle-budget.mjs (new): after `vite build`, the main window's first-load JavaScript is the
  entry script dist/index.html names, the chunks it preloads, and App (main.tsx starts `import("./App")`
  at once, FIX-4), each with every chunk it imports statically (`from"./x.js"`, `import"./x.js"`);
  on-demand chunks (`import("./x.js")`: diagrams, PDF, languages) and CSS do not count. CEILING =
  3,300,000 bytes: today 3,152,680 plus about 5% for this cycle's other lanes. The ponytail comment
  records the 1.5 MB target as the upgrade path (move what App draws only on demand behind import()).
  It refuses a missing build and a build without exactly one App chunk, so it cannot pass by not looking.
- .github/workflows/ci.yml:61-65: the checks job runs invoke-contract, then `pnpm exec vite build`, then
  bundle-budget. Job id, name, and the rest of the layout (4 Linux shards, Windows Rust, installer on
  dispatch/tag, result gate) unchanged.
- package.json:11: `pnpm check` (the local merge gate) also runs invoke-contract.
