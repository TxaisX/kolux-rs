T-604 · Protected rules fail closed (R03-safety-accounts.1, .2, .3; SAFE-014, SAFE-016)
Safety lane, 2026-10-30, branch lane/safety (base 025eda2).

WHAT THE USER GETS
- A stray quote can no longer switch the protected rules off. An apostrophe in a "#" comment, in a
  heredoc or PowerShell here-string body, a backslash- or backtick-escaped quote, the '\'' idiom, or a
  line continued with "\" or "`" no longer hides a force-push, a hard reset or a folder delete that
  follows it: Kolux pauses it as it would the bare command.
- The user's own "starts with" rules now see a command the way the built-in rules do: through
  NAME=value, sudo and other wrappers, npx / bunx / pnpm exec / pnpm dlx / npm exec / yarn dlx,
  folders and .exe/.cmd, PowerShell's "& prog", a lone "&", bash -c "..." and (cd d && ...).
  "npm publish" still matches npm publish as written.
- A paused 1 MB command is answered within the hook's time (it never finished before), so a long
  command can no longer outlast the hook's 1.5 s and run without the ask.

  readings are worked out once per command for all seven rules (`check`, line 49).

- 497-539  `substitutions`: in the Shell reading a "'" inside double quotes is text (it used to hide

LIMITS (ponytail notes in the code)
- mask() itself is still superlinear on a long run of -p/-u flags when the text names mysql, curl
  or sshpass, and on long runs of pipes; nothing in the app masks unbounded text any more (the
  attempt is masked from its first 4,048 characters), so the hook's cost no longer grows with the
  command. Masking the head can miss a secret only when what decides it lies more than 2,048
  characters after it (a pipe into sudo -S that far on, an -AsPlainText that far on); a JSON value
  cut by the head is hidden to the end.
- The Blind reading can ask for an odd command whose quotes never close and that holds a dangerous
  command inside its quoted text (fails closed, never the other way).
- A starts-with rule still means "the program and its first words": kubectl --context prod delete
  does not match "kubectl delete" (options before the subcommand are not guessed).

Each test lists every case it misses, so the BEFORE output names each bypass. The BEFORE runs are the
lane at 76201ceb with only the new tests added; the AFTER runs are the final code (merged with origin/main

What changed (protected.rs, Shell reading and rules; protected_custom.rs):
- A backslash + LF or CRLF joins the next line with nothing between (`git reset --ha\<LF>rd` is --hard);
  PowerShell's backtick join still leaves a space.
- Outside quotes a backslash before an ordinary character is dropped (`g\it`, `--forc\e`). It stays before a
  quote, a shell mark (; & | ( ) < > $ # \ ` space) or a wildcard (* ? [ ~), and every backslash of a word read
  as a Windows path stays (a `:` or `%` earlier in the word, or a word starting `.\`, `..\`, `~\`), so
  `C:\Users\..\Temp\x`, `dist\*.o` and `.\build\out` read as before. (A first version dropped those too; the
  full cargo test caught it in safe013_home_or_an_ancestor_of_home_under_temp_is_never_a_temp_delete, and t604r2
  now also checks that relative Windows-path deletes still run.)
- `$'..'` (ANSI-C quote) honours `\'`.
- `git -c alias.X=..` then running X reads the alias (`!` alias: its shell command) as the command.
- Shortened long options: git push (--del, --force-w, --mirr, any prefix of force/force-with-lease/
  force-if-includes/mirror/delete), git reset (--ha), git clean (--forc), rm (--recu).
- Any rm short-option bundle of r f v d i holding r (`-rrrrf`), with no length cap.
- `env -S` / `-S<value>` / `--split-string[=]` read as a command, with the words after it.
- `$IFS` and `${IFS}` split words.
- protected_custom.rs: a paused command is masked before the attempts lock is taken (Attempt::masked, then
  Attempts::keep under the lock); the Safety page's list is copied under the lock and masked after. This closes
  status-hooks STATE follow-up (4). In this lane the mask already read only the first 4 KB (mask_head), so the
  lock was held about 8 ms rather than the 2 s seen on main's code; now about 8 to 22 microseconds.

RE-REVIEW OF PR #15 at 4e22f05d (2026-10-30, integrator): every word read both ways
The Windows-path rule of the first review fix (keep a word's backslashes after a `:` or `%`, or after `.\`)
is gone. In its place a fourth reading, `Bash`, reads the text with a backslash before an ordinary
character dropped by bash's rules; `Shell` keeps every backslash. Every rule runs on every reading and
asks when any reading trips it. The delete rule: on a non-Windows base both readings are judged in full,
so a delete runs only when each reading of it is safe (temp or inside the workspace). On a Windows base
(a drive letter in the workspace, folder, home or temp) a backslash is a folder separator: `Bash` is paired
word for word with `Shell`, the program, its wrappers and its options from `Bash` (`r\m -\rf ~` asks) and
every other word from `Shell` (`rd /s /q C:\...\Temp\other` still runs); chains that do not line up are judged
in full. There is no per-word state in shell_text any more, so a backtick or `$(` needs no new-word rule.
The `Bash` reading is built only when the text has a backslash or names powershell/pwsh (an encoded command
may decode to one); otherwise it would equal `Shell`.
