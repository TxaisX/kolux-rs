T-604 · Protected rules fail closed (R03-safety-accounts.1, .2, .3; SAFE-014, SAFE-016)
Safety lane, 2026-10-30, branch lane/safety (base 025eda2).

WHAT THE USER GETS
- A stray quote can no longer switch the protected rules off. An apostrophe in a "#" comment, in a
  heredoc or PowerShell here-string body, a backslash- or backtick-escaped quote, the '\'' idiom, or a
  line continued with "\" or "`" no longer hides a force-push, a hard reset or a folder delete that
  follows it: Kolux pauses it as it would the bare command.
- The user's own "starts with" rules now see a command the way the built-in rules do: through
  NAME=value, sudo and other wrappers, npx / bunx / pnpm exec / pnpm dlx / npm exec / yarn dlx,
  folders and .exe/.cmd, PowerShell's "& prog", a lone "&", bash -c "..." and (cd d && ...).
  "npm publish" still matches npm publish as written.
- A paused 1 MB command is answered within the hook's time (it never finished before), so a long
  command can no longer outlast the hook's 1.5 s and run without the ask.

WHAT CHANGED (file:line at the commit)
src-tauri/src/protected.rs
- 286-339  `Reading` (Plain / Shell / Blind), `Seg`, `Read` and `chains`: a command is read as
  written (the old SAFE-014 reading, unchanged), as a shell reads it, and, when either of those ended
  inside a quote that never closed, with quotes ignored. A rule asks when any reading trips it. The
  readings are worked out once per command for all seven rules (`check`, line 49).
- 341-370  `collect` takes the reading; 376-495 `shell_text`, `plain`, `copy_body`: the Shell
  reading drops "#" comments that begin a word outside quotes and PowerShell "<# #>" blocks, joins
  lines ended by "\" or "`", turns quotes escaped by "\" (outside single quotes) or "`", and every
  quote of a heredoc or here-string body and its closing mark, into "_". Bodies stay in place and are
  still read line by line (a heredoc may feed a shell).
- 497-539  `substitutions`: in the Shell reading a "'" inside double quotes is text (it used to hide
  a later $( )); in the Blind reading nothing hides a substitution.
- 541-563  `split`: reports a quote that never closed; the Blind reading splits everywhere.
- 594-626  `program_at` replaces `unwrap`: counts instead of removing from the front (a 1 MB run of
  "A=1 " or "sudo " was quadratic) and reports every step for the user's rules.
- 634-645  `starts_with` (pub(crate)): the user's starts-with rules, every reading, every step.
- 88-95    `recursive_delete` walks each reading's chain on its own (a cd shifts only its own chain).
- 929-951  `mask` unchanged in its answers; new `mask_head(text, n)` masks only the first n
  characters; where that cut falls inside a JSON secret value the value is hidden to the end
  (`json_values(t, cut)`, 2132).
- 1587-1597 `secret_flags`: reads the words before a flag at most once per flag, and only when a
  program that flag belongs to (curl, sshpass, mysql/mariadb/7z/rar) is named in the text at all.
  Proven exact: the two recorded-digest tests over generated inputs still match (see below).
- 2370-2374 test fix: the Windows-only letter-case assertion in
  safe013_recursive_deletes_outside_unknown_or_piped_ask_inside_and_temp_run now runs on Windows only,
  as the neighbouring test already did ("Letter case is ignored on Windows only."). It failed on Linux
  at the base commit (55 pass, 1 fail before this lane; 61 pass now).
src-tauri/src/protected_custom.rs
- 24       MASK_MARGIN = 2048: masking reads the 2,000 shown characters and 2,048 after them.
- 59       a starts-with rule calls protected::starts_with; the old local splitter is deleted.
- 369      `paused` masks with mask_head(raw, COMMAND_SHOWN + MASK_MARGIN) instead of the whole command.

LIMITS (ponytail notes in the code)
- mask() itself is still superlinear on a long run of -p/-u flags when the text names mysql, curl
  or sshpass, and on long runs of pipes; nothing in the app masks unbounded text any more (the
  attempt is masked from its first 4,048 characters), so the hook's cost no longer grows with the
  command. Masking the head can miss a secret only when what decides it lies more than 2,048
  characters after it (a pipe into sudo -S that far on, an -AsPlainText that far on); a JSON value
  cut by the head is hidden to the end.
- The Blind reading can ask for an odd command whose quotes never close and that holds a dangerous
  command inside its quoted text (fails closed, never the other way).
- A starts-with rule still means "the program and its first words": kubectl --context prod delete
  does not match "kubectl delete" (options before the subcommand are not guessed).
