- kolux automations create / edit take --reuse-session (each run continues in the session the last run left open, existing worktree only)
  and --fresh-session (the reverse); both at once, or a reuse with a new worktree for every run, is refused before the app is asked.
  list / show print "keeps one session across runs".
- An automation saved under another host's name (this Kolux has none) shows in list / show as orphaned with why and the commands that
  get out of it (show, remove, create again); edit and run are refused with code owned_elsewhere (owner, action, steps, hint in the error
  data); a timed run of it is logged skipped (cause unavailable) naming the host; remove works. An edit carries the owner it read: if the
  automation changed hands before the save, owner_conflict explains it and nothing is saved; if it was removed meanwhile, not_found says
  so with no steps to retry.
- Next-step commands put quotes around values with spaces the way the shell expects (double quotes on Windows, single quotes elsewhere;
  plain selectors stay bare; a value a shell would act on even in quotes leaves that step out).
