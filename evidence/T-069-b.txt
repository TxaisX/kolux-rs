T-069-b (VIEW-107, reshaped by council C2): a slow start never drops the saved tabs
Built 2026-10-13 on lane look, dev app on port 1426, scratch profile (CLAUDE_CONFIG_DIR and
CODEX_HOME under the batch scratch folder), lane identifier com.txaisxiong.kolux-rs.look.

What changed
- main.tsx tells App whether get_settings answered inside the 1500 ms start window (read=false
  when the race timed out and the window started from the empty fallback).
- App.tsx, the PROJ-067 layout effect: while read=false and no later settings read has landed,
  a change to the panes writes no savedLayout. Before, the fallback shell shown during the stall
  was written over the saved tabs.
- settings/general.ts saveLayout: a failed layout write is tried once more after 300 ms; if that
  fails too, only the durable part is written (the tabs and the workspace in front; focus,
  active tab per cell and stacked cells are dropped).

Setup
- seed: 6 shell tabs "Saved tab 1" .. "Saved tab 6" written into the lane profile's savedLayout.
- stall: CDP Page.addScriptToEvaluateOnNewDocument wraps window.fetch so every IPC call to
  /get_settings is held back 3000 ms (past the 1500 ms start window), then Page.reload.

Run 1, without the fix (App.tsx and main.tsx stashed), same stall:
  window after stalled start: 1 fallback shell (stalls counted: 14)
  savedLayout afterwards: saved tabs: 1 [1] activeDir=null      <- the 6 saved tabs were lost

Run 2, with the fix, same stall:
  window after stalled start: 1 fallback shell (stalls counted: 5)
  savedLayout afterwards: saved tabs: 6 (Saved tab 1 .. 6)       <- nothing overwritten
Then the app was killed and started normally (no stall), pid 41556:
  the window shows all 6 tabs "Saved tab 1" .. "Saved tab 6"     <- acceptance met
  screenshot: evidence/T-069-b.png (1920 wide, dark)

Run 3, retry path live: the first settings_patch fetch was made to fail, then Ctrl+T opened a tab:
  failed writes: 1; savedLayout afterwards: 7 tabs, activeTab {"1":7}, focused 7
  (the retry landed; Tauri's own postMessage fallback carried it)
Durable-only fallback: unit test "VIEW-107: a failed layout save is retried once, then only the
durable part is saved" in src/settings/general.test.ts (saved / retried / durable / rejects after
3 calls).

Not here: rebuilding restored workspaces in session order in one pass (T-069-c, after the trial).
