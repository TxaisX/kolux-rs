T-159 · BROW-040 Document previews are fenced to their folder
lane/browser from 99763733, 2026-10-20 (routing v3: build first, live proofs batched)

What changed
- src-tauri/src/browser_preview.rs: Preview gains files (the documents opened from the folder)
  and granted. fenced(root, rest) is the one path check before the join: NUL, a parent step in
  either slash (on the decoded rest, so %2e%2e and %5c are caught), a root (`\x`), a drive or
  `\\?\` prefix, any colon; respond() then canonicalizes the file and the folder and serves only
  when the real file lies under the real folder, so a symlink or junction inside the folder leads
  nowhere (403, the body says why). Until the folder is allowed only the opened documents are read
  (403 with "Allow folder" named); grant(url) / browser_preview_grant allow the folder for the run.
  A file past FILE_MAX (32 MiB) answers 413 with its size. of() refuses escapes too and reports
  granted. The tab side: Page {id, token, rendered, offered, noticed} per preview tab, set by
  loading() at a load's start (a non-preview address frees the tab), rendered() at its end;
  verdict() (pure): a preview tab follows its own files, about:blank and what the app asked for
  (expect(): the bar, the command line's goto, Back/Forward, for 5 s or until the load starts), the
  first outside address is offered (Verdict::Offer, once per page), later ones dropped;
  download_refused(id) says whether a refusal gets its notice (one per 2 s burst, notice_due);
  drivable(id) refuses agent commands until the preview has rendered; forget(id) on close.
- src-tauri/src/browser.rs: OUTBOUND_EVENT "browser-outbound" (LinkPayload). on_new_window: a
  preview tab's popups and script windows are denied, an outside address offered once; on_navigation
  Nav::Load goes through preview::navigating (Offer emits, Drop loads nothing); on_page_load
  started -> preview::loading, finished -> preview::rendered; on_download refuses a preview tab's
  downloads (a failed row "a document preview may not download", one per burst); browser_navigate,
  step_history and Act::Navigate call preview::expect; drive() checks preview::drivable;
  browser_close forgets.
- src/browser/BrowserPane.tsx: Preview.granted; the chip's "Allow folder" button
  (browser_preview_grant, then reload); the browser-outbound listener and the offer bar
  ("This preview wants to open <full address>" with Open and Cancel; Open goes through
  navigateTo, so the bar's own navigation is expected and not fenced again; a new load clears it).
- src/browser/browser.css: .notice.preview-ask rules (the address wraps, stays selectable).
- evidence/browser-T-159-lib.rs.patch (new): registers browser::preview::browser_preview_grant
  after browser::browser_open (context keybindings_reload/show, open | bounds/navigate/go), so it
  applies before or after browser-T-242-lib.rs and browser-T-238-b-lib.rs.
- Left open (no public API in tauri 2.12 / wry 0.57; after-list): permission requests from a
  preview (camera, location, notifications) are not denied by the app; an embedded frame pointing
  at an outside host is not blocked (the server itself serves only inside the folder; main-frame
  navigations are the only ones the handler sees); a genuine click is not told from a script's
  navigation, so the offer is once per page load instead.
