== What is built (src-tauri/src/pty_service.rs, declared from pty.rs as pty::service) ==
- One copy per user and app identifier: named mutex Local\<identifier>.terminals (reuses lifecycle::claim_named, the app's own APP-001 lock); a lane or trial build never blocks the installed one; a second copy exits 3 (lifecycle::DUPLICATE_EXIT).
- Local IPC only, the local CLI's way (DT-C22): TCP on 127.0.0.1, random port, a per-start random token (cli::secret) in terminals.json in the user's own data folder, written to a temp name then renamed, removed at exit only when it still names this process. Every connection must open with a hello carrying the token; anything else gets {"ok":false} and nothing more.
- Wire: one JSON object per line. Requests list / spawn (program+args or the user's shell, cwd, cols, rows, env) / write (base64; carries the generation; a replaced run's typing is refused, APP-052) / resize / kill. A connection that sends attach is a window: its answer lists every running terminal with its recent output (the ORCH-057 tail, terminal::Snap, now pub(crate)), then output and exit events follow in order (all lines go through one writer thread per connection, registration and tail under one lock, so no event older than the tail is sent after it). detach or a closed connection ends the attachment; terminals go on.
- Writes to a terminal happen outside the service lock, so a program that is not reading never holds up output.
- Idle exit: no terminal and no attached window for IDLE_LIMIT = 10 minutes ends the service (coordinator default; Txais may overrule; after-list row). Idle::tick takes the clock as an argument.
- Client side: Client (hello, request, read events), probe (None / Ready / Refused), before_open (CLI-011), ensure (start-or-attach for the window, launch injectable, waits up to a limit), launch_detached (DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP, with CREATE_BREAKAWAY_FROM_JOB when allowed, so it outlives the window).
- Pairing: a service older than OLDEST_PROTOCOL is refused with a clear reason ("... from an older Kolux ... Kolux cannot safely open its window on those terminals ..."); a newer one is kept (additions only). A service that answers but refuses the token is also refused, never started over.
