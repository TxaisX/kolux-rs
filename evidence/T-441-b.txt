T-441-b  settings: a failed read is never saved over; the backup from before a wipe is kept
Date: 2026-10-13, lane reliability (text proof; no visible UI)

Bug (council day-one): patch_settings laid the change over settings(), which returns {} when the
read fails. save_settings re-read the file before writing, so a read that failed once and worked on
the retry (a file briefly locked by a scanner, say) saved {} plus the change over the real file.
The same read-then-save shape is in lib.rs write_settings and about 20 other writers. Also,
settings.json.bak was replaced on every save, so after a wipe the good copy lasted one more save.

Fix (src-tauri/src/state.rs, the one place every writer goes through):
- Store keeps read_failed: set by every read that fell back to defaults, cleared by a read that
  works. save_settings refuses while it is set, so no writer can save what a failed read gave it.
- patch_settings uses try_settings()? and fails loudly with the read error.
- save_settings reads the file once, checks it, and writes those exact bytes to settings.json.bak
  (synced), except that an empty set never replaces an existing backup.
