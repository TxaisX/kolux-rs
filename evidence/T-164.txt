## Seen, not fixed
- xterm 6 (the installed version) ignores a wheel event's size and moves about three rows a notch; the evidence helper's
  "wheel <selector> <deltaY>" therefore scrolls three rows per call whatever deltaY is passed.
- A chunked paste into a program in bracketed-paste mode arrives as one bracketed paste per 64 KiB chunk (term.paste wraps
  each call); readline-style programs insert each as text, so nothing runs early, but a program that acts on the end of a
  bracket sees several. Only pastes over 64 KiB are affected.
- ConPTY's input path handles about 12 KB/s here; a multi-megabyte paste takes minutes to reach the program whatever the app does.
