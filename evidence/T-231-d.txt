Split in place: the multi-repository picker and starting or resuming a workspace from an issue or PR
(with the `kolux worktree create|set --issue` CLI) move to the new PLAN line T-231-e.

What the user can do: Tasks > New issue opens a dialog that targets the repository the issue list
shows (the fork's parent when Issues from = upstream) or the fork itself, with title, Markdown
description, labels and assignees (suggested from this repository's labels and people). The draft is
saved as it is typed (settings key tasksIssueDraft) and comes back when the dialog is closed and
opened again; changing repository clears the labels and assignees; a draft whose repository is no
longer offered moves to the first one. A draft over 20 000 characters is not written to settings but
is held in memory for the run (the dialog says so) and the issue can still be created. On success the
draft is cleared, the new issue goes to the top of the list and its dialog opens.

Rust (src-tauri/src/github.rs): create_issue() / #[tauri::command] github_issue_create. One REST call,
`gh api -X POST repos/<owner>/<name>/issues --hostname <host> --input -`, with title, body, labels and
assignees as JSON on stdin (never on the command line). Refused before gh runs: an empty title, a
description over 65 536 characters, an assignee that is not a GitHub login, an empty label name, a bad
owner/name or host; the FIX-1 host gate (host_allowed) runs before the call. An answer without an issue
number says "refresh the list to see whether it is there". A gh timeout on create says the issue may
have been opened (issueActions.ts actionError "create").
