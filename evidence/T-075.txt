== Slice b · APP-050 ==
What was missing and is now built: the quit path (lib.rs RunEvent::Exit) ran the five save steps one after another with no overall
   bound except ACCT-025's per-step limit on the seals, and a batched activity save could still start a write during the quit.
1. src-tauri/src/final_save.rs (new core module; `pub mod final_save;` is the one lib.rs registration line committed directly):
   begin() = the quit barrier (first caller wins; quitting() true from then on), QUIT_DEADLINE = 5 s, run(deadline, steps) runs the
   steps in order, each on its own thread through secrets::within (reused, ACCT-025), waiting for each only as long as the deadline
   leaves; a step that panics is "failed", one still running when the deadline is spent is "timed out", steps that come after the
   deadline is spent are started but not waited for. Report::line() -> "final save: N finished in M ms; failed: ..; timed out: ..;
   not waited for: .." goes to diag.
2. lib.rs PATCH (evidence/core-T-075-lib.rs.patch, regenerated, now 3 hunks): RunEvent::Exit calls final_save::begin() then
   final_save::run(QUIT_DEADLINE, [activity counts, agent status, sign-ins cancelled, codex sign-in sealed, claude sign-in sealed]),
   writes the report line through diag::write, then kill_all() as before; the batched activity saver thread skips its save once
   quitting() is true (so no new write is queued behind the final one).
