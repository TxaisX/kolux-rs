== What is built ==
- src-tauri/src/pty_link.rs (new, pty::link): the window's side of pty::service.
  - Link: one attached connection per window; a reader thread hands each terminal's output and exit to the handlers the window registered for it, in the service's order. Events for a terminal not registered yet (output while its start is still answering, or between the attach answer and the adoption) are held (256 KB cap, oldest dropped) and handed over first. The connection closing ends every terminal it carried, as unverifiable (exit None). detach() at quit drops the handlers unrun.
  - Remote: one control connection per terminal (30 s wait, reopened after a failure), so a program that is not reading holds up only its own pane. Typing goes as the service's write op with the link's generation (APP-052); resize; kill (closing a pane ends its tree in the service, the exit event follows).
  - A start sends the commands the window built (argv, folder, the whole environment incl. KOLUX_TERMINAL_HANDLE / KOLUX_PANE_KEY / PATH / hooks variables, fallback shells in order) plus a meta record (handle, pane, secret, program, folder) the service keeps with the terminal.
  - Pure rules: wanted (installed build, or KOLUX_TERMINAL_SERVICE=1; =0 turns it off), adopted_id (keep the old handle unless taken), missed (what the pane's saved output lacks: the newest seq-seen bytes of the service tail; nothing without a clean-quit record), the terminals-seen.json record (service run + per-terminal output count the window drew).
- src-tauri/src/pty_service.rs: spawn takes the built commands (`commands`) and keeps `meta`, returned in list/attach rows; Client::set_wait (the event connection waits forever); the service process clears "ignore Ctrl+C" before its first shell (TERM-115; it is started in its own process group).
- src-tauri/src/terminal.rs:
  - Session = Local(PtySession) | Remote(link::Remote); every registry use goes through it.
  - spawn: when linked, the start goes to the service (a refused start runs in the window instead); the output/exit bodies are one helper (handlers) shared with the adoption; a remote pane never blocks the shared reader (ACCT-054 flow waits only for a pane's own reader).
  - use_service (called once from setup, patch below): on a thread, pty::service::ensure (starting current_exe --terminal-service <identifier> <data folder> detached when none answers), Link::connect, then generation() answers for the service's run and the service's terminals are adopted: each keeps its handle, pane, secret, folder and program mark; its Snap is seeded with the service's count and tail; its pane's history file (TERM-106) gets what was printed while no window was open. A failure leaves panes in the window and writes one diag line.
  - terminal_service_info / terminal_attach wait (up to 10 s) while the link starts, so the pane's reattach (src/terminal/reattach.ts, unchanged) gets "attached" for its kept terminal.
  - kill_all (quit, update, window destroyed): ends the window's own sessions, leaves the service's running, detaches, writes terminals-seen.json.

== LIVE PROOF PENDING (batched) ==
On an installed (release) build with patches 1-6:
1. Open two shell panes and one agent pane; type `echo before` in a shell.
2. Quit Kolux. Task Manager: one kolux-rs.exe --terminal-service process remains with the shells under it.
3. In a shell's process (before quitting) start `ping -t localhost`; after quitting wait 10 s.
4. Reopen Kolux: each pane shows its old output plus the ping lines printed while closed, accepts typing at once, Ctrl+C stops the ping.
5. Close one pane: its shell process is gone from Task Manager. Close all panes and wait 10 minutes: the service exits by itself.
