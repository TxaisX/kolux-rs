What is built (src-tauri/src/orchestration/pointer.rs)
- line(count, run): "<n> orchestration message(s) are waiting for you [in <run>]; read them with:
  <cli> orchestration check [--run <run>]". The Run is named only when every waiting message is mail
  to the Run the pane is tied to; mail straight to a pane's own handle (and mixed mail) gets the plain
  check with no Run.
- Pointers::arrive / checked / rebind / decide / typed: one pending line per pane.
  - idle is the pane's hook state (done, interrupted, idle); working, permission, waiting and blocked
    hold the line; with no hook state reported, 3 s without output counts as idle.
  - a waiting check seen in the last 2 s (it polls every 0.5 s) takes the mail: nothing typed.
  - a check by the pane on its own mail drops a line not yet typed; repeat notices are not re-queued.
  - mail for a Run the pane has left (bindings resynced after every mail command) is dropped.
  - a dead pane is dropped, never written to.
  - a second arrival while a line is being typed never types a second line; after a line went in,
    new mail waits up to 15 s for the hooks to say the agent woke (working) before another line.
  - Cursor panes get the line without Enter.
  - chat hand-back / detached chat session hold the line (fields exist; no chat view takes a pane
    over yet, so the app passes false: after-list row).
- readers(mail, to, dispatches, from): term:<h> -> h; dispatch:<id> -> its live worker terminal
  (none once finished or from an earlier app run); run:<id> -> every pane tied to that Run; the
  sender is left out. Only agent panes (peer list) get a pointer.
- pump: one runner thread per pane polls every second and types through orchestration::sendonce
  (lands once, Enter after the size-scaled pause, Enter held when another writer takes the pane,
  nothing pasted over a permission prompt).
- cli.rs side (shared file): evidence/orchestration-T-030-b-cli.patch (SEND -> after_send, CHECK ->
  after_check with --wait, every mail command -> rebind). Until it is applied, pointer.rs carries
  #[allow(dead_code)] on `pub mod pointer;` in orchestration.rs; the resolver drops that allow with it.
