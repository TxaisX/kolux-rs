What the user gets
- A pull request link whose owner part starts with @ (a hand link, or one an untrusted origin
  hands back through the PR poll) can no longer make gh read a file such as an SSH key and send
  it to another host: owner and name go to gh as raw strings, and such a link is refused outright.
- Kolux asks gh about a pull request (merge box state, merge actions, a hand-linked PR) only on a
  host gh is signed in to; any other host gets no request at all, and the reason says to run
  gh auth login for it.
Changes (src-tauri/src/scm.rs only)
- merge_info: -f owner= / -f name=; -F stays only on the digit-checked number. No other -F on a gh
  call in scm.rs (the one other -F is git commit -F - reading stdin); github.rs uses -f only.
- pr_url_in: plain host (no user, password, port), owner 1-39 of [A-Za-z0-9-] starting
  alphanumeric, name 1-100 of [A-Za-z0-9._-] not starting with a dot, so no @, no dot start, no /
  or \. pr_parts (merge_info, merge_act) and the printed-link scanner use it; pr_link now also
  needs it.
- signed_host(gh, host): scm-local host gate (gh_account on that host, from gh's own config, no
  network); called by merge_info, merge_act, pr_link. crate::github::host_allowed (tasks FIX-1) is
  not in this tree, so this stands in for it; switch over when it lands.
