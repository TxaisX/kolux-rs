T-590 · Kolux cannot be framed by a web page: content policy part (L1-tauri.1, R07-browser.1)
lane/release-ci, 2026-10-30, Linux cloud sandbox

WHAT WAS WRONG
Kolux's content policy had no frame-ancestors rule, so a web page in a browser tab (a repository's own
localhost dev server, or any site) could load http://tauri.localhost/ in an invisible frame. On Windows
that frame gets the app's command bridge (the audit's chain: wry adds init scripts to subframes, the
framed page's origin reads as the app itself).

WHAT CHANGED
- src-tauri/tauri.conf.json:28  the release policy gains `frame-ancestors 'none'`.
- vite.config.ts:9  the dev server's policy gains the same rule (the T-500 test already demands that the
  dev policy keep every release rule); comment at :8-9 says why it must be a header.
- Checked in the tauri 2.12.1 source (this sandbox's cargo registry): protocol/tauri.rs:182-183 sends the
  policy as a Content-Security-Policy response header for HTML assets (manager/mod.rs:422-438), and the
  policy string is parsed into a generic directive map (tauri-utils config.rs Csp), so the new directive
  passes through. frame-ancestors is ignored in a <meta> policy; here it travels as a header both ways.
- Kolux's own frames are unaffected: the diagram frames are sandboxed srcdoc documents and the artifact
  viewer is served by its own kolux-artifact protocol with its own policy; neither loads index.html.
