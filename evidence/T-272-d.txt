T-272-d: keyboard-chord provenance guard (a page in one split cannot send the address-bar chord
while the user types in another split's page). Guard built with tests; the live part stays open.
lane/browser from 383ce906 · 2026-10-20 · Opus 5.5

Why not the engine's key event: the WebView2 AcceleratorKeyPressed route needs webview2-com as a
direct dependency (Cargo.toml, outside the lane; no new dependencies this pass).

What was built instead (no new dependency; windows-sys and tauri's PlatformWebview are already in)
- src-tauri/src/browser_holder.rs (new): each tab's container window is recorded when its page is
  created (tauri's with_webview -> the controller's ParentWindow). When a keyboard chord (the
  address-bar chord, back, reload, find, zoom) or an app shortcut arrives from a page, the system is
  asked which window holds the keyboard (GetGUIThreadInfo on the foreground thread, then IsChild
  against each container). If ANOTHER page's container holds it, the chord was sent by this page's
  script and is dropped. If this page holds it, or the system cannot say (no container matches,
  the read fails, not Windows), nothing changes and the earlier checks decide (document focus,
  window focus, once a second per tab): it fails open, so a wrong reading never eats a real key.
- src-tauri/src/browser.rs: the module, the record after the page is created, forget on close,
  and the guard arm ahead of the chord and shortcut arms of the navigation handler.
- Right-click menus are not guarded (a right-click may not move the keyboard into the page).

==== 2026-10-20 (lane/browser from fea63414 · Opus 5.5): the engine key-event route ====
webview2-com is now a direct dependency (coordinator decision; evidence/browser-T-158-b-Cargo.toml.patch),
so the route the card asks for is built: a chord counts only when a real key was pressed in that very page.

What was built
- src-tauri/src/browser_engine.rs: each page's engine hook adds a handler to the controller's
  AcceleratorKeyPressed event. It reads the event's key kind and virtual key and records every key
  going down (plain or with Alt) for that page; it never sets Handled, so the page still gets the
  key. When the hook is in place the page is "watched".
- src-tauri/src/browser_holder.rs: the pure logic. A browser chord needs a key: the address-bar
  chord L, find F, reload R, zoom reset 0 / numpad 0 (keyboard only); back Left/[, forward Right/],
  zoom in =/numpad +, zoom out -/numpad - (these also come from the mouse's side buttons or
  Ctrl+wheel, which leave no key). An app shortcut needs the key of its key code or typed key
  (either, so a remapped layout matches), or any real key when neither maps. A real press counts
  for one second and backs one chord (used up). Verdict per chord from a watched page: a match =
  kept (the system-focus reading is not asked); no match = dropped, except a mouse-able chord with
  no key, which is left to the earlier checks. An unwatched page (hook failed, closed tab) is left
  to the system-focus reading and the earlier checks, as before.
- src-tauri/src/browser.rs: the navigation handler's guard arms pass each chord's need.
