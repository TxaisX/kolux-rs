ports-stop (lane5/ports-stop from origin/main 3af39cf3, 2026-11-01): the Stop safety guards of PR #42 (lane/ports), ported
onto main's Ports code. PR #42 branched 2026-10-19, had no common ancestor with main and its ports.rs was never wired into
lib.rs there (its tests never ran in CI); it is replaced by this unit. Route A of the brief: main's scan stays as it is
(netstat -ano, pane-ancestry tie, own rows first then at most 12 external, 10 s cadence with the popover closed, no per-scan
memory reads of other processes, non-Windows shows no ports and no error). Only what a Stop may end changed. No app launched
here (Linux container): on-screen behaviour is LIVE PROOF PENDING at the end. Logs in the session scratchpad
(ports-stop-logs/red.log, red-vitest.log, green-ports.log, green-vitest.log, tsc.log, win-check.log, win-clippy.log).

What the user can do now: a Stop in the Ports popover ends only the program the row showed. A process id that now belongs
to another program is refused ("process N now belongs to another program; nothing was stopped"): the start time travels
with the row, is read again in a fresh scan and once more right before the kill, and all three must agree. A port also
held by a program outside the workspace, by Kolux itself or by a system process is refused as a whole (every holder is
checked before anything is ended). A stop is licensed only by a workspace folder at least two folders deep, no home
folder (USERPROFILE, HOMEDRIVE+HOMEPATH, HOME, the terminals' home) and no parent of one, with a .git on disk, that the
project store lists or Git lists for the project whose folder holds it. After the kill Kolux waits up to 2 s for the
program to be gone and reports one still running. A port already gone, or now held by a program the user never saw,
counts as success and ends nothing. A printed address labels a port only when the terminal that printed it started the
holder (terminal A's "http://localhost:3000" never labels terminal B's server). The kept rule stays: only a program
started from a Kolux pane in the workspace gets a Stop at all (external rows have none).

Changes
- src-tauri/src/ports.rs: PortRow gains `started` (the holder's start time as text; empty for an external row and where the
  system keeps none) and `terminal` (the Kolux terminal whose shell started the holder; None for an external row).
  rows_for takes sessions as (id, shell pid, folder) and a start-time reader, asked once per own holder, never for an
  external one. New pure guards: stop_target (gone / every holder own / no Kolux or system pid / same start time),
  same_start (strict on Windows: a withheld start time never confirms a pid), depth, folder_check (depth >= 2, no home
  or parent of one, has .git, known), known_workspace (store first; Git only for the one project whose folder holds the
  path), homes_from. start_time(pid) on Windows: OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION) + GetProcessTimes, no
  memory read, no new Cargo feature. ports_stop takes `started`, reads the store before the blocking part, runs the scan,
  stop_target, folder_check (Git last), the third start-time reading, kill_tree, then wait_gone(2 s). ports_list unchanged
  in contract (rows carry the two new fields).
- src-tauri/src/labels.rs: the PROJ-088 test row literal gains the two fields (no behaviour change).
- src/ports/ports.ts: PortRow with started/terminal; PrintedUrls keyed by terminal and port, forPort answers only for a
  holder under the printing terminal; stopArgs builds what a Stop sends (started as a string).
- src/ports/PortsItem.tsx: records each output chunk under its terminal id; Stop sends stopArgs. Cadence untouched.
- src/look/cardPorts.test.ts: the row helper gains the two fields. cardPorts.ts itself is unchanged.
- DECISIONS.md DT-C64, docs/guide/terminals.md "Ports in the status bar", settings.md status bar items list,
