# T-049-c evidence: Classic chrome, a sidebar-width title header in place of the full-width top bar (lane/chrome 2026-10-19, Routing v3)

No app launch (builder rule). Cards: VIEW-003 (classic chrome keeps a sidebar-width title header and no top bar),
SET-037 (the Classic / New look), VIEW-004 (Classic keeps the sidebar everywhere).

## What was built (chrome files only)
- src/chrome/titleHeader.ts: chromeLayout(classic, sidebarOpen, sidebarWidth) maps the look to the bar. Classic: the
  title header (class titlebar), no top bar, no screen switcher, left cell width = sidebar width + 8 px gap (never under
  168 px; a hidden sidebar leaves 168). New look: the top bar (class topbar), unchanged.
- src/chrome/TopBar.tsx: takes sidebarWidth, asks chromeLayout, wears the class it names, sets the left cell's inline width
  in Classic only, and draws the switcher only when the layout says so. The New look markup is byte for byte as before
  (shell.test.ts still passes unchanged).
- The look itself is the existing General > Look choice (readLook, uiLook), already saved through the settings path.
- Decision (default taken, no Txais call needed): the window has no OS title bar, so the search hint, bell, usage pill
  and the window's minimize / maximize / close stay at the far end of the same 36 px row; nothing overlays the workspace.

## Unit tests (src/chrome/titleHeader.test.ts, 6 tests)
- the look maps to the bar (Classic: titlebar, no top bar, no switcher; New: topbar, switcher);
- header width = sidebar width + gap at LEFT_MIN, default, 333 and LEFT_MAX; minimum when too narrow, hidden or NaN;
- header width follows the saved sidebar width (readLeft clamps 9000 to LEFT_MAX);

- New markup: class topbar, switcher, no inline width, identical with and without a sidebar width;
