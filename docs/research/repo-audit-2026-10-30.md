# Kolux RS audit, 30 October 2026

This audit covers the whole repository at commit `f564c0f` (`main`, 29 October 2026): about 139,000 lines of Rust and 137,000 lines of TypeScript. It looks at the code, the ponytail notes, the libraries and how current Kolux's use of them is (your context7 check), and how the project is built, tested, released and recorded. It is written for you in plain words, and each item names the file and line for whoever fixes it.

The full detail sits in three companion files:

- [Every finding in the Rust back end](repo-audit-2026-10-30-rust.md)
- [Every finding in the front end, security, process, tests and libraries](repo-audit-2026-10-30-app.md)
- [Every ponytail note, judged one by one](repo-audit-2026-10-30-ponytail.md)

No code was changed, and nothing was run on your PC.

## The short version

- **Kolux RS is carefully built.** 29 auditors looked: 25 hunting for problems and 4 reviewing the ponytail notes. They kept praising the same things. Saves check the file on disk first. Deletes are guarded. Kolux's own records survive a crash. Windows programs are started and stopped carefully. The `kolux` command and the hook line (the channel agents use to report their status to Kolux) refuse web pages and any caller without Kolux's secret key. And the large test suite tests real behaviour, not just code shapes.
- **It is not ready for a stranger yet.** The auditors reported 194 findings. Reviewers told to knock them down confirmed 104 and refuted 4; one stayed uncertain, and the 85 that their auditors rated low were not double-checked. Twelve stayed high after the checks. The ones that matter most fall into four groups: someone else's content acting on your computer, risky commands skipping your approval, losing work or running agents, and broken updates, releases and `kolux` command setup, which are exactly what your "grade A" depends on.
- **None of it needs a redesign.** Almost every fix is local: a few lines to a day of work each.
- **Many of the worst bugs come from changes that were not carried through.** When T-184 changed what happens to Kolux's programs at quit, the update installer started dying with the app (item 14) and orchestration started treating helper agents as dead after a reopen (item 11). Removing kits (T-568) left the first-run wizard with a button that does nothing and two open tasks that still describe kits. The Skills page runs commands inside WSL although you decided Kolux never does (OD-12). A step in the build loop that asks "what else relied on the old rule?" whenever a decision changes would catch this kind of bug early.
- **CI, GitHub's automatic build-and-test run, has never run**, because of a GitHub billing setting. Once it runs it will still fail ("go red") for at least two reasons your PC never shows.
- **Your progress page is wrong in places.** `STATE.md` is weeks old and shows six of your decisions the wrong way round.
- **The ponytail habit is working.** Of 167 notes, 101 are honest trade-offs, 16 should be fixed now, and 13 describe problems already fixed and should be deleted. Nine of them were at first hidden from search by one invisible character in `scm.rs`, which is itself worth fixing.
- **The libraries are current enough.** Upgrade the diagram library (mermaid) and the code-colouring library (highlight.js) now. Three security warnings the Rust dependency check is told to ignore can go after one routine update.

## Fix these first

In order of harm to someone using Kolux. "Found by" counts how many auditors reported the problem on their own. "Confirmed" means the reviewers told to refute it could not: two reviewers for a finding first rated high, one for a finding first rated medium.

### Someone else's content can act on your computer

1. **A GitHub issue title can run commands on your PC.** "Start with an agent" on an issue or pull request puts its title into the agent's opening prompt. Agents installed through npm, the Node.js package installer (Gemini CLI, OpenCode, Pi and others, and Codex or Copilot when installed that way), are started through the old Windows command prompt, `cmd.exe`. Kolux wraps the title in quotes, but the command prompt reads quotes differently, which leaves the title itself unprotected. So a stranger's title containing `&` or `|` can run a command of their choosing, and even an ordinary title such as "Fix A & B" breaks the start. Found by three auditors, confirmed. *Where:* `src-tauri/src/pty.rs:334-347`, `src-tauri/src/agents.rs:559`, `src/agentstart/fromItem.ts:18`. *Fix:* start the real program behind the npm launcher directly, or type the prompt in after the agent starts; never pass outside text through the command prompt. The same fix cures two side effects: these agents receive only the first line of a multi-line prompt (so helper agents can start without their task), and when npm's folder path has a space in it they fail to start whenever they are given an opening prompt.
   - The same way of starting programs is behind four more problems listed further down: AI writers installed as `.cmd` launchers fail, the skills installer runs a bare `npx.cmd` that a project folder can replace, an optional `conpty.dll` can be loaded from the folder `kolux open` was run in, and that same inherited folder is why Windows refuses to delete the worktree afterwards. One shared way to start programs (full paths Kolux found itself, never outside text through the command prompt, and Kolux and its terminal service started from a neutral folder) closes all of them.
2. **AI commit messages can run a stranger's code.** The Source Control button that writes your commit message with AI ("Write the message with AI") runs `claude -p` inside the workspace. In that mode Claude Code skips its "do you trust this folder?" question but still runs the scripts, settings and add-on tool servers the repository itself sets up (its Claude hooks, environment settings and MCP servers). In a workspace made from someone else's pull request, that can run their code on your PC or send your Claude sign-in to their server. Confirmed. *Where:* `src-tauri/src/scm_writers.rs:95`. *Fix:* run the writers from an empty temporary folder (the changes are already in the prompt) with the repository's own Claude settings switched off.
   - A related exposure is your call rather than a bug. By design (SAFE-023, kept in DT-C28), Kolux answers Claude Code's and Codex's own "Do you trust this folder?" question for every worktree it makes, including checkouts of other people's pull requests. Starting an agent there skips the warning that would hold back that repository's agent settings. A reviewer set this aside because your spec asks for it. Decide whether pre-trust should skip pull requests from forks.
3. **A web page in the built-in browser may be able to take over Kolux (Windows).** A page can show Kolux's own screen inside itself, in an invisible frame (a page within a page). On Windows the web engine gives that frame Kolux's full command access, so the page could steer your clicks and typing into it, including into your terminals. Found by two auditors, confirmed by tracing Kolux's code and the library source, but nobody has tried it on a real Windows machine yet. The auditors did not all agree: the security auditor took it that the command access only reaches a page's top frame, which is also what your isolation decision (DT-R38, T-500) assumed; the two who traced the Windows library code found it reaches every frame. A live test settles it. *Where:* `src-tauri/src/browser_engine.rs:87`, `src-tauri/tauri.conf.json:28`. *Fix:* add `frame-ancestors 'none'` to the page's security policy (CSP), and refuse frames of Kolux's own address in every tab (today only preview tabs check frames). Then try it live.
4. **Notes, agent plans and chat can restyle the window and hide lines from a plan you approve.** Markdown is cleaned by DOMPurify, a library that strips dangerous parts out of web content, but with its default settings. Those let through style blocks (which can restyle the whole window), forms and hidden text. Previewing a README from a repository you clone can blank or restyle the whole Kolux window, and because preview tabs reopen at start, it comes back after every restart. A plan an agent writes can hide lines from the review sheet where you approve it. Found by four auditors, reproduced in a real browser engine, confirmed. *Where:* `src/editor/PreviewPane.tsx:32`, also used by `src/terminal/PlanSheet.tsx` and `src/chat/StepRows.tsx:111`. *Fix:* for notes, forbid style, form, input, button, map and area tags and the `hidden`, `style` and `popover` attributes, and block clicks on anything but links; in plans and chat, show raw HTML as text. Upgrade mermaid at the same time, because today a note can also freeze Kolux (see [Libraries](#libraries-and-their-current-apis-your-context7-check)).

### Risky commands can skip your approval

5. **One apostrophe switches off the built-in protected rules.** Before the rules check a command, one piece of code cuts it into parts, and that code misreads ordinary command text. An apostrophe in a comment (`# Let's clean up`), a block of embedded text, or an escaped quote hides the rest of the command from the rules. A force-push to main or a hard reset (both can throw away git history), or a folder delete, then runs without Kolux's pause. Kolux starts Claude in auto permission mode by default, so that pause is your main brake. Confirmed by running the exact rule code. *Where:* `src-tauri/src/protected.rs:354`. *Fix:* make that code treat anything it cannot read as risky: strip comments and embedded text before cutting, and when a quote is left open, check the command again with quotes ignored. Your own "starts with" rules have a related gap, confirmed by one reviewer: they miss `npx`, `sudo`, `FOO=1`, `.exe` paths and `bash -c` forms (`src-tauri/src/protected_custom.rs:67`).
6. **Slow work on the hook line lets risky commands through.** Every agent's status report and every protected-command check go through one line into Kolux, and the agent's side gives up after 1.5 seconds. Several things do slow work on that line or hold the lock its answer needs (while one part of Kolux holds the main data lock, every other part that needs Kolux's stored data waits):
   - an "agent finished" automation runs its precheck on the line itself, for up to 10 minutes (for example a test run) (`src-tauri/src/hooks.rs:707`, `src-tauri/src/automations.rs:1206`);
   - the landing screen's tool check and some `kolux` command lookups hold the main data lock while running git for every project (`src-tauri/src/tools.rs:204`, `src-tauri/src/cli.rs:1982`);
   - hiding the secrets in a very large paused command, before showing it to you, takes seconds (`src-tauri/src/protected_custom.rs:371`).

   While any of these run, status lights freeze and a risky command can go ahead without asking. Each part was confirmed by one reviewer. For the `kolux` command lookups, the delay to the protected-command answer is my own reading: that answer takes the same lock (`src-tauri/src/hooks.rs:648`). *Fix:* answer each hook on its own thread, and never run git, prechecks or long masking while holding the line or the main lock.

### You can lose work or running agents

7. **Deleting a workspace deletes commits that were never pushed, while saying nothing would be lost.** The question only checks for uncommitted files ("Nothing uncommitted is there"), then the branch is force-deleted with its commits. Confirmed. *Where:* `src/projects/ProjectsPanel.tsx:1130`, `src-tauri/src/projects.rs:1502`. *Fix:* count commits that exist nowhere else, name them in the question, and keep the branch by default when there are any. If this has already happened to you, the commits usually still exist for a while: `git fsck --lost-found` in the project can find them until git's routine clean-up removes them, so act soon.
8. **Removing workspaces can kill agents you just started.** The remove action writes back the list of open tabs as it was when you clicked. Tabs opened while the removal ran (it takes seconds on Windows) are closed and their programs ended. After removing several, tabs of the deleted workspaces come back broken. Confirmed. *Where:* `src/projects/useWorkspaces.ts:97`. *Fix:* update the tab list from its current value, not from the copy taken at the click.
9. **The update box can restart Kolux in the middle of your work.** After you collapse it, or after a background download fails, the half-hourly check reopens it and moves the keyboard to it. When it says "ready", an Enter you meant for an agent restarts Kolux and ends every running agent. Because of item 14, the update does not even install. Confirmed. *Where:* `src/update/UpdateCenter.tsx:169`. *Fix:* background checks must never reopen a collapsed card or take the keyboard.
10. **Closing a busy terminal can freeze every terminal (Windows 10, and Windows 11 before the 24H2 update).** The background terminal service closes a pane's terminal while holding the one lock every pane needs to show its output. If the closing pane is printing a lot, every Kolux terminal freezes for good, and the only way out is ending Kolux's terminal process in Task Manager, which stops all your agents. Confirmed. *Where:* `src-tauri/src/pty_service.rs:322`. *Fix:* take the pane out of the shared list while holding the lock, then close it after letting go, as the service's own exit path and the window's terminal code already do.
11. **After a quit and reopen, helper agents that kept working are treated as dead.** Helper agents (workers) are the agents a coordinating agent starts for parts of a job. Terminals now survive a quit, but orchestration still ties each worker to the app's old process. After a reopen, every running worker is declared "cut short", its reports are ignored, and following Kolux's advice starts a second copy of the same work. Confirmed. *Where:* `src-tauri/src/orchestration/restart.rs:16`. *Fix:* identify a worker by the terminal it runs in, not by the app's process, and after a reopen only cut short workers whose terminal is really gone.
12. **A slow start wipes your saved tabs.** If settings take more than 1.5 seconds to load at start, which can happen on a slow or busy Windows start, Kolux opens with no tabs and your next click saves that empty layout over the real one. Confirmed. *Where:* `src/App.tsx:1566`. *Fix:* block layout saves until the saved layout is back, and put it back when the late settings answer arrives (the same restore Kolux does at start), or reload the window.
13. **Smaller ways to lose work**, all confirmed (the last three by one reviewer):
    - Renaming a file to another file's name in different capitals overwrites that file, with no undo and nothing in the Recycle Bin (`src-tauri/src/fsops.rs:53`).
    - The rich Markdown view silently deletes table cell text after a typed `|` or an extra cell (`src/editor/richTable.ts:269`).
    - A workspace folder you rename by hand is never repaired, and its Git record is deleted at the next start (`src-tauri/src/projects.rs:2447`).
    - "Discard N changes?" survives a workspace switch, then discards same-named files in the new workspace (`src/scm/SourceControlPanel.tsx:341`).
    - Saving a file that is a link (for example `CLAUDE.md` pointing at `AGENTS.md`) replaces the link with a separate copy, so the other file never sees the change (`src-tauri/src/files.rs:99`).
    - The `.worktreeinclude` copy into a new workspace promises to stop at about 2 GB but does not count what links point to, so it can copy many gigabytes (`src-tauri/src/include.rs:108`).

### Shipping is blocked

14. **Updates never install.** Since T-184, Kolux puts itself and the programs it starts into a Windows "job", a group that Windows ends all at once when Kolux exits. The update installer and the restarted copy stay in that job. So "Restart to update" closes Kolux and ends your terminals but never installs anything, and "Restart in safe graphics" never comes back. The only live update proof was made before the job existed, with a stand-in installer. Confirmed by two reviewers from the code and Microsoft's documentation. *Where:* `src-tauri/src/update.rs:409`, `src-tauri/src/procs.rs:217`. *Fix:* start the installer and the restarted copy outside the job (the job already allows that, and the terminal service does it), and have the restarted copy wait for the old one to close before it checks whether Kolux is already running. Then prove v0.1.0 to v0.1.1 live. Also check whether editors and files Kolux opens for you close when you quit Kolux; that has the same cause and was not verified.
15. **Releases cannot publish.** `scripts/release.mjs` calls `onGitHub()`, which is never defined. Every real release stops with "onGitHub is not defined". It is a one-line fix; see [CI and releasing](#ci-and-releasing).
16. **The `kolux` command cannot be installed from the app.** The Register button in the setup guide and in Settings looks for `kolux.exe` in the app's folder, but the installer puts it in `bin\`, so it always fails. The installer itself does not add Kolux to PATH (the list of folders Windows searches when you type a command), and the setup guide's CLI step can never complete. Confirmed. *Where:* `src-tauri/src/cli_register.rs:508`, `src-tauri/src/onboarding.rs:551`. *Fix:* one shared helper that picks the `bin` folder (the terminal code already does this), plus a test with the installed layout. The same setup step's "install Kolux skills" command also fails for everyone: it points at a GitHub repository, `kolux/skills`, that your own records say does not exist yet, and whoever ends up owning that name would supply your agents' skills. Publish it under an account you control and pin a version, or hide the step until then (`src-tauri/src/skills/installer.rs:18`).
17. **CI cannot go green, even after the billing fix.** The Windows Rust tests need stand-in home folders (throwaway copies, so tests never touch your real settings) that you set up by hand before your own test runs, and one front-end test fails on Linux. See [CI and releasing](#ci-and-releasing).

### Not a Windows problem, but a trap

18. **On Linux, stopping a stuck program can kill every program you have open.** This is what crashed the audit machine. Every running program has a number, its process id. `src-tauri/src/procs.rs:315` runs `kill -9 -<pid>` without `--`, and the `kill` that ships with Debian and Ubuntu reads only the first digit of that number. A number starting with 1 then means "stop every program you are allowed to stop"; 2 to 9 stops unrelated groups of programs instead. Windows is not affected. It matters for anyone who runs the tests on Linux, and it must be fixed before any Linux build. *Fix:* call the system's kill function directly with safety checks, or add the `--` (`scm.rs` already does this correctly), and add a test that pins the exact command.

## CI and releasing

**CI has never run.** GitHub refused every job before it started: no machine was assigned and no step ran. That is a billing or spending-limit setting on your GitHub account, not the code. You fix it on GitHub's billing page (<https://github.com/settings/billing>): fix the failed payment or add a payment method, raise the Actions spending limit or budget above $0, and check how many included minutes are left this month.

**Once it runs, it will still be red** for two reasons your PC never shows, and two more things can turn it red now and then:

1. **The Windows Rust job cannot pass.** At least 93 integration tests (93 on Linux, a couple more on Windows) refuse to run unless your home folder and the Claude and Codex settings folders point into a throwaway folder marked with a `.kolux-rs-scratch` file. You set that up by hand before your own test runs; `ci.yml` never does. The test step fails, so the code-checker, dependency and spec-firewall steps after it never run. Fix: commit one script that makes those folders (for example `scripts/test-env.ps1`), and run it both in your own gate and in CI.
2. **One front-end test fails on Linux.** `src/chrome/__cards__/STAT-052.test.ts:33` looks for spinner rules with a pattern that only matches when files have Windows line endings, and CI's four test machines run Linux. Fix the pattern (changing line endings alone would not fix it), and add a `.gitattributes` rule so your PC and CI check out the same line endings. While you are there: one auditor also noticed, without a second check, that the browser tab's loading spinner keeps spinning when Windows is set to reduce motion, which is what the card is about.
3. **A timing test can fail under load.** In your 29 October run, one Rust test (`pty` row 1014) failed under load and passed alone. GitHub's Windows machines may well be slower than your PC, so expect it to fail there sometimes.
4. **The dependency check can go red on its own.** `cargo deny` failed on 28 October with no change to Kolux's dependencies, because new advisories were published. That will keep happening. It is the check doing its job, but plan for it.
5. **Nothing checks your rule that Mac and Linux keep compiling.** CI builds the Rust side only on Windows, which is how the `git.rs:1600` test line and the 93 code-checker errors slipped in. A small Linux job that runs `cargo check --all-targets` and the code checker would catch the next one. Do not run the Rust tests on Linux until item 18 is fixed.

**Releases cannot publish at all.** `scripts/release.mjs` calls a helper named `onGitHub()` at lines 162 and 261, and it is never defined. Every real release, from `pnpm ship --main` or from the GitHub release workflow, stops with "onGitHub is not defined" right after cloning, and nothing is published. An auditor ran a copy of the script and got exactly that. Your rehearsals never hit it because every test sets `KOLUX_RELEASE_PUBLISH_DIR`, which sends the script down a different path. The fix is one line (the rule is already written down as DT-R11): `const onGitHub = (repo, env) => isGitHub(repo) || env.GITHUB_ACTIONS === "true";`, plus a test that runs the real path with GitHub's command-line tool (`gh`) replaced by a stand-in. Even then, the GitHub release workflow waits for CI on its commit and refuses to publish unless CI passed (`scripts/ci-gate.mjs`), so releases built on GitHub stay blocked until the CI problems above are fixed too. `pnpm ship --main` from your PC does not wait for CI.

**The release job hands its secrets to more code than it needs to.** The release workflow (`.github/workflows/release.yml`) uses ready-made steps written by other people, named by labels their authors can point at new code at any time (`pnpm/action-setup@v4`, `dtolnay/rust-toolchain@stable`). It also hands the update-signing key, its password and the release token to the library install (`pnpm install`) and to the whole Rust build, where every library's own setup code runs. Anyone who took over one of those could sign a fake update that every installed Kolux RS would accept. Fix: pin outside steps to exact commit hashes; build without the key, then sign the installer in a separate step that is the only one to get the key and its password (write the key file just before that step and delete it afterwards); and give the token only to the three `gh release` calls (view, create and upload).

**Nothing in CI watches the front-end libraries for new security holes.** `pnpm audit` is not run anywhere. Add it after the DOMPurify and mermaid upgrades (today it would fail at once on the critical and high warnings that do not reach Kolux), failing on high and critical, with an ignore list that gives a reason for each entry, as `deny.toml` does for Rust.

## Area by area

Each area had its own auditor. The counts leave out findings the reviewers refuted, and "serious" means high or critical after the checks. Every finding, with how it happens and a suggested fix, is in the [Rust](repo-audit-2026-10-30-rust.md) and [front-end](repo-audit-2026-10-30-app.md) detail files.

**Back end (Rust)**

- **The `kolux` command and its local server** (R01: 12 findings, 1 serious). The edge is well defended: every request needs Kolux's random secret, web pages are turned away, file commands stay inside the agent's workspace folder, and errors are clear. The serious one is that registering `kolux` on an installed copy looks in the wrong folder and always fails (item 16). The server answers one request at a time, so one slow command (a worker start, a page wait, a download) makes every other agent wait. Separately, several lookups hold the app's main data lock while they run git for every project, which can make the window stutter. `kolux open` starts Kolux inside the folder it was run from, which Windows then refuses to delete or rename. Once any one project's folder is deleted or its drive unplugged, `kolux worktree list` returns nothing at all, which breaks agents that look up workspaces. Several command words and flags have drifted from `COMPAT.md`, and one oversized `--wait-submit` number crashes the whole app.
- **Status hooks** (R02: 8 findings). Settings files are edited carefully: backups are verified, and removal puts files back exactly as they were. A pane can say "working" forever after you press Esc while Claude runs a helper agent. Claude hooks never install if your settings file has an empty hook list left by another tool (for example `"Stop": []`). The Antigravity hook may give no answer outside Kolux (not confirmed), and the Amp plugin gives no answer anywhere, where Amp expects one (not tried live).
- **Safety rules and accounts** (R03: 8 findings). File fences, secrets locked with Windows' own encryption (DPAPI) and account removal are solid. The weak part is the code that cuts a command into parts before the protected rules check it (item 5), and the slow masking of large commands (item 6). Your own "starts with" rules do not see through `npx`, `sudo`, `.exe` paths or `bash -c`. Smaller: the Codex usage bar can show another sign-in's figures.
- **Projects and files** (R04: 8 findings). Workspace delete, saves that never leave a half-written file, the path fence, search and clone are all defensive. The problems are listed under item 13: the letter-case rename, the hand-renamed folder, saving through a link, and the `.worktreeinclude` copy. Also, "hide git-ignored files" can hang on a folder of a few thousand files (reproduced).
- **Git and GitHub** (R05: 9 findings, 1 serious). Careful with branch names, paths and GitHub calls. The serious one is the AI writers running the repository's own Claude settings (item 2). Installing packages inside a repository nested in another (a git submodule) makes Kolux start thousands of git processes. The Copilot, Kimi, Cursor and Antigravity writers always fail when installed as Windows `.cmd` launchers, for example Copilot from npm. The fetch before a workspace is created has no time limit or cancel, and blocks every other create for that project.
- **Terminals and processes** (R06: 6 findings, 1 serious). Built carefully for Windows: closing a pane always ends its programs, the output kept in memory is capped, a fast program cannot flood the window, and the parts take shared locks in a fixed order so they cannot jam each other. Much of it is tested. The serious one is the frozen terminals when a busy pane closes (item 10). The Linux kill bug (item 18) lives here too. On a Mac, your shell's command history would be saved in a Kolux folder instead of yours, and Kolux's add-on for the bash shell switches off prompt tools such as starship or atuin, Git Bash on Windows included.
- **Built-in browser** (R07: 10 findings). Careful against the obvious attacks: the address bar, redirects, certificates, permission prompts and download names all have explicit rules and tests. This auditor also found the frame problem (item 3). Pages can open tabs, and windows in your normal browser, without a click, because WebView2 switches Edge's pop-up blocker off. Passwords and headers an agent sets for one site are sent to every later site in that tab. An allowed preview folder can be read and uploaded by its page. Microsoft SmartScreen is off. The Ports panel and the Preview button find nothing on non-English Windows.
- **Orchestration, automations and chat** (R08: 9 findings, 2 serious). Defensive with stored data, daylight-saving changes and transcripts. Both serious problems come from changes elsewhere that this area did not follow: workers declared dead after a reopen (item 11), and npm-installed agents (Gemini as Kolux installs it included) receiving only the first line of their brief (item 1). Also: the mail pointer can keep a CPU core busy, and the "continue after the usage limit" option may type its message without sending it.
- **App core, updates and installers** (R09: 6 findings, 1 serious). Start-up, settings and quit are careful: damaged files are set aside, the last save before quitting has a time limit, and scripts and installs need your trust first. The serious one is the update installer dying with the app (item 14). The landing screen's tool check also holds the main data lock while it runs git for every project (item 6).
- **Skills** (R10: 7 findings). The skill delete engine is the strongest code in this area: it keeps a crash-safe record of every step and is careful with links. The weak part is the community skills installer, built against a stand-in and never checked against the real tool. Every install command points at a repository that does not exist yet (item 16). Updates can never be offered, because two different fingerprints are compared. On Windows, Kolux starts the installer by its short name (`npx.cmd`), so Windows may pick a file of that name planted in the project folder. The Skills page also runs commands inside WSL (Linux running inside Windows), against your decision OD-12.

**Front end (React and TypeScript)**

- **Editor and previews** (F01: 10 findings). Built hard around not losing work: saves are checked against the disk copy, drafts survive crashes, and closing asks first. The PDF viewer and maths are locked down, and finished diagrams are shown in a locked frame, although mermaid still draws each diagram inside Kolux's own window first (see Libraries). The problems: the preview puts a repository's HTML into Kolux's own page (item 4); the rich view writes Unix line endings into Windows-style notes and garbles the source view; it can silently delete table cell text (item 13); and a file whose line endings change while it is open can collapse into one line.
- **Settings and updates** (F02: 7 findings, 1 serious). The back end merges partial saves under one lock and writes them safely, and secrets never reach the window. The serious one is the update box that opens itself and lets Enter restart Kolux (item 9). Settings fields can also quietly revert when a save fails, and the Appearance page can undo a terminal font change made a moment before.
- **Terminal panes and keyboard** (F03: 8 findings). Paste, links and cleanup on close are defended in depth. Replaying a restored pane's saved output re-runs its live effects: bells and notifications ring again, your clipboard can be overwritten, and stray answers can be typed at the new prompt. The floating terminal is the least finished part: some keys act on the pane behind it, Ctrl+W closes a running program without the usual question, and PowerShell there probably shows its prompt about 4 seconds late.
- **Projects sidebar and Source Control** (F04: 11 findings, 1 serious). The back-end checks are good; the trouble is in how the screens wire them together after a wait. Removing workspaces can close tabs opened in the meantime and kill their agents (item 8). Deleting a workspace deletes unpushed commits (item 7). "Discard N changes?" survives a workspace switch (item 13). One-click pull requests silently leave out files beyond the first 1,000. Stacked pull requests (pull requests built on top of each other) are marked done in the plan but cannot be reached.
- **App shell, launch, status, Board and Inbox** (F05: 8 findings). Background work in the window cleans up after itself, and the quit flow waits for the last save. A false "agent has not started" warning appears every time you return to a workspace with agent tabs. A slow start wipes your saved tabs (item 12). After a restart, a new tab can inherit a closed tab's "needs you" or "working" state, because tab numbers are reused. A multi-agent Start hangs on "Starting…" if its Setup tab is closed.
- **Tasks and chat** (F06: 6 findings). Agent-written plans and to-do lists go into the window as live HTML (item 4). A long encoded string in an agent's reply freezes the chat, and long sessions make the window lag while the agent writes. Saving an issue description overwrites edits made on GitHub in the meantime.
- **Browser, usage and automations screens** (F07: 6 findings). Mostly healthy. The bugs come from parts of Kolux disagreeing about units or meaning. Claude reset times in usage alerts are wrong, because milliseconds are read as seconds. Preview and Ports open `0.0.0.0` addresses that Windows cannot reach. Back and Forward are wrong for tabs opened straight at an address. An artifact page can open websites in your normal browser without a click. Automation usage can be counted several times over.
- **Onboarding, chrome, look and the rest** (F08: 8 findings). In good shape overall. The crash screen reloads itself after about 20 seconds and wipes a report you are writing. The first-run wizard's last button does nothing for a new user who pressed Continue on "Your work", a leftover of removing kits. Several dialogs do not take keyboard focus, so keys and Escape reach the terminal behind them.

## How this audit was done, and its limits

- **Scope.** Commit `f564c0f` on `main`: the whole of `src-tauri/src` and `src/`, the scripts, the CI files, the project records (`STATE.md`, `PLAN.md`, `PLAN-done.md`, `LOOP.md`, `DECISIONS.md`, `PROVENANCE.md`, `COMPAT.md`) and the locked dependencies.

- **How findings were checked.** Every finding an auditor rated critical or high went to two separate reviewers told to refute it: one traced the real code path, the other asked whether it can happen in the shipped Windows app and whether the spec meant it that way. Findings rated medium went to one reviewer, in batches of up to six. Findings rated low were not double-checked. Ponytail notes judged high-risk or fix-now went to a reviewer in batches. When reviewers disagreed on how serious a finding is, the report uses the lowest rating from any reviewer who agreed it was real. Finally, six more reviewers checked this report itself against the evidence, for plain words and for gaps, and their corrections are in it.
- **What ran.** The project's checks that work on Linux without opening the app, in a Linux cloud machine: types, front-end tests, the front-end build, licence, plan and workflow checks, `pnpm audit`, the Rust code checker, the Rust tests and `cargo deny`. Several auditors reproduced their finding with the project's real code in a test harness: the table-cell loss, the line endings, DOMPurify letting `<style>` through, the mermaid freeze, the protected-rule splitter and the release script error.
