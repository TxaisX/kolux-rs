## CLI-011 (triage: partly-buildable-here, effort S)

Why / what exists today:
The tick (a minimised real window coming to the front, live doc B-5) needs Windows. The code is on main: src-tauri/src/cli/mod.rs:1019-1027 'app.open' calls ctx.front, which at mod.rs:3630-3634 does unminimize, show, set_focus (all queued to the event-loop thread in order, tauri-runtime-wry lib.rs:2105/2240; tao 0.37.1 window.rs:139-150 falls back to the SendInput Alt trick at :1514 when SetForegroundWindow is refused); the client at mod.rs:231 sends first and launches only when unreachable. Two gaps a builder can close here: no unit test asserts that 'app.open' asks for the front (every dispatch test stubs `front: &|| Ok(())`, e.g. mod.rs:7543), and unlike the second-launch road (lifecycle.rs:253-271 forward_to: allow_foreground(pid) then raise_by_pid verified with GetForegroundWindow), `kolux open` never grants the running app the foreground and never reports whether the window actually came forward, so a refused SetForegroundWindow leaves the window restored behind the terminal with only a taskbar flash, and B-5 can only be judged by eye.

Scope to build (from the triage agent; verify every file:line yourself, the code may differ):
(1) cli/mod.rs test cli011_box2_app_open_asks_the_window_forward: dispatch 'app.open' with a counting `front` closure, assert exactly one call and `started` absent/false; a `front` that errs makes the request fail. (2) Make `kolux open` self-reporting like forward_to: in cli::open (mod.rs:231), before the first send read the startup file's pid (cli::FILE, written at mod.rs:3602) and call lifecycle::allow_foreground(pid) (make lifecycle's two helpers pub(crate) for the cli module; lifecycle.rs:164, :204); after the app answers, call raise_by_pid(pid, RAISE_TRIES, sleep) and put `raised: bool` into the JSON result, with cli/text.rs:369 saying 'its window is in front' only when raised is true and 'restored, but Windows kept another window in front' otherwise. Tests: a cli::open unit test with injected send/launch/grant/raise closures proving the grant happens before the send and `raised` carries through; cargo test --manifest-path src-tauri/Cargo.toml cli011, plus cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu for the Windows arm (target installed here). Then B-5 is `kolux open --json` printing "raised": true, and the tick is a one-line read of that log on Txais's PC.
