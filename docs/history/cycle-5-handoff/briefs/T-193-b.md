## T-193-b (triage: partly-buildable-here, effort L)

Why / what exists today:
Main has no Hermes/OpenClaw automation code at all (src-tauri/src/automations.rs and src/automations/model.ts carry only Kolux's own rows; 'hermes' on main is only the status-hook adapter src-tauri/src/agent_hooks/hermes.rs). Neither tool is installed here, but both are public packages a builder can install in this container (PyPI hermes-agent 0.19.0, npm openclaw 2026.10.9) and their official docs now name enough: Hermes `hermes cron create|list|pause|resume|run|remove|edit`, jobs in ~/.hermes/cron/jobs.json with named fields (name, schedule, prompt, enabled, next_run_at, last_run_at, last_status, paused_reason, workdir, timezone...), run output in ~/.hermes/cron/output/{job_id}/{timestamp}.md; OpenClaw `openclaw cron list --json` (documented fields: status = disabled|running|ok|error|skipped|idle, enabled, state.runningAtMs, state.lastRunStatus, agentId, effectiveAgentId), enable/disable/rm/run, jobs in a SQLite store and every cron command needs a running Gateway. The two acceptance boxes (a Hermes job created from Kolux shows in the list; an OpenClaw job paused from Kolux is reported paused by OpenClaw) still need the tools on Txais's PC, so that remainder is needs-live-windows. Not touched by PR #44 (lane/vendors: Hermes status hooks only, zero 'cron' hunks).
