kolux automations create

Usage: kolux automations create --name <name> --trigger <preset|cron|rrule> --prompt <text> --provider <agent> [--precheck <command>] [--repo <selector>|--workspace <selector>|--project <id> [--host <id>]|--project-host-setup <id>] [--json]

Create a scheduled Kolux automation

Options:
  --help                 Show this help message
  --json                 Emit machine-readable JSON
  --pairing-code
  --environment
  --name <name>          Name for the new worktree or automation
  --prompt <text>        Prompt text for agent-backed commands
  --provider <agent>     Agent id such as codex, claude, or gemini
  --precheck
  --precheck-timeout
  --repo <selector>      Repo selector such as id:<id>, name:<name>, or path:<path>
  --workspace <selector> Existing worktree selector for automation runs
  --project
  --host
  --project-host-setup
  --source-context <json|null> Explicit TaskSourceContext for automation task/provider data
  --workspace-mode <mode> existing or new-per-run
  --base-branch <ref>    Base branch/ref to create the worktree from
  --trigger <schedule>   Automation schedule preset, cron, or RRULE
  --schedule <schedule>  Alias for --trigger
  --time <HH:MM>        Time used with daily/weekdays/weekly presets
  --day <0-6>           Day used with weekly preset, Sunday=0
  --timezone <tz>       IANA timezone for the automation
  --enabled              Enable the automation
  --disabled             Disable the automation
  --missed-run-grace-minutes <n> Missed-run grace window
  --reuse-session        Reuse the previous live session for existing-workspace runs
  --fresh-session        Disable session reuse for future runs

Notes:
  Trigger accepts hourly, daily, weekdays, weekly, a 5-field cron expression, or an RRULE string.
  When --repo is omitted, the CLI uses the enclosing Kolux worktree when one can be resolved from cwd.
  Use --project with --host, or --project-host-setup, to run on a specific project host setup.
  --host runtime:<environment-id> targets that paired Kolux server; use the id from `kolux environment list`, not the environment name.
  Use --source-context with a JSON TaskSourceContext when task/provider data should come from a specific host/account; pass null on edit to clear it.
  Use --workspace to run in an existing worktree; otherwise the automation creates a new worktree per run.
  Use --precheck to run a bounded command before scheduled runs; exit code 0 continues, anything else records a skipped run.
  Use --reuse-session only with existing-workspace automations to submit later runs to the previous live automation session when it is still available. Use --fresh-session to disable reuse.

Examples:
  $ kolux automations create --name "Daily review" --trigger daily --prompt "Review open changes" --provider codex
  $ kolux automations create --name "Weekday triage" --trigger "0 9 * * 1-5" --prompt "Triage issues" --provider claude --repo my-repo
  $ kolux automations create --name "PR review" --trigger hourly --precheck "gh pr list --json number -q .[0].number" --prompt "Review requested PRs" --provider codex
